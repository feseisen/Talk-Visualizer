# 公開版に入るもの・入らないもの

このリポジトリは、元の作業場から**骨組みだけ**を切り出した公開版です。元の作業場には、この道具を作るときに使った素材や、作っている間の記録が一緒にありますが、それらは公開版に入れません。

## 入らないもの

| 入らないもの | なぜ |
|---|---|
| **文字起こし**（この道具を作るときに聞いた逐語） | 第三者の発話。話した人の許可なく配れない。道具の骨組みではない |
| **実走記録**（v1 の形式で書いた判断ログ、その再生ページ、実走の覚え書き） | 中身が上の逐語を引いている。カードの文・問いの文・所感に発話が写っている |
| **旧 HTML**（この道具より前に作った画面） | 逐語を丸ごと埋め込んでいるものがある。開いただけで第三者の発話が出る |
| **作業の判断ログ**（作っている間の記録） | 作っている間に何をどう判断したかの記録。作った人に紐づくもので、使う人には要らない |
| **一時ファイル**（`scratch/` など） | 作業中の生成物。再現できる |
| **会議の記録**（判断ログ・素材ログ・覚え書き・バッチ・印・文字起こし。`*.jsonl`・`*.next.json`・`*.owner`・`*.watch.json`・`*.watch.json.*.tmp`・`*.txt`・`*.tsv`・`*.vtt`、`live/`・`records/`） | 使う人の会議の中身。置き場に依らず `.gitignore` で止めてある（通すのは `tests/` の架空の素材と `format/` の下だけ） |
| **鍵**（`.env`・`.env.*`・`*.key`・`*.pem`） | API の鍵はファイルに書かない。画面で貼って、既定ではタブを閉じると消える。`build_html.py` が鍵の形の文字列を見つけると組み立てを止める |

## 入るもの

この道具のフォルダ（`kiku.html` のあるフォルダ）の中身は全部入ります。生成物も含みます。

- `kiku.html` — `build_html.py` が `src/`・`format/`・`prompts/` から組み立てた 1 枚。ZIP で受け取った人がそのまま開けるように入れる
- `tests/_data.js` — `tools/make_test_data.py` が規則表・cases・fixture から作る。node 無しで `tests/tests.html` を開くために要る
- `tests/fixtures/` — **架空**の会議（話者・社名・製品名は作りもの）。実在の人物・組織・過去の素材を連想させないことを `tests/README.md` の決まりで縛っている
- `.claude/settings.json` — Claude Code を分析役にするときの許可の雛形（説明は `.claude/README.md`）

## 同僚に渡すとき

- **素材ログ `<会議名>.src.jsonl` は渡さない。**渡すのは判断ログ `<会議名>.jsonl` だけ
- `kiku.html` には、書き出した判断ログを読み込む口が無い。受け取った人は画面で再生できず、1 行に 1 件の JSON の文字として読むことになる（追体験で見直せるのは、記録を書いたページを開いている間だけ）
- 判断ログの話者名は役割名に置き換える（`who` の欄と、`note`・カードの見出しや詳細などの文の中）
- 録ることの告知は、使う人の責任
- 対応環境の表（`README.md`）には、実際に確かめた環境と、そこで分かったことだけを書く。確かめていないものを「動く」と書かない

## ブラウザ内蔵の音声認識

- **ブラウザ内蔵の音声認識は、音声を外へ送ることがある。**MDN の Web Speech API の説明では、Chrome などの音声認識はサーバ側の認識エンジンを使い、音声を web のサービスへ送って文字にする（記憶している文で、頁を開き直して確かめてはいない）
- だから `kiku.html` は、聞き始める前に、この PC の中だけで日本語を文字にできるかをブラウザに尋ね（`SpeechRecognition.available()`。部品が無ければ `install()` で入れられる）、その答えに従う。できると答えたら、認識に `processLocally` を立てて PC の中で文字にし、音声は外へ出さない。できないと答えたとき（尋ねる口が無いときも）は、入口の欄の「音声を…送って文字にすることを承知した」に印を付けないと聞き始めない。この印はページに覚えさせない（`autocomplete="off"`。開き直したら付け直す）。PC の中で文字にする設定で始めた後に失敗しても、黙ってサーバーへ切り替えない（使う人向けの説明は `README.md` の「外へ出るもの」）
- 確かめた範囲：尋ねる口の名前と形（`available()`・`install()` と、認識の `processLocally`）は、試験に使った Chromium 141.0.7390.37（headless）で確かめ、合っていた。その環境では日本語の部品が入らず（`install()` は `false` を返した）、PC の中で実際に文字にするところまでは試せていない。実物の Chrome 150 と Edge では確かめていない（未確認）。Edge にも PC の中で文字にする仕組みがあるかもしれない（未確認）。どのブラウザでも、ページはブラウザに尋ねて、その答えに従う
- サーバーへ送る設定で聞いている間、入口の欄には「音声は提供元のサーバーへ送られている」と出る。ブラウザが自分の判断で PC の中で文字にすることもあるので、この札は言い過ぎのことがある。逆の向き（PC の中だと言いながら送る）には、ページの側からは倒れない。「PC の中で文字にしている」と出すのは、`processLocally` を立てて始めたときだけ（立てた指定をブラウザが守るかは、実物では確かめていない）
- 送ってよいかは、使う場所の決まりしだい。道具からは分からない
- `check.html` はこれに当たらない。認識の口とマイクの入口が**あるか**を見るだけで、認識を始めず（`start()` を呼ばない）、マイクの許可も求めない（`check.html` の `checkStatic`）
