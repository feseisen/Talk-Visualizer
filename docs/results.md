## 環境を調べる計器（`check.html`）

headless の Chromium 141 で `file://` のまま開き、「調べる」を押して、貼るための文字と、外へ出た要求を数えました。社内の中継をまねた小さな中継（つなぐ申し込みを受けて中身を開き、型ごとに決めた返事をする）をこちらで立て、ブラウザをその中継越しに動かしています。数えたのは、中継に届いた要求のうち、ページが出したもの（送り元が `null` のもの）だけです。ブラウザが自分で出す更新の確認などは数えていません。

### いまの作り（事実）

- API 1 つにつき、要求は多くて 3 本です。
  1. 送る要求（鍵なし・中身の無い呼び出し。POST）を 1 回出します。独自の見出しが付くので、ブラウザがその前に下見の要求（OPTIONS）を自分で 1 回出します。下見が通らなければ、送る要求そのものは出ません。
  2. 送る要求の返事が読めず、案内（転送）が返ったとも分からなかったときだけ、API の根元へ見るだけの要求（GET）を 1 回出します。独自の見出しを付けないので、下見は出ません。
- どの要求にも、案内を追わない指定（`redirect: 'manual'`）、クッキーを付けない指定（`credentials: 'omit'`）、ページの住所を付けない指定（`referrerPolicy: 'no-referrer'`）を付けます。鍵は付けません。
- 時間切れ（送る要求は 15 秒、見るだけの要求は 10 秒）にした要求は、その場で取り消します（`AbortController`）。
- 「可」と書くのは、送る要求の返事が読めて、状態が 401 で、本文が JSON として読め、その API が鍵の無い呼び出しを断るときの形のときだけです（6 回目から。形は次の節）。401 でも形が違えば、2 項目とも「不可（401 が返ったが API の形ではない。中継の可能性）」です。読めても 401 でなければ「不可」とし、状態の数字と「API か社内の中継かは区別できない」を添えます。見るだけの要求の返事が読めたときも「可」とは書きません（理由は次の節）。
- ページには、つなぎ先を 2 つの API の住所に絞る決まり（`connect-src`）も入れてあります。決まりに触れた知らせは、送り先の住所と時刻で要求ごとに数え分け、その要求の欄にだけ「案内が返った」と書きます。案内を追わないので、ふつうは知らせが来ません（2 つ目の守りです）。

### 本物の API の答え方（2026-10-08、この環境から curl で確かめた事実）

鍵は付けずに呼びました。

6 回目に、`check.html` をこの環境の網でそのまま開いて「調べる」を押しました（事実）。Anthropic の 2 項目は、本物の本文で「可（API が応答した。鍵なしの呼び出しが 401 で断られた）」と「可（鍵なしの呼び出しが 401 で断られた。ページからの呼び出しは通る）」になりました。

### 401 の本文の形の決め（6 回目）

- Anthropic: 本文が JSON で、`error` が欄を持つ入れ物で、`error.type` が `authentication_error`。上の実物の形です（事実）。
- OpenAI: 本文が JSON で、`error` が欄を持つ入れ物で、次のどちらか。1 つは、`error.code` が文字列で、`api_key` か `apikey` を含む（`invalid_api_key` など）。もう 1 つは、`error.type` がちょうど `invalid_request_error` で、`error.message` が文字列で、`api key`・`api_key`・`apikey`・`bearer`・`authenticat` のどれかを含む（`authenticat` は authentication・authenticate の頭）。語はどれも大小文字を問わず、含むかだけを見ます。だから、鍵と関係のない認証の文（「Proxy authentication required」など）でも、`error.type` が `invalid_request_error` なら OpenAI の形として数えます（7 回目に、この文書の言葉を実装に合わせました。判定は 6 回目と同じ）。Anthropic の実物の形（`error.type` が `authentication_error` で、`code` が無い）は、OpenAI の形として数えません。
- OpenAI の形は推測です。この環境からは OpenAI につなげず、実物を見ていません。鍵の無い呼び出しには、鍵を渡していないと言う英文（`code` は空）か、bearer の認証が無いと言う英文が返り、鍵の誤りには `code` が `invalid_api_key` の形が返る、という覚えに基づいています。実物がこのどれとも違えば、本物の OpenAI でも「不可（401 が返ったが API の形ではない。中継の可能性）」になります。

ここからの判断（推測に基づく決め）: 見るだけの要求の返事が読めたときは、本物の API ではない何か（社内の中継など）が答えた見込みが高いので、「確かめられない」と書いて「可」にはしません。

### 残る危険（7 回目）

事実（確かめて分かっていること）:

- 音声の入口の「聞き終える」は、認識の終わりの知らせを 3 秒までしか待ちません。3 秒を過ぎて届いた確定の結果は、記録に入りません（入口の知らせの欄と、素材ログの出来事で分かります）。確かめたのは模擬の認識器だけです。
- 音声の入口では、最後の窓の終わりは「聞き終える」を押した秒ではなく、認識の終わりを待ち終えた秒（押してから 3 秒以内）です。待つ間に届いた結果を窓に入れるためです。打つ／貼る入口は待たないので、ふつうは押した秒です（同じ秒に届いた行があれば、その行も入るように次の秒まで待ちます）。ただし、どの入口でも、前の窓の返事を待っている間に押すと、返事を書き終えてから時計を読むので、押した秒より後ろになります（8 回目に直した文。前は「押した秒です」と言い切っていました。8 回目の表の 21）。
- 待つ間（長くて 3 秒）は、「聞き終える」「中断する」「再開する」を押せません。
- 続きから聞くときにもう一度出す知らせは、まだ窓で渡していない発話（最後の窓の `lines[1]` より後ろ）に付いたものと、最後の発話より後ろのものだけです。前に渡した窓の知らせは、もう一度は出しません（`rt.py next` も同じ）。
- `alone` の素材に「時刻＋空白＋本文」の行が混ざると、その行の話は前の発話の本文として、前の発話の窓で渡ります（決めどおりの残り。知らせはその同じ窓で出ます）。（8 回目の確かめで、`alone` のほかにも、時刻のすぐ後ろに字が続く行・括弧で囲んだ時刻の行・読めないバイトを含む行が、どの書き方でも知らせ無しで前の発話に入ると分かりました。8 回目の表の 5 で直しています）
- `check.html` の OpenAI の形は、語を含むかだけを見ます。中継が OpenAI の `error` の入れ物と `invalid_request_error` を真似て、認証の語を含む文を返せば「可」になります。この回は言葉を実装に合わせただけで、判定は変えていません。
- メモ帳の突き合わせが、同じ中身の消えた行を、別々の保存の分として 2 つ以上覚えている場合、知らせのとおり末尾に打ち直した行も、また戻した行とみなされます（覚えの数だけ打ち直しが要り、そのたびに名指します）。相づちの多い言葉で打つ・消す・戻す・空にするを乱数で 40 回ずつ並べた 300 通りで、350 回ありました。黙って欠けたものは 0 です。

- 覚えから外した中身の行を、エディタの「元に戻す」で末尾に戻すと、新しい発話として二重に入ります。そのときは「同じ発話が二重に入っています」と知らせます（上の 300 通りで 14 回。どれも知らせつき）。
- 道具はメモ帳の中身だけを見るので、同じ保存で読み終えた行を消し、消した行と同じ中身の行を打つと、消した行が残っているのと見分けられないことがあります（たとえば、3 行以上あるメモ帳の最後の 2 行を消して、同じ保存で、消した 1 行目と同じ中身を打つ。道具には最後の 1 行が消えただけに見える）。そのときは、その行を拾いも名指しもしません。打つ・消す・戻す・書き換える・空にするを乱数で並べた 2000 通りを 3 回流して、71〜102 行でした。

## 再現のしかた

どれも、この道具の根（`kiku.html` のあるフォルダ）で打ちます。Windows では `python3` の代わりに、たいてい `py -3` と打ちます。

```
python3 build_html.py
python3 tools/test_rt.py
node tests/run_node.js
node tests/run_analyst_node.js
node tests/e2e/e2e_kiku.js
node tests/e2e/e2e_routes.js
python3 tools/audit_r2b.py <落ちた判断ログ>
```

`tests/e2e/*.js` は playwright と Chromium が要ります。Chromium を playwright の既定の場所に置いていないときは、その場所を環境変数 `CHROMIUM_PATH` で渡します。出力は既定で OS の一時フォルダの `kiku-e2e/`（結果の JSON、落ちた 2 つのログ、5 窓後の全ページ撮影）。
