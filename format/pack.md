# 状態の最小表現（pack）

分析役（読み手）に毎回渡す JSON。**道具が判断ログを畳み込んで作る。** 分析役はこれと新しい素材だけを見て、1ステップ分の返事（`schema.json` の形）を返す。
指示（固定の接頭辞）の後ろに置くので、ここに入るものは毎回変わってよい。

```json
{"now":{"n":13,"t":390,"at":"2026-10-07T09:06:00Z"},
 "known":"",
 "open_holds":[{"id":"H3","t":98,"age":292,"who":"栗原","q":"去年の値上げで、なぜ数量が落ちなかったのか"},
               {"id":"H7","t":316,"age":74,"who":"栗原","q":"桃色を試す数はいくつにするか"}],
 "top":{"id":"C15","ti":"一点目の着地：値上げ一割、先に価値を説明する資料"},
 "open_groups":[{"id":"D","lb":"三点目：店舗の在庫","span":[361,null],"kind":"start"}],
 "closed_groups":[{"id":"C","lb":"二点目：新色","span":[271,322]},
                  {"id":"B","lb":"価値をどう説明するか","span":[128,253]},
                  {"id":"A","lb":"一点目：値上げ","span":[13,268]}],
 "lists":[{"id":"L1","n":3,"items":["値上げをするかどうか","新色","店舗の在庫"],"at_item":3}],
 "recent_cards":[{"id":"C23","t":380,"d":2,"role":"claim","who":"栗原","ti":"黄色は棚で緑の後ろに置かれがち"}],
 "recent_notes":["三点目に入った。…","H3 が決着。…","二点目は短く決まった。…"],
 "settled":{"count":5,"median":21,"longest":240},
 "next_ids":{"card":"C24","hold":"H9","group":"E","list":"L2"},
 "attempt":1,
 "violations":[],
 "gap_lines":[],
 "new":{"t":[390,420],"lines":[{"i":66,"t":391,"who":"栗原","text":"それもありますが、黄色は暗いところで光が弱いと言われています。"}]}}
```

## 各欄の意味

| 欄 | 中身 | 出どころ |
|---|---|---|
| `now.n` | これから書くステップの番号 | 直前の `step.n` ＋ 1 |
| `now.t` | 聞き終えている時刻（秒）。これより先の時刻は書けない | 渡す窓の終わり ＝ `new.t[1]` |
| `now.at` | いまの壁時計（UTC） | 道具 |
| `known` | 聞き始める前に知っていたこと | `open.known` |
| `open_holds[]` | 開いている保留。`age` は `now.t − t`。古い順。`kind:"gap"` の保留には `"kind":"gap"` が付く | `hold` − `close` |
| `top` | 最上位候補。無ければ `null` | 最後の `top` |
| `open_groups[]` | 終わりが `null` の括り | `group`＋`fix(span)` |
| `closed_groups[]` | 閉じた括り。新しい順に最大 8 件。`echo`・`rename` の相手として要る | 同上 |
| `lists[]` | 数え上げ。`at_item` は、その数え上げを `li` で指した最後のカードの「何番目か」。無ければ `null` | `list`＋`fix(items/n)`＋`card.li` |
| `recent_cards[]` | 直近のカード。新しい順に最大 8 枚（`b` は入れない） | `card`＋`fix` |
| `recent_notes[]` | 直近の `note.x`。新しい順に 3 件 | `note` |
| `settled` | 決着した保留の数・決着までの中央値・最長（秒）。`kind:"gap"` は入れない。同じ保留に答えが2つあれば1つ目で数える | `close.t − hold.t` |
| `next_ids` | 次に使う id。**返事の新しい id はこの値から順に使う。違えば拒む** | 下の採番規則 |
| `attempt` | この窓で何回目の呼び出しか（1〜3）。返事が機械向けの形として読めなかったとき（JSON として壊れている、`events` が配列でない、など）も 1 回に数える | 道具 |
| `violations[]` | 直前の返事が検証に落ちたときの違反文（id 付き）。読めなかったときはその旨の文。初回は `[]` | 検査器 |
| `gap_lines[]` | 直前の窓が検証に3回落ちて `kind:"gap"` の保留になっているとき、その窓の発話。無ければ `[]`。これを根拠にカードを過去の位置に置き、`close.by` で保留を閉じてよい | 素材ログ |
| `new.t` | いまの窓 `[始まり, 終わり]`。返事の `step.t` はこれと同じ値を返す。発話の数の上限で切った窓では、終わりを「渡さなかった最初の発話の時刻」まで縮め、その時刻と同じ時刻の発話は次の窓に回してある（窓の発話はどれも終わりより前）。同じ時刻の発話が窓の最初から上限より多く続くときと、遅れて届いた発話（時刻が窓の始まりより前）で上限に当たったときだけ、始まりと終わりが同じ値になる | 刻み |
| `new.lines[]` | いまの窓の発話 `{i,t,who,text}`。`limits.step.max_lines`（40）件まで（超えた分は次の窓）。`t` は素材を読むときに単調にした時刻（`FORMAT.md`「素材ファイルの形」）。`who` が無い素材では `null`。言い直しの行は `"replaces":i` が付く | 素材ログ |

**入れないもの**: 総尺・残り時間・まだ先の発話。聞いている人は残りがどれだけあるかを知らないので、分析役にも渡さない。

## `next_ids` の採番規則

| 種類 | 規則 | 例 |
|---|---|---|
| カード | `C` ＋（既存のカード数 ＋ 1） | 23 枚あれば `C24` |
| 保留 | `H` ＋（既存の保留数 ＋ 1）。`kind:"gap"` の保留も数に入る | 8 件あれば `H9` |
| 数え上げ | `L` ＋（既存の数え上げ数 ＋ 1） | 1 件あれば `L2` |
| 括り | 既存の括り数 ＋ 1 番目の列名。`A, B, …, Z, AA, AB, …, AZ, BA, …` | 4 件あれば `E`、26 件あれば `AA` |

- 1バッチで同じ種類を複数出すときは、`next_ids` の値から順に 1 つずつ進める（`C24`, `C25`, …）
- 列名の計算: 番号 k（1 から）を 26 進で表し、各桁を `A`〜`Z` に写す。ただし桁に 0 が無い記法（表計算の列名と同じ）。1→A、26→Z、27→AA、52→AZ、53→BA、702→ZZ、703→AAA
- v1 の記録（欠番あり）には当てない。v1 の読み込みでは `next_ids` を作らない

## 大きさの目安

約 600〜1,000 トークン（推測）。`recent_cards` 8・`closed_groups` 8・`recent_notes` 3 の件数は、無状態の呼び出しでも直前の文脈が残る最小として置いた仮の数で、v2 での最初の実走で見直す。
