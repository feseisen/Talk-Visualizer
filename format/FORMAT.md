# 判断ログの記録の形 v2

**凍結日: 2026-10-07。次の実走で使う素材（会議の文字起こし）は、一行も目にしないまま凍結した。**
v1 と同じく、形式を先に固めてから素材を読む。素材の中身を知ったあとで、その素材に都合のよい形へ決め直す道を残さないためである。
凍結のあとの直し（1 つの窓の発話の上限、素材の時刻を単調にする読み方、並びの位置の検査 P29、読めない行の知らせ、素材ファイルの 4 つの書き方、判断ログの名前の決まりなど）も、次の実走の素材を見ないまま入れた。

v1 の語彙はそのまま引き継ぐ。足したもの・落としたものは「版の差」の節にまとめてある。
**機械が読む正本は `format/rules.json`（規則表）**で、この文書はその説明である。
文書と規則表が食い違ったら規則表が正しく、食い違いそのものが直すべき欠陥である。

---

## この記録の役目

本体は、話を聞きながらその場で構造を組み上げる処理のほうにある。画面も再生も、その処理が残した跡を映すだけで、跡とは別に飾り立てるものではない。
そこで記録は、**書いた順に並べて流すだけで、手を加えずに再生できる**形にする。処理の途中で足した行をそのまま流せば、経過を早回しで見返せる。

順序の決まりは、書き手の注意に任せず、**道具が通さない作り**にして守る。
読むときも書くときも検査器（`tools/rt.py`、ページの中では `verify.js`）を通し、違反がどれか1つでもあれば、その追記は丸ごと書かない。

## ファイル

| ファイル | 何が入るか |
|---|---|
| `<会議名>.jsonl` | 判断ログ。1行1イベント、追記専用。**唯一の正**で、再生の唯一の入力。名前の決まりは下 |
| `<会議名>.src.jsonl` | 素材ログ。確定した発話 `{"i":1,"t":2,"who":"話者A","text":"…","at":"…"}` を1行ずつ（`at` は道具がその発話を受け取った壁時計）。発話でない出来事（認識の切断・再開、素材の読めない行 `{"ev":"unreadable",…}`、聞き終えた後に届いて記録に入れなかった認識の結果 `{"ev":"late",…}`）もここに書く。音声認識が後から言い直した発話は、古い行を書き換えず `"replaces":i` を持つ新しい行で表す。判断ログには持ち込まない |
| 素材ファイル | `file` の記録で読む文字起こし（形は下の「素材ファイルの形」）。道具は窓ごとに先頭から読み、残りを数えない |
| 素材の隣の `.owner` | `rt.py open` が書く。中身はその素材を開いたログのパス。**1つの素材ファイルに開けるログは1つ**で、別のログで同じ素材を `open`・`next` しようとすると断る（P07） |
| `<会議名>.next.json` | `rt.py next` が窓を出したときの覚え書き（渡した窓）。`append` がこれと素材を照らす |
| `<会議名>.watch.json` | `live` の記録で `rt.py watch` が回っている間の印。中身に、判断ログの名前（フォルダを除いた名前）と、最後に動いた時刻を書く |

**判断ログと素材ログは足していくだけで、書いた行は二度と書き換えない。** 直したいときは `fix` を足す。

**判断ログの名前（`rt.py`）。** 道具は、素材ログ・覚え書き・watch の印の名前を、判断ログの名前から作る。だから名前を次のように縛る。

- 判断ログの名前は、ちょうど小文字の `.jsonl` で終わる（`.JSONL`・`.peek`・拡張子の無い名前は断る）。ただし `.src.jsonl` で終わる名前（大小文字を問わない）は素材ログの名前なので断る。返事のバッチの名前（`.batch.jsonl`）も断る
- 名前から `.jsonl` を除いたものを**語幹**と呼ぶ。派生ファイルは同じフォルダの `<語幹>.src.jsonl`（素材ログ）・`<語幹>.next.json`（覚え書き）・`<語幹>.watch.json`（watch の印）
- `open` は、判断ログ自身か派生ファイルのどれかがもうあるときと、同じフォルダに語幹が大小文字を無視して同じになる別の判断ログか派生ファイルがあるときは、何も書かずに断る（中身が空のファイルでも）。大小文字を区別しない場所（Windows など）で、別のログの派生ファイルを自分のものとして読み書きしないため
- watch の印には判断ログの名前を書く。`watch`・`next`・`append`・`end`・`pause` は、印に書かれた名前が自分の名前と違えば（名前の無い印も）、何もせずに断る。止まった `watch` が残した古い印（最後に動いた時刻が 5 秒より前）を新しい `watch` が引き継ぐのも、印に書かれた名前が自分と同じときだけ
- 判断ログのパスの区切りの間に `..`（一つ上のフォルダ）があれば、何もせずに断る（`会議/x/../会議.jsonl` など）
- `open` は、断る・受ける・印を見るのどの判定よりも前に、判断ログのパスを絶対パスに直し（シンボリックリンクも解く）、直したパスで上の照らしをする。無いフォルダを挟んだ書き方で、同じフォルダにある判断ログや派生ファイルを見落とさないため
- 判断ログの名前そのものがシンボリックリンクなら（渡された名前の実体が、フォルダの部分だけを解いた場所と違えば）、`open` も含めてどの命令も何もせずに断る。語幹の違うリンクで本番の判断ログを指し、派生ファイルを別の語幹で作らせないため。同じ名前で別のフォルダから指すリンクと、まだ無いファイルを指すリンクも断る（派生ファイルが、渡した名前の隣とは別の場所にできるため）。フォルダの部分にあるリンクは解いて使う
- 判断ログを置くフォルダが無いとき、`open` が作るのはそのフォルダ 1 つだけで、その上の無いフォルダは作らない。途中に同じ名前のファイルがあるなどで作れないときは、使う人に向けた文で断る（何も書かない）。途中がファイルのときは、文で「同じ名前のファイルがあります」と言う
- 判断ログの名前の終わりが「/」「/.」のとき、判断ログとしてフォルダを渡されたとき、まだ無い判断ログを `open` 以外の命令に渡されたときは、どの命令も使う人に向けた文で断る（Python の Traceback を出さない）。`status` と `digest` は、無い判断ログを「まだ窓を一つも書いていない」とは言わずに断る
- `status`・`digest` と監査の道具（`tools/audit_r2b.py`）も、同じ名前の決まりを照らす。渡された名前だけでなく、絶対パスに直した実体の名前にも照らす。素材ログ・覚え書き・watch の印を判断ログとして渡されたら（それらを指すリンクも）、中身を読まずに断る（行の数も出さない）

**メモ帳・素材のパス（`rt.py`）。** `open` の `--transcript`（`live` のメモ帳と `file` の素材）にも、次の決まりを当てる。

- 名前の区切りの間に `..` があれば、何もせずに断る（`live/無いフォルダ/../会議.txt` など。持ち主の印を書く場所と、`watch` が読む場所が食い違わないため）
- `open` は、メモ帳・素材のパスを絶対パスに直し（シンボリックリンクも解く）、直したパスで持ち主の印（隣の `.owner`）を書き、1 つの素材に開けるログは 1 つの照らし（P07）をする
- `live` のメモ帳が `open` の時点で無ければ、空のファイルとして作る。ただし作るのは、メモ帳を置くフォルダが既にあるときだけ。持ち主の印を書くときも、作るフォルダは直上の 1 つだけ
- メモ帳が見つからない・フォルダのときの `watch`・`next`・`next --last` の振る舞いは、下の「`live` のメモ帳」

素材ログの `i` は 1 から始まる連番で、言い直しの行も新しい `i` を取る。判断ログは発話を `i` で指す（`card.src`）。

## 版

判断ログの先頭 `open` の `v` が版を表す。**規則表の `versions.<版>.open_v` に当てて決める**（`v` が無ければ v1）。
当てるときは型も比べる（`true` は `1` ではない。`2.0` は JSON を読んだ時点で `2` と同じなので v2）。
どの版の `open_v` にも無い `v` は**知らない版として拒む**（F07）。黙って v1 扱いにしない。
ページの側で版だけが要るときも、自前で `v` を読まず検査器の `versionOf` を呼ぶ。

- **v1**: 前の形式。v1 で取った実走記録がこれ。読み込みは v1 の列で検査する
- **v2**: この文書の形式

**新しい記録は v2 でしか始まらない。** 新しい記録を始める入口は `rt.py open`（とページの「新しい記録」）だけで、どちらも v2 の `open` を書く。`rt.py append` は `open` を受けないので、空のファイルに v1 の先頭を書いて v2 の守りを外すことはできない。v1 の記録には、既にあるものの続きを足せるだけ（P01）。

変換器は作らない。検査器は規則表の**版ごとの列**を読んで、同じコードで両方を通す。
v1 の記録を v2 に書き直すことは、過去のログを書き換えることなので、しない。

## 1ステップ＝1窓

**1ステップ＝1窓＝分析役（読み手）への1回の呼び出し。**

- 窓は時間で切る。既定の幅は `open.window` 秒（5〜180 の整数、既定 30）。**窓は発話の境界でしか閉じない**
- 窓に入るのは、まだ読んでいない発話のうち `発話.t ＜ t[1]` のものを、先頭から順に **`limits.step.max_lines`（40）件まで**。超えた分は次の窓に回す。終わりの時刻ちょうどの発話は、**それが最後の発話でも**次の窓（素材の終わりで閉じる最後の窓）に回す。素材がそこで終わることを、窓の中身から先に分からせないため
- **40 件の上限に当たった窓は、終わり `t[1]` を「渡さなかった最初の発話（41 件目）の時刻 T」まで縮める。** 聞いたのはそこまで、という扱いにする。こうすると、P09・P15 や監査が「聞き終えた所」として見る `t[1]` と、実際に分析役へ渡した発話とが食い違わない
- **窓の中に T と同じ時刻の発話があれば、その同じ時刻の塊の手前で切る**（窓は 40 件より少なくなる。塊は次の窓に回る）。こうして「`t[0] ≦ 発話.t ＜ t[1]`」を道具が自分で破らない。例: 0:00〜0:17 に 36 発話、0:20 に 9 発話なら、窓は 0:00〜0:20 で発話 1〜36、次の窓は 0:20 から始まり 0:20 の 9 発話を含む
- **塊が窓の最初の発話から始まる**（窓に入る 41 件以上がすべて同じ時刻 T）ときだけ、幅 0 の窓 `[T, T]` に 40 件ちょうどを入れる（始まりも T まで進む）。次の窓は T から始まり、同じ時刻の残りを含む
- **T が窓の始まり以下のとき**（`live` で遅れて届いた発話で上限に当たったとき）は、始まりより前には縮めない。窓は幅 0 の `[始まり, 始まり]` で、先頭から 40 件ちょうど（塊の手前では切らない。始まりも動かさない）。次の窓は同じ始まりから、残りを含む
- 幅 0 を受けるのは、上の 2 つの幅 0 の窓だけ（P05）。`rt.py` とページは、同じ入力から一字違わず同じ窓を作り、検査器はこれらの形の縮めた窓だけを受ける
- **素材の時刻は、読むときに単調にする。** 前の発話より前の時刻は、前の発話の時刻に揃える（下の「素材ファイルの形」。ページの打つ・音声認識の入口も同じ）。だから、まだ読んでいない発話の時刻が窓の始まりより前になるのは、`live` で遅れて届いた分だけになる（40 件で切れて次の窓に回った分は、遅れて届いた分でなければ、時刻が次の窓の始まりちょうどか後）。時刻の打ち間違いや巻き戻りがあっても、1つの窓が素材の残りを丸ごと渡すことはない
- 窓は直前の窓の終わりから始まる（最初は 0。発話の無い窓を丸ごと飛ばすときだけ、窓の幅の刻みで先へ進む。上の幅 0 の窓だけは、始まりが塊の時刻 T まで進む）。素材のある記録では、道具が素材から窓を計算し直して確かめる（P07）
- 分析役の返事が遅れて追いつかなければ、次の窓は溜まった発話を渡す。ただし1窓の幅は `open.window × 3`（既定 90 秒）まで、発話は 40 件まで（上限に当たれば上のとおり終わりを縮める）。超えるときは、分析役が呼び出されている間に溜まった発話を分けて渡す
- **`live` の窓の終わりは、窓の幅の刻みの位置に置く。** 終わりの候補は「始まり + window」と、それに window を 1 回・2 回足した値（window × 3 まで）の 3 つ。壁時計（聞き始めからの秒）が過ぎた候補のうち、最も後ろを終わりにする（どれも過ぎていなければ、まだ閉じない）。返事の遅れや中断で遅れて閉じても、時計の秒では閉じない。例: 窓幅 5 秒で 0:00〜0:05 の窓を書いたあと 0:05 に中断し、中断の間の 0:08 に打った行があって 0:12 に再開したら、次の窓は 0:05〜0:10（0:05〜0:12 ではない）、その次は 0:10 から。`rt.py` とページは同じ足し算で候補を作る（掛け算にすると、始まりが小数のとき最後の桁が食い違うことがある）。`file` の窓の終わりは「始まり + window」だけ。素材の終わりで閉じる最後の窓は下の「`live` の終わり方」
- 発話が1つも無い窓では分析役を呼ばず、`step` も書かない。だから `step.lines` は常に1行以上
- **ある窓の判断を全部書き終えるまで、次の窓を開けない。** 次の発話を読むのは、書いた後

1回の追記（バッチ）の形:

```
step → （card / hold / close / fix / group / rename / top / echo / list を順不同で）→ note
```

- 1 件目はいつも `step`。`note` はちょうど1件（置く位置は末尾が習わし。検査は件数だけを見る）
- 例外は `open`（新しいログの先頭）・`end`・`pause` で、それぞれ**1件だけの追記**として書く。他のイベントと同じ追記に混ぜない（下の語彙）
- バッチの中で後ろのイベントが前のイベントを指せる（例: このバッチで出したカードで保留を閉じる）。**指す相手は、既存か、このバッチでそれより前に並んだものに限る**

時刻は2種類ある。

| 名前 | 欄 | 単位 | 誰が決めるか |
|---|---|---|---|
| **素材時間** | `t` | 秒（会議の頭からの経過。素材ログの `t` と同じ尺）。0 以上 | 分析役が書く |
| **壁時計** | `at` | ISO 8601 の UTC（例 `2026-10-07T09:00:30Z`）。数字は半角、暦にある日時だけ | **道具が押す。** 分析役が `step`・`end`・`pause` に書いた値は、検査の前に捨てる（どんな値を書いても、それを理由には拒まない） |

`live` の記録では、壁時計は聞き終えた時刻より前には押せない。`step.at − open.t0 ≧ step.t[1]`（P27）。

## 素材ファイルの形

`file` の記録で `rt.py` が読む素材と、ページの「ファイル」の入口が読む素材は、**同じ決まりで同じ発話の列に読み、同じ行を同じ知らせにする**（素材を読み直して窓や話者を照らす P07・P20・P29 の前提）。
共通の試験素材と期待値は `tests/fixtures/materials.json` に並べてある。書き方ごとの素材（`alone`・`tsv`・`inline`・`vtt` と、書き方の混ざった素材・最後の発話より後ろに知らせのある素材・発話の無い素材）と、それぞれの `*.expect.json`（書き方・発話の列・読めない行・読めないバイトを含む行 `bad_bytes`・時刻が飛んでいる行・時刻で始まる本文の行・黙って飛ばした行・知らせを付ける発話・発話の無い素材を断る文 `refuse`・窓幅 30 秒で流したときの窓とその窓の知らせの文）。両方の実装がこれと一字違わず同じ結果を返すことを試験で縛る。

### 書き方は 4 つ

素材を読み始めたところで、次の 4 つのどれか 1 つに決まる。決まった書き方は、素材の途中で変わらない。

| 書き方 | どう決まるか | 行の例 |
|---|---|---|
| `alone`（時刻の行と本文の行） | 見出しの後の最初の時刻のある行が、時刻だけの行 | `0:05` の次の行に `始めます` |
| `tsv`（表） | 最初の時刻のある行が、タブで区切った表の行 | `0:05<TAB>甲<TAB>始めます` |
| `inline`（時刻と本文を空白で区切った行） | 最初の時刻のある行が、時刻＋空白＋本文の行 | `0:05 甲: 始めます` |
| `vtt`（WebVTT の字幕） | 先頭の空でない行が `WEBVTT` で始まる。または、書き方が決まる前に字幕の時刻の行の形の行（下の 12。`00:00:01.000 --> 00:00:04.000` のように、数字と `:`・`.` だけの字＋`-->`＋数字と `:`・`.` だけの字）が来る | 会議の道具が書き出す字幕のファイル（`WEBVTT` の行の無い書き出しも） |

素材の名前の拡張子（`.txt`・`.tsv`・`.vtt`）では決めず、中身だけで決める。だから `.vtt` の名前でも、先頭が `WEBVTT` でなく、書き方が決まる前に字幕の時刻の行の形の行も来なければ `vtt` としては読まない。`.txt` の名前でも、先頭が `WEBVTT` なら `vtt` として読む。

時刻のある行（下の 7）より先に字幕の時刻の行の形の行が来たときだけ `vtt` になる。先に時刻のある行で `alone`・`tsv`・`inline` に決まった素材は、あとで字幕の時刻の行の形の行が来ても `vtt` に変わらない（その書き方の決まりで読む）。区切りに `,` を使う字幕の時刻（`00:00:01,000 --> …`。SRT の形）は字幕の時刻の行の形に当たらないので、`vtt` にはならない。

### 字の決まり（4 つの書き方で同じ）

1. **文字**: UTF-8。先頭の BOM は捨てる。UTF-8 として読めないバイトは置換文字（U+FFFD）に置き換え、置換文字を含む行は読めない行にする（下の 9b の (c)。どの書き方でも）
2. **行**: LF だけで分ける。CR は行の区切りにしない（行の前後の空白として除く）。最後の行に改行が無くてもよい。行番号は 1 から数え、空の行も数える
3. **空白**: 半角スペース・タブ・CR・全角スペースの 4 つだけを指す。前後の空白を除いて空になる行は読み飛ばす（本文の続きは切れない。`vtt` では字幕の区切り）
4. **全角を直す**（`alone`・`tsv`・`inline`）: 時刻として読む字（下の 5 の時刻と、行の頭）は、当てる前に全角の数字（０〜９）と全角のコロン（：）だけを半角に直す。本文は直さない。全角のピリオドなど、ほかの字は直さない
5. **時刻の書き方**（`alone`・`tsv`・`inline`）: `分:秒` か `時:分:秒`。数字は半角の 0〜9 だけ。先頭の数（分か時）は 1〜6 桁、続く数はちょうど 2 桁で 00〜59。秒の後ろに小数部（`.` と 1 桁以上の数字）を付けてよい。値は「整数の秒」に「小数部」を足したもの（秒）
6. **時刻らしい字と、行の頭**: 時刻らしいとは、全角を直したあとで、数字で始まり、数字と `:` と `.` だけでできていて、`:` を 1 つ以上含むこと（時刻として読めるかは問わない）。行の頭は、前後の空白を除いた行の、最初の半角スペースか全角スペースの手前まで（無ければ行の全体）

### `alone`・`tsv`・`inline` の行

7. **時刻のある行**: 新しい発話を始める行。次の 3 つの形
   - **時刻の行**（タブを含まない）: 前後の空白を除いた行の**全体**が時刻の書き方に合う行。話者無し、本文は空で始め、続く行で埋める
   - **表の行**（タブを含む）: 行をタブで列に分け、1 列目の前後の空白を除いたものが時刻の書き方に合う行。列が 3 つ以上なら 2 列目が話者（前後の空白を除き、終わりの「:」「：」の並びを落とし、もう一度前後の空白を除いたもの。空になれば話者無し。打つ入口とメモ帳の「話者<TAB>本文」と同じ）、3 列目以降をタブでつないで前後の空白を除いたものが本文。列が 2 つなら話者無し、2 列目が本文
   - **時刻＋空白＋本文の行**（タブを含まない）: 行の頭が時刻の書き方に合い、そのあとに空白と本文が続く行。**`tsv` と `inline` でだけ**時刻のある行にする（書き方がまだ決まっていないときも。その行で `inline` に決まる）。本文は行の頭より後ろの字で、そこに下の「話者の切り出し」を当てる。例: `0:08 係: 古い紙は月末に外します。` は話者「係」。`0:45 乙 反対です` は話者無しで本文「乙 反対です」（「名前: 」の形でないので話者にしない）。`0:48 から 0:50 までは休憩です。` は 0:48 の発話で、本文は「から 0:50 までは休憩です。」（字は落とさないが、行の頭の時刻は本文に残らない）
8. **読めない行**: 時刻を書いたつもりらしいのに、時刻として読めない行。次のどれか
   - タブを含むのに、1 列目が時刻の書き方に合わない行（秒が 1 桁、区切りの打ち間違い、表の見出しの行など）
   - タブを含まず、行の**全体**が時刻らしいのに、時刻の書き方に合わない行（`0:5`・`1:2:3:4`・`12:345` だけの行など）
   - タブを含まず、行の頭が時刻らしいのに時刻の書き方に合わず、空白と本文が続く行（`0:3 係: …`・`1:2 の比で…`）。**`tsv`・`inline` と、書き方がまだ決まっていないとき**。`alone` では 9 の時刻で始まる本文の行にする
   - 読めない行のあとに続く、タブを含まない行（次の時刻のある行まで）。読めない行の本文の続きにあたるので、前の発話には混ぜない
   - 下の 9b の (a) の行で、書き方がまだ決まっていないとき。9b の (c) の行（どの書き方でも）

   読めない行は発話にしない。最初の時刻のある行より前でも同じ扱い（見出しとして黙って飛ばさない）。読めない行に来たら、まだ出していない発話はそこで閉じる（読めない行より後ろの字を、前の発話の本文に足さない）
9. **時刻で始まる本文の行**（`alone` だけ）: タブを含まず、**行の頭**が時刻らしく、そのあとに空白と本文が続く行（「9:00 から始めて、」「12:00 に昼休みを取ります。」「0:45 甲 反対です」「1:2 の比で」）。行の頭が正しい時刻でも、時刻のある行にしない。読めない行にもしない。10 と同じく**直前の発話の本文の続き**にして知らせる（`timehead`）。時刻のある行にしたいなら、時刻だけを 1 行に書く
9b. **時刻らしい頭の行**（タブを含まない行の (a)(b) と、どの行にも当たる (c)）。次の形の行は、黙って本文の続きにも見出しにもしない
    - (a) **時刻に字が続く頭**: 行の頭（6）が時刻らしくなく、全角を直した頭の先頭から時刻の書き方（5）を最も長く取った部分が時刻として読め（続く数が 00〜59）、そのすぐ後ろに字が続く行。例「0:45司会：次の議題です」「1:30甲 反対です」「9:00から始めます」「0:45.司会」（小数点の後ろに数字が無いので、時刻は「0:45」まで）。行の頭が時刻らしい行（「1:305 の比で」）は (a) ではなく、8・9 のまま
    - (b) **括弧で囲んだ時刻**: 前後の空白を除いた行の最初の字が `[` `(` `（` `【` のどれかで、そのあと最初に来る対の閉じ括弧（`]` `)` `）` `】`）までの中身（前後の空白を除き、全角を直す）が時刻の書き方に合う行。閉じ括弧の後ろは空白でも字でもよく、何も無くてもよい。例「[0:45] 甲: …」「(1:30)乙：…」「【１:０５】」「[ 0:55 ] 乙: …」
    - (c) **読めないバイトを含む行**: 行の中に置換文字（U+FFFD）がある行。タブを含む行・時刻のある行・`vtt` の行も含む

    扱いは書き方で決まる。

    | 形 | `alone` | `tsv`・`inline` | 書き方がまだ決まっていない |
    |---|---|---|---|
    | (a) | 直前の発話の本文の続きにして知らせる（`timehead`） | 同じ | 読めない行（見出しとして黙って飛ばさない） |
    | (b) | 直前の発話の本文の続きにして知らせる（`timehead`） | 括弧の中の時刻の新しい発話。本文は閉じ括弧より後ろの字で、そこに下の「話者の切り出し」を当てる。後ろに何も無ければ、時刻だけの行と同じく続く行で本文を埋める | その行で `inline` に決め、括弧の中の時刻の新しい発話 |
    | (c) | 読めない行（知らせの種類は `badbyte`） | 同じ | 同じ。書き方の見分けにも使わない（字幕の時刻の行の形でも `vtt` に決めない） |

    - 読めない行の続きの中（8 の 4 つ目）では、(a) と `alone` の (b) も読めない行。`tsv`・`inline` の (b) は時刻のある行なので、読めない行の続きはそこで終わる
    - (c) の行に来たら、まだ出していない発話はその手前で閉じ、続く行は読めない行の続きになる（8 と同じ）
    - タブを含む行には (a)(b) を当てない（1 列目が時刻の書き方に合わなければ、今までどおり 8 の読めない行。「[0:52]<TAB>係<TAB>…」も読めない行）
10. **時刻の無い行**: 7〜9b のどれにも当たらない行（タブを含まない）。前後の空白を除いて、**直前の発話の本文の続き**にする（本文が空でなければ半角スペース 1 つを挟む）。最初の時刻のある行より前なら、見出しとして黙って読み飛ばす。本文の途中に時刻があるだけの行（「午後は 13:00 から再開です。」）もこれ

7〜9b から分かること（事実。ページの読み手で、共通の試験素材と小さな例を読んで確かめた）:

- 素材の**全部**を「0:05 甲 始めます」のように空白で区切って書くと、`inline` として 1 行ずつ発話に読む（前の版では発話が 0 件だった）。話者を切り出すのは「甲: 始めます」「甲：始めます」の形のときだけ
- 見出しの中に「10:00 から始めます」のような、正しい時刻と空白で始まる行があると、その行が最初の時刻のある行になり、書き方は `inline` に決まる（その行は 10:00 の発話になる）。見出しに時刻を書くなら、時刻の前に字を置く（「開始 10:00」）
- `tsv` の素材に、表の行ではない「0:30 甲 一つ目の話です」のような行が混ざっていたら、それぞれ別の発話になる。`alone` の素材に混ざっていたら、前の発話の本文の続きになり、知らせが出る
- だから `alone` の素材に「0:45 甲 反対です」のような行が混ざると、その行の話は前の発話の本文に入り、前の発話の窓で（0:45 より早い窓で）分析役に渡る。道具が先の行を読みに行ったのではなく、素材のその行を前の発話の本文として読んだ結果で、その窓に時刻で始まる本文の行の知らせが出る。0:45 の発話として読ませたいなら、「0:45」だけを 1 行に書く
- 同じことが、どの書き方でも 9b の (a) の行（「0:45司会：次の議題です」）と、`alone` の (b) の行で起きる。どれも、その窓に時刻で始まる本文の行の知らせが出る（7 回目の版までは、知らせの出ないまま前の発話の本文に入っていた）
- 9b に当たらない形は、今までどおり 10 の時刻の無い行で、知らせは出ない。括弧の中が時刻の書き方に合わない行（「[0:5] 甲: …」）、対にならない括弧（「[0:45) 甲: …」）、時刻らしい字に続く字があっても先頭が時刻として読めない行（「1:60分の話」「16:9の画面」）がこれにあたる。ページの読み手で小さな例を読んで確かめた。こうした行が素材の時刻の打ち間違いなら、その話は前の発話の窓で知らせ無しに渡る（残る危険）
- SRT の字幕（時刻のミリ秒の区切りが「,」）を `.txt` にした素材では、「00:00:01,000 --> …」の行が (a) にあたる。書き方が決まる前なので読めない行になり、発話が 0 件で断られるときの文に、読めない行の知らせが続く

### `vtt` の行

11. **塊**: 空行で区切った行の並びを塊と呼ぶ。先頭の `WEBVTT` の行から最初の空行までの塊（見出し）と、`NOTE`・`STYLE`・`REGION` で始まる行から始まる塊は、黙って飛ばす。`WEBVTT` の行の無い字幕では、`vtt` に決めた字幕の時刻の行より前の行は、書き方が決まる前の行として扱ったまま（空でない行は見出しとして黙って飛ばし、読めない行は読めない行のまま。識別子にあたる行も飛ばした行に数える）
12. **字幕の時刻の行**: `-->` を含む行。どこにあっても（見出しや NOTE の塊の中でも、前の字幕との間に空行が無くても）新しい字幕を始め、前の字幕はそこで閉じる。形は `始まり --> 終わり` で、終わりの後ろに空白かタブで区切った設定（`align:start` など）が続いてもよい。`-->` の前後の空白は無くてもよい
13. **字幕の時刻**: `[時:]分:秒.ミリ秒`。時は 1〜6 桁で、無くてもよい。分と秒はちょうど 2 桁で 00〜59、ミリ秒はちょうど 3 桁。**全角は直さない。** 始まりと終わりの両方がこの形に合うときだけ字幕を始める。発話の時刻は、始まりのミリ秒を切り捨てた整数の秒（終わりは使わない）
14. **識別子**: 塊の最初の行のすぐ次が字幕の時刻の行なら、その最初の行は識別子として黙って飛ばす（数字でも、`7d3e/12-0` のような字でもよい）
15. **字幕の本文**: 時刻の行の次から、空行か次の時刻の行か素材の終わりまでの行を、半角スペース 1 つでつないだもの。頭が `<v 名前>` か `<v.クラス 名前>` なら、その名前（前後の空白を除いて空なら話者無し）が話者。`<…>` の札をすべて除き、`&amp;`・`&lt;`・`&gt;`・`&nbsp;`・`&quot;`・`&#39;` の 6 つだけを 1 回だけ字に戻し（`&amp;lt;` は `&lt;` になる）、前後の空白を除いたものが本文。1 つの字幕が 1 つの発話
16. **読めない行**: 時刻の形に合わない字幕の時刻の行と、そこから空行（か次の字幕の時刻の行）までの行。また、見出し・NOTE などの塊でも、字幕の時刻の行か「識別子＋字幕の時刻の行」で始まる塊でもない塊は、空行（か次の字幕の時刻の行）までのすべての行。読めないバイトを含む行（9b の (c)）も、字幕の時刻の行・字幕の本文の行・見出しや NOTE の塊の行のどこにあっても読めない行で、まだ出していない字幕はその手前で閉じ、その行から空行（か次の字幕の時刻の行）までを読めない行にする（識別子かもしれない行がその直前にあれば、それも読めない行）。ただし先頭の `WEBVTT` の行だけは、読めないバイトを含んでも見出しの塊の頭として扱う

### どの書き方でも同じ決まり

17. **本文の無い発話**: 本文が空のまま次の時刻のある行（か読めない行、素材の終わり）に来た発話は、発話にしない（番号を使わない）
18. **番号**: 発話の `i` は 1 から振る
19. **時刻を単調にする**: 発話の時刻が直前の発話より前なら、直前の発話の時刻に揃える。揃えたあとの時刻を、窓・素材ログ・検査のすべてで使う
20. **時刻が飛んでいる行**: 番号を振った発話ごとに、揃える前の時刻を、1 つ前に番号を振った発話の揃える前の時刻と比べる。前より小さい（巻き戻り）か、600 秒（10 分）より大きく先へ進んでいれば、その発話の時刻のある行（`vtt` では字幕の時刻の行）を「時刻が飛んでいる行」とする。最初の発話は比べない。拒まず、発話もそのまま読む（時刻は 19 のとおり揃える）
21. **発話の無い素材**: 読み終えて発話が 1 つも無い素材は、`rt.py` の `file` の `open` も、ページのファイルの入口も、記録を作らずに断る（判断ログも素材ログも作らない）。断りの文は、次の 1 文と、そのあとに素材の知らせの文（下の「知らせ」の文。知らせがあるときだけ）を並べたもの。どちらの実装も一字違わず同じ文を出す（共通の期待値の `refuse`）
    - 時刻のある行（`vtt` では、形の合う字幕の時刻の行）が 1 つも無いとき: 「時刻のある行が 1 つもありません（見出しとして飛ばした行 N 行）。素材の形は format/FORMAT.md の「素材ファイルの形」を見てください」。N は黙って飛ばした行の数（見出し・`WEBVTT` の行・`NOTE` などの塊・識別子）
    - 時刻のある行はあるが、どれも本文が空だったとき（17）: 「本文のある発話が 1 つもありません（時刻のある行 N 行は、どれも本文が空でした）。素材の形は format/FORMAT.md の「素材ファイルの形」を見てください」。N は時刻のある行の数
    - `WEBVTT` の行が無いまま、字幕の時刻の行の形の行で `vtt` に決めた素材なら、上の文の次に「N 行目を字幕の時刻の行（「-->」を含む行）とみなし、そこから後ろを字幕（WebVTT）として読みました。字幕でなければ、その行の「-->」を書き換えてください」を添える（N は `vtt` に決めた行の番号。見出しの「10:00 --> 11:00 定例」のような行で `vtt` に決まった素材を持つ人に、時刻の行が読まれなかったわけを言う）

    例: 字幕の時刻の区切りに `,` を使う SRT の形の素材は、どの行も時刻のある行にならないので、1 つ目の文で断られる（「00:00:01,000 --> …」の行は 9b の (a) なので、読めない行の知らせが続く）。0 バイトの素材と、空白だけの行しか無い素材も、1 つ目の文（見出しとして飛ばした行 0 行）で断る。ページの「聞き始める」も同じ文で断る

ページの打つ入口と音声認識の入口も、確定した発話の `t` を直前の発話以上に揃える（壁時計が戻っても発話の時刻は戻らない）。

### 読めない行と、読めないバイトを含む行と、時刻の飛びと、時刻で始まる本文の行の知らせ

- **黙って捨てない。** 読めない行ごとに（読めないバイトを含む行も）、素材ログへ `{"ev":"unreadable","line":行番号,"raw":行の中身}` を残す。`raw` は前後の空白を除いた行の先頭 100 字（コードポイントで数える）。道具が `at`・`t` を書き足すことがある。素材ログに残すのは読めない行（読めないバイトを含む行も、種類は `unreadable` のまま）だけ（時刻が飛んでいる行と時刻で始まる本文の行の中身は、発話に入っている）
- 知らせの種類の名前は、読めない行が `unreadable`、読めないバイトを含む行（9b の (c)）が `badbyte`、時刻が飛んでいる行が `jump`、時刻で始まる本文の行（9 と、9b の (a)・`alone` の (b)）が `timehead`（`rt.py` とページで同じ）
- **知らせを付ける発話**:
  - 発話の本文に入った行（時刻で始まる本文の行）の知らせは、その行を本文に含む発話に付ける
  - どの発話にも入らない行（読めない行・読めないバイトを含む行と、その続き）の知らせは、後ろの最初の発話に付ける。読めない行の時刻は分からないので、後ろの発話より先には出さない
  - 時刻が飛んでいる行の知らせは、その発話に付ける
  - 最後の発話より後ろの知らせは、最後の発話に付ける。発話が 1 つも無ければ、どの発話にも付かず、素材を断る文（21）の後ろに並べて出す
- **知らせる時期**: 知らせを付けた発話を渡す窓で出す。最後の発話より後ろの知らせも、最後の発話を渡す窓で出す（素材の終わりを告げるときまで遅らせない）。ページの入口の欄は、窓を分析役に渡したときに、その窓の発話に付いた知らせを出す（同じ時刻の発話が多くて 40 件の上限で次の窓に回った発話の知らせは、その発話を渡す窓まで出さない。最後の発話より後ろの知らせは、素材を読み切ったときに最後の発話を渡した窓の欄に足す）
  - ページの入口の欄には、いまの窓の文のほかに「前の窓までの知らせ」の 1 行（種類と行番号だけ）がある。続きから聞いたとき（同じ名前の記録を開き直したとき）は、この 1 行は、開き直した後に渡した窓の知らせしか持たない。開き直す前に渡した窓の知らせは、前に聞いたときの欄にだけ出た（7 回目の確かめでページを動かして確かめた。`rt.py` にはこの 1 行が無い）
- **文**: 1 つの窓の知らせは、種類ごとに 1 文にまとめ、読めない行・読めないバイトを含む行・時刻が飛んでいる行・時刻で始まる本文の行の順に出す（知らせの無い種類は出さない）。説明は 1 つの窓で種類ごとに 1 回だけ。`rt.py next` の出力とページの入口の知らせの欄で、同じ文にする
  - 「読めない行があった（{行}）。発話にしていない。時刻の書き方を確かめる」
  - 「読めないバイトを含む行（{行}）。発話にしていない。素材の文字コードが UTF-8 かを確かめる」
  - 「時刻が飛んでいる行（{行}）。前に戻った時刻は前の発話の時刻に揃え、10 分を超えて進んだ時刻はそのまま読んだ」
  - 「時刻で始まる行は本文として読んだ（{行}）。時刻の行にするなら、時刻だけを1行に書く」

  {行} は、その窓のその種類の行番号を小さい順に最初の 5 つまで「・」でつないで「 行目」を付けたもの（「2・3 行目」）。6 つ以上なら後ろに「ほか N 行」を付ける（N は残りの数。「2・3・4・5・6 行目ほか 16 行」）。読めない行は右の逐語にも出る
- どれも拒む理由にはしない。直すなら素材ファイルを直して、新しい記録で読み直す

### 話者の切り出し（打つ入口と、メモ帳の「話者: 本文」）

ページの打つ入口（OS の音声入力もここに入る）と、`live` のメモ帳のタブを含まない行は、行の頭の「名前:」を話者として切り出す。行の前後の空白を除き、行頭から最初の「:」か「：」までを候補にし、次を**すべて**満たすときだけ話者と認める。認めないときは、行の全体が話者無しの本文になる。ここで言う空白は、下の「返事の読み方」に列挙した空白の集まり（JS の `trim` と同じ）。

- 1〜20 字（コードポイントで数える）で、空白を含まない
- 数字（半角の 0〜9 か全角の ０〜９）で始まらない
- 区切りが全角の「：」か、半角の「:」の直後が空白

例: 「司会: 始めます」「司会：始めます」は話者「司会」。「15:00までに送る」「9:00 から」「16:9 の画面」「https://example.com を見る」「0:05 司会: 始めます」は話者無し。「結論：A案」は話者「結論」になる（形からは話者名と区別できない）。

素材ファイルの `inline` の行（と `tsv` に混ざった時刻＋空白＋本文の行）は、行の頭の時刻より後ろの字にこの決まりを当てる。タブで区切った話者の列（素材ファイルの表の行、打つ入口とメモ帳の「話者<TAB>本文」）には、この決まりを当てない。話者の列は、前後の空白を除き、終わりの「:」「：」の並びを落とし、もう一度前後の空白を除いたものを話者にする（空になれば話者無し。「司会:」「司会 ：」は話者「司会」）。素材ファイルの表の行と、打つ入口・メモ帳で同じ。

### `live` のメモ帳

`live` の記録で `rt.py` が会議のあいだ見張るメモ帳も、字の決まり（1〜5）は同じ。違うのは次のところで、細かな手順は `prompts/for-claude-code.md` と `rt.py` の説明にある。

ページの打つ入口（打つ・貼る）も、1 行の読み方（下の「読み方は次のとおり」）と「空でない行はすべて 1 つの発話」は同じ。共通の期待値は `tests/fixtures/typed_lines.json` で、`rt.py`（`memo_kind`）とページ（`readTypedLine`）の両方がこの表と一字違わず同じ結果を返すことを試験で縛る。ページで 1 列目の時刻を落とした行が初めて来たときは、入口の知らせの欄に「打った行の 1 列目の時刻は使わない（届いた時刻で押す）」と出す（素材ログには残さない。入口の札は変えないので、「中断中」などの札を上書きしない）。ページの確定は「Enter か、入力が 2 秒止まったら」で、時刻はどの行もその確定の時刻になる。

- **発話の `t` は、いつも道具（`watch`）がその行を発話として足した時刻（会議の頭からの秒。整数の秒に切り捨て）。メモ帳に打った時刻は `t` に使わない。** 時刻を 1 か所打ち間違えても、それ以後の発話の位置はずれない。改行の無い最後の行は、下の 2 秒の確定のあとに足すので、その時刻になる
- **空でない行は、すべて 1 つの発話になる。** 1 行が 1 つの発話で、時刻の無い行の続きにはしない。`live` には読めない行も、時刻が飛んでいる行の知らせも無い。読み方は次のとおり
  - タブを含み、1 列目が**時刻らしい**行（上の 6。前後の空白を除き、全角の数字とコロンを直してから見る。時刻の書き方に合わなくてよい。「0:20」「1:2:3」「0:60」「12.5:00」）: 1 列目を落とす。残りの列が 2 つ以上なら「話者<TAB>本文」（3 列目以降はタブでつなぐ）、1 つなら、その列に上の「話者の切り出し」を当てる（「0:20<TAB>司会: 始めます」は話者「司会」）。素材ログの `raw` には打ったままの行を残す。`rt.py` は最初の 1 回だけ「メモ帳の時刻は使いません（届いた時刻で押します）」と知らせる
  - タブを含み、1 列目が時刻らしくない行（「0:2O」のように英字を含む列、「9:00 から」のように空白と字を含む列も）: 「話者<TAB>本文」として読む
  - 「話者<TAB>本文」の話者の列は、前後の空白を除き、終わりの「:」「：」の並びを落とし、もう一度前後の空白を除く（「司会:<TAB>始めます」「司会 ：<TAB>始めます」の話者は「司会」。空になれば話者無し）
  - タブを含まない行: 上の「話者の切り出し」で話者を切り出す。行の頭が時刻らしい行（「0:45 甲 反対です」「9:00 から」）は、上の決まりで話者と認められないので、行の全体が話者無しの本文になる
  - どの形でも、本文が空になる行（時刻だけ・話者だけの行）は、行の全体（空でない列を半角スペース 1 つでつなぐ）を話者無しの本文にする
- 時刻を単調にする処理（19）は、届いた時刻が戻ったとき（時計が戻ったとき）にだけ効く
- **確定**: 改行で終わった行は、見つけたときに発話として確定する。改行の無い最後の行は、**同じ中身のまま 2 秒変わらなければ**確定する（ページの打つ入口の「Enter か 2 秒で確定」と同じ）。確定した後にその行へ字が足されたら、読み終えた行の書き換えとして扱う（どの行を拾い、どの行を知らせるかは下の「読み終えた行との突き合わせ」）
- 読み終えた行はあとから直せない。書き換え・消し・分け・まとめは道具が見つけて知らせ、新しい行は末尾に足したものだけを拾う。書き換えの知らせには「読み終えた行は直せません。直した行や新しい行は、メモ帳の末尾に足してください」を添える
- **行の鍵（突き合わせで比べる中身）**: 下の突き合わせでは、行どうしを「鍵」で比べる。鍵は、前後の空白を除いた行から、上で落とす時刻の列（タブを含む行の 1 列目が時刻らしいもの）を落とし、残りの前後の空白を除いたもの。時刻の列の無い行は、行そのものが鍵。だから「12:30<TAB>乙<TAB>はい」と「12:31<TAB>乙<TAB>はい」と「乙<TAB>はい」は同じ鍵になる。並べるとき・消えた行の覚えと組にするとき・もう組にしない覚え（下の 6）を見るとき、どれも鍵で比べる
- **時刻の列だけの直し**: 読み終えた行と組になった行（下の 3）の鍵が同じで、打ったままの行が違うもの（1 列目の時刻だけを直した行）は、記録に効かない。`rt.py` は「読み終えた行の時刻の列だけが書き換わった（N 行目）」と「時刻の列だけの直しは記録に効きません（時刻は届いた時刻で押します）」を知らせ、末尾に足すようにとは言わない。同じ鍵の行が続くとき（「12:05<TAB>乙<TAB>はい」が 2 行など）に、前の行・後ろの行・途中の行の時刻だけを直しても、その直しを元に戻しても、発話は二重にならず、起きていない「消えた」の知らせも出ない（ページの打つ入口は確定した行を欄から消すので、この場面が無い）
- **読み終えた行との突き合わせ**（`rt.py` の `watch`）。原則は「黙って欠かさない・黙って二重にしない」。発話にしなかった行は、下の 8 の場面で行番号を挙げて知らせる。ただし、メモ帳の中身からは見分けられず、知らせが出ない形がある（知らせの出ない二重を含む。下の 12）。メモ帳を読むたびに、次の手順で新しい発話を決める
  1. 前に読んだときのメモ帳の確定した行の並びを C、いまのメモ帳の確定した行（改行の無い最後の行は、上の 2 秒の確定のあと）を M とする。道具は C とは別に、次の 2 つを覚えておく。消えた読み終えた行の中身（以下「消えた行の覚え」。消えた保存のあとも、下の 5 で組にするか、6・7 で外すまで残る）と、もう組にしない中身（以下「もう組にしない覚え」。6・7 で消えた行の覚えから外したもの）。C の行のうち、戻した行とみなして知らせた行には、その印を付けておく
  2. **書き換えの無いとき**: M の頭が C と鍵でちょうど同じなら、C の行はどれも同じ位置の M の行と組になり、新しい発話は M の残りの行。知らせは無い（打ったままの行が違う組は、上の「時刻の列だけの直し」）
  3. **書き換えのあったとき**: C と M の共通の頭と共通の尻を外し、残った真ん中どうしを、順を保ったまま同じ鍵の行を最も多く組にする並べ方（最長共通部分列。動的計画法で求める）で並べる。並べ方が複数あるときは、C の側は後ろのほうの行を組に残し、M の側は前のほうの行を組にする並べ方を選ぶ（M の後ろの行を末尾の新しい行に残し、新しく足した行が前に消えた同じ中身の行に吸われないため）。この決め方は試験で縛る
  4. M の行のうち組にならなかった行は、組になった M の最後の行より後ろにあれば「末尾の新しい行の候補」、前にあれば「読み終えた行の間の行」。C の行のうち組にならなかった行は「消えた行」で、そのうち発話にした行を消えた行の覚えに足す
  5. 組にならなかった M の行を、前から順に次のように分ける
     - 末尾の候補で、組になった C の行に、同じ鍵で「戻した行とみなして知らせた」印の付いた行があれば、知らせのとおり末尾にもう一度打った行とみなして**新しい発話にする**。消えた行の覚えに同じ鍵の行が残っていても組にしない。印はこの 1 回で外す。そのうえで、消えた行の覚えともう組にしない覚えから同じ鍵の項目をすべて除き、除いた項目があったときだけ下の 8 の「末尾にもう一度打った行」の知らせを出す（除く項目が無ければ、この行と二重になりうる消えた行が無いので知らせない）。ただし、同じ保存の末尾の候補に同じ鍵の行がまだ続くときは、もう組にしない覚えの 1 つだけを除き（あれば知らせる）、残りの覚えは後ろの行たちに回す（後ろの行は、消えた行の覚えと組になれば戻した行、もう組にしない覚えに当たれば 6 の打ち直した行として名指される）
     - そうでなく、消えた行の覚えに同じ鍵の行があれば、覚えたのが新しいほうの 1 つと組にして、発話にしない（戻した行。末尾の候補でも、読み終えた行の間の行でも同じ。覚えの 1 つと組になれるのは行 1 つだけ）
     - どちらでもなければ、末尾の候補は新しい発話にし、読み終えた行の間の行は拾わない
  6. 戻した行と組にした覚えと同じ保存で消えた、同じ鍵の行がほかにも覚えに残っていれば、それはもう組にしない（消えた行の覚えから外し、もう組にしない覚えに移す）。もう組にしない覚えにある鍵の行が、あとで末尾の新しい発話として現れたら、新しい発話にしたうえで知らせ（下の 8 の「末尾にもう一度打った行」）、もう組にしない覚えからその鍵の項目を除く。同じ保存の末尾に同じ鍵の行が何行も続くとき（消した行をまとめて元に戻したときなど）は、覚えの項目を前の行から 1 つずつ配り、最後の行に残りをすべて渡す。だから、その保存では覚えにあった数までの行をそれぞれ名指し、それより後ろの同じ鍵の行は知らせずに新しい発話にする。この保存のあとは、もう組にしない覚えにその鍵の項目は残らない。だから、相づちの「はい」を消したあとで新しい「はい」を何度打っても、知らせが出るのは最初に打った保存だけ（その保存で何行も打てば、覚えにあった数までの行）。この決め方のために、知らせの出ない二重が起きうる（下の 12）
  7. 発話にした行の半分以上が一度に消え（消えた読み終えた行の数が、組になった読み終えた行の数以上）、**しかも消えた読み終えた行が 3 行以上**の保存では、読み終えた行と組になった M の行をすべて名指す（「残った行」。前に読み終えた行の間の行として拾わなかった行と組になった行も含む）。メモ帳を空にするのと同じ保存で、前の行と同じ中身の行を打ったとき、その行が前の行とみなされたことを黙らずに言うため。名指した行と同じ鍵で、この保存で消えた行も、もう組にしない（6 と同じ）。消えた読み終えた行が 2 行以下なら名指さない（2 行のメモ帳で最後の行を書き換えただけで、書き換えていない 1 行目まで名指さないため）。この敷居のために、名指しが出ない形がある（下の 12）
  8. 発話にしなかった行は、次の場面で行番号を挙げて知らせる。文は次のとおり（行の中身は出さない）
     - 戻した行（5）: 「消えた行と同じ中身なので、戻した行とみなして足していません（N 行目）。新しい発話なら、末尾にもう一度打ってください」
     - 読み終えた行の間の行（5）: 「読み終えた行の間の行は拾いません（N 行目）。新しい発話なら、末尾に打ってください」
     - 残った行（7）: 「読み終えた行の半分以上が一度に消えました。残った行（N 行目）は読み終えた行と同じ中身なので、前からある行とみなして足していません。新しい発話なら、末尾にもう一度打ってください」
     - 末尾にもう一度打った行（5・6）: 「消えた行と同じ中身ですが、末尾にもう一度打った行とみなして足しました（N 行目）。消した行を戻しただけなら、同じ発話が二重に入っています」。この行は新しい発話として窓に入る。知らせのとおり打ち直したのか、消した行を戻しただけなのかは、道具には見分けられないので、黙らずに知らせる
     - 消えた行: 「読み終えた行が消えた（いまの N 行目の手前）」。続けて消えた行は 1 文にまとめて行数を言う（「読み終えた行が 3 行消えた（いまの 1 行目の手前）」）。拾っていなかった行（読み終えた行の間の行）が消えたときは知らせない
     - 時刻の列だけの直しは、上の「時刻の列だけの直し」のまま
  9. 戻した行とみなされた行をメモ帳に残したまま、知らせのとおり末尾にもう一度打つと、その行は新しい発話になる（5 の 1 つ目）。同じ中身の消えた行を別の保存の分として覚えていても、打ち直した行をまた戻した行にはしない。戻した行を消してから末尾に打ち直したとき（戻した行を末尾へ動かしたとき）は、下の 10 の「末尾へ動かす」と同じで、末尾の行はまた戻した行になる
  10. よくある直しの結果: 読み終えた行を末尾へ動かすと、元の場所は「消えた」、末尾の行は戻した行になり、拾わない。読み終えた行の途中を書き換えると、元の行の「消えた」と、書き換えた行の「読み終えた行の間の行は拾いません」の 2 つの知らせになる。最後の行に字を足したときだけは、足した後の行が末尾の新しい発話になり、元の行を「消えた」と知らせる
  11. 速さ: 共通の頭と尻を外したあとで、メモ帳 3000 行・真ん中 300 行の突き合わせが 0.2 秒以内
  12. **知らせが出ない形・知らせが実際の操作と合わない形**（事実。道具が見るのは保存ごとのメモ帳の中身だけで、保存と保存の間に何をしたかは見えない）
     - 前と同じ中身の行が、組になる位置に残って見えるとき、消して打ち直した行でも前からある行とみなし、名指さない。例: 2 行のメモ帳（「甲: 提案です」「乙: はい」）を空にして「乙: はい」を打つと、「読み終えた行が消えた（いまの 1 行目の手前）」だけが出て、打った「はい」は発話にならない。3 行のメモ帳を空にして最後の行と同じ中身を打っても同じ（消えた読み終えた行が 2 行で、7 の敷居に届かない）。3 行以上のメモ帳で最後の 2 行を消し、同じ保存で消した 1 行目と同じ中身を打つと、最後の 1 行だけを消したのと同じ中身になり、「消えた」の 1 文だけが出る（8 回目の版の `rt.py` に、それぞれの保存を直に当てて確かめた）
     - 一度「読み終えた行の間の行は拾いません」と名指した行が、あとでメモ帳を空にして元に戻すと、名指されずに新しい発話になる。そのとき素材ログでの発話の順は、メモ帳の行の順と違う（8 回目の版の `rt.py` で確かめた。欠けも二重も無い）
     - 最後の読み終えた行のすぐ手前に、その行と時刻の列だけが違う同じ鍵の行を足すと（手前の読み終えた行をそう書き換えても）、最後の行の時刻の列を直して末尾に同じ鍵の行を打った保存と中身が同じになる。道具は後のほうとみなし、「読み終えた行の時刻の列だけが書き換わった」と知らせて、末尾の行を新しい発話にする（足した行は間の行として名指されず、同じ中身の発話が 1 つ増える。メモ帳の同じ鍵の行の数と、素材ログの発話の数は合う）。並べ方を変えると、時刻の列を直して末尾に打った場面のほうが黙って欠けるので、変えていない（8 回目の乱数の試験で見つけた。並べ方は試験で縛る）
     - 読み終えた行を消したあとで打ち直しの知らせ（6）が出て、そのあと元に戻す（undo）を重ねて消す前の行まで戻すと、戻った行のうちいくつかが名指されずに二度目の発話になる（**知らせの出ない二重**）。打ち直しの知らせで、もう組にしない覚えをその保存で使い切るため（6）。メモ帳を空にして知らせのとおり末尾に打ち直したあとにも、最後の数行を選んで打ち直したあとにも、元に戻す保存そのもので打ち直しの知らせが出たあとにも起きた。8 回目の版の `rt.py` に、7 回目の確かめの乱数の台本（1 回あたり 60 操作）を当て、行を時刻の列を落とした中身で見分けて数えた結果は、1000 回あたり、時刻の列の無いメモ帳で 3 件（種 1）と 1 件（種 2）、時刻の列を混ぜたメモ帳で 3 件（種 1）。どれも元に戻す操作の後だった。時刻の列を混ぜたメモ帳を、時刻の列まで含めた打った字のままで見分けて数えると 41 件に見えるが、増えた 38 件は、時刻の列だけが違う同じ中身の行のあいだで、どの行の発話とみなすかが入れ替わった数え方の違いで、中身ごとの発話の数は合う（上の 3 つ目の形がこれにあたる。途中に打つ・行の複製・途中の行を書き換える・元に戻すの後に出た）。覚えを 1 行ごとに 1 つずつ減らす決め方にすれば減らせる見込みがあるが（推測。試していない）、相づちを打つたびに知らせが出ることになり 6 の決めと合わないので、変えていない
     - 共通の頭も尻も無く、真ん中が動的計画法の上限（升目 25 万）を超え、目印になる行も無い大きな入れ替え（相づちだけの長いメモ帳をまるごと別の中身にするなど）では、知らせの数と行番号の並びが実際の操作と大きく違う（7 回目の確かめで測った。黙った欠けや二重は無かった）
     - 8 の文は行番号だけを出すので、どの行の話かは、メモ帳のその行番号を見て確かめる
- **突き合わせの知らせの残し方**: 知らせは素材ログに出来事として残す。同じ出来事は二度書かない（メモ帳が変わらない限り、毎秒書き足さない）。覚えから外したこと（6・7）も出来事として残すが、知らせには出さない。`next` と `next --last` は、知らせを、出来事の後で最初に届いた発話を渡す窓の出力に必ず出す。最後の発話より後ろで起きた出来事は、最後の窓（`next --last`）に出す。最後の窓をもう渡し終えていて渡す発話が残っていないときは、`next --last` は「（最後の発話より後ろで起きたメモ帳の出来事の知らせです。最後の窓で知らせたものも含みます）」に続けてその知らせを出し、そのあとで「渡す発話は残っていません」と言う。`--json` を付けたときは、このときも JSON で出す（下の「`live` の終わり方」）
- **メモ帳が見つからないとき**（`rt.py` の `watch`）: メモ帳が無い・フォルダになっている・読めない間は、空のメモ帳とみなさない（読み終えた行がすべて消えたことにしない）。`watch` は「メモ帳 … が見つかりません」（フォルダのときは「メモ帳 … はフォルダです」）で始まる知らせを、毎回ではなく、見つからなくなったとき・また見つかったときなど状態が変わったときに出す。`next` と `next --last` の出力にもこの知らせを出す（黙って 0 行の窓にしない）。メモ帳はファイルとして在るのに開けない間（ほかのアプリが掴んでいる・権限が無い）は、`next` の出力に「メモ帳 … を開けません」で始まる知らせを出し、`next --last` と `end` は開けるようになるまで同じ文で断る（開けない間に打った行が、知らせ無しに記録から欠けないように。8 回目の確かめ）

### `live` の終わり方

- **`rt.py next --last`**: `watch` がメモ帳の変化をすべて素材ログに書き終えたのを確かめてから、まだ窓にしていない発話を「最後の窓」として出す。待つのは次のどちらかがあるあいだ（`rt.py` の `memo_pending` の数え。`end` の断りと同じ数え）
  - いまのメモ帳を突き合わせると、素材ログに何かを書くことになる。新しい発話だけでなく、戻した行・読み終えた行の間の行・残った行・消えた行・時刻の列だけの直し・打ち直した行の出来事も数える（知らせに出ない片付けの出来事は数えない）
  - 改行の無い最後の行が、まだ確定していない（上の 2 秒の確定の前）

  書き終えた出来事の知らせは、最後の窓に出す。`watch` が回っていなければ、窓を出さずに断る（「watch が回っていません。メモ帳に、素材ログへまだ入っていない変化（…）が N 件あります…」）。メモ帳が見つからない・フォルダのときは待たずに、その知らせを最後の窓に出し、「すべて読みました」とは言わない
  - **最後の窓の終わり `t[1]`**（`rt.py next --last` とページの「聞き終える」で同じ）: 聞き終えた時計の秒（会議の頭からの秒を整数に切り捨てた値 H）。窓の幅の刻みには合わせない。中断の後に再開せずに聞き終えたときも同じ。窓の始まりは、いつもの窓と同じ（直前の窓の終わり。発話の無い窓を丸ごと飛ばすときは、窓の幅の刻みで先へ進める）
  - **H は、道具が最後の窓を閉じるときに読んだ時計の秒**で、人が聞き終えると決めた秒とは限らない（事実）。`rt.py` は `next --last` を打った後（メモ帳の変化を待った後）の秒。ページは、前の窓の返事を待っている間に「聞き終える」を押すと、返事を書き終えてから時計を読むので、押した秒より後ろになる（7 回目の確かめでページを動かして確かめた。窓幅 5 秒・7.3 秒に押し・前の窓の返事を 15.3 秒に書いた場面で、最後の窓は 0:05〜0:15、`end` の `t` は 18）。どちらも先を読むことにはならない（時計が進んだ所までしか渡さない）
  - ただし幅は `open.window × 3` まで。H が「始まり + `open.window × 3`」以上なら、終わりはその「始まり + `open.window × 3`」で、そこちょうどか後ろの発話は次の最後の窓に回す（`rt.py` は「append のあとで、もう一度 next --last を打ってください」と言う）
  - H のほうが手前で、まだ窓にしていない発話に H ちょうどの発話（同じ秒に届いた発話）があれば、その発話も窓に入るように、時計が次の秒へ進むまで待ってから閉じる。窓の終わりは、窓の中のどの発話の時刻よりも後になる
  - 例: 窓幅 10 秒で、直前の窓の終わりが 1:00、まだ窓にしていない発話が 1:08 にあり、1:26.4 に聞き終えたら、最後の窓は 1:00〜1:26（1:00〜1:20 ではない）。1:35 に聞き終えたら、1:00〜1:30。窓幅 5 秒で 0:05 に中断し、中断の間の 0:08 に打った行があって、再開せずに 0:22 に聞き終えたら、0:05〜0:20
  - 最後の窓にも 1 窓の発話の上限（40 件）と、上の縮め方が当たる。超えた分は、次の `next --last` で出る
  - 最後の窓の出力にも、メモ帳の突き合わせの知らせ（戻した行とみなした行・読み終えた行の間の行・消えた行など）を出す。最後の発話より後ろで起きた出来事の知らせも、ここに出す
  - 最後の窓の結びの文は「最後の窓です。メモ帳の行はすべて読みました（足していない行は上の知らせのとおり）。append のあとで end を打てます」。足していない行の知らせと並んでも食い違わないように、「すべて素材ログに入っています」とは言わない
  - 返事が検査に落ちて打ち直すときは、前に出した最後の窓をそのまま出す（同じ窓の回数を数え続ける）
  - 渡す発話が無ければ「渡す発話は残っていません。メモ帳の行はすべて読みました（足していない行は上の知らせのとおり）。end を打てます」と言う。`--json` を付けたときは、このときも JSON で `{"last": true, "window": null, "notices": [...]}` を出す（`notices` には、知らせと、この結びの文を入れる）
- **`rt.py end`** は、`live` の v2 の記録で次のどちらかのときは何も書かずに断り、「まだ渡していない発話が N 件あります。next --last で最後の窓を出し、追記してから end を打ってください」と言う
  - 素材ログに、判断ログのどの窓（`step.lines`）にも入っていない発話がある
  - メモ帳に、まだ素材ログに入っていない変化がある（上の `next --last` が待つのと同じ数え。新しい行だけでなく、出来事になる変化と、改行の無い最後の行も含む）

  N は、この 2 つを足した数。
- `rt.py append` に `end` だけの返事（バッチ）を渡したときも、`rt.py end` と同じ 1 つの断りを通る（まだ渡していない発話があれば、何も書かずに同じ文で断る）。`end` を書く道はどれも、この断りを通る
- **`end` の `t`**（道具が決める既定。`rt.py end` とページの「聞き終える」で同じ）: `live` は「聞き終えた時計の秒（聞き始めからの秒を整数に切り捨て）」と「直前の窓の終わり」の大きいほう。`file` は直前の窓の終わり（窓が無ければ 0）。どちらも直前の step の `t[1]` 以上になる
  - ここの「聞き終えた時計の秒」は、`end` を書くときに読み直した時計の秒。道具は時計を 2 回読む（最後の窓を閉じるときと、`end` を書くとき）ので、最後の窓の終わりと `end` の `t` は 1 秒ずれることがある（事実。`rt.py` もページも同じ作りで、食い違いではない）
- `rt.py end --t` で `t` を指定するときも、`live` の記録では、聞き終えた時計の秒より先には置けない（断る。聞き終える前の所に終わりを置かせないため。P27 と同じ考え）。試験の時計（環境変数 `KIKU_TEST_CLOCK=1` と `--now`）を使うときは除く
- だから `live` の聞き終え方は **`next --last` → `append` → `end`** の順。ページの「聞き終える」も、残りを最後の窓として渡してから `end` を書くので、まだ渡していない発話を残して終わることはどちらにも無い。最後の窓の終わりの決め方も同じ（上の `t[1]`）
- **ページの音声認識の入口で「聞き終える」を押したとき**は、止めたのに終わりの知らせ（`onend`）がまだ来ていない認識を、いま動いているものも、中断や再開で前に止めた古いものも、すべて待つ（上限は合わせて 3 秒）。そのあとで上と同じ流れ（最後の窓 → `end`）に進む
  - 待っている間に、どの認識が返した確定の結果も捨てず、最後の窓に入れる（中断のときと同じ）
  - 3 秒待っても終わりの知らせが来ない認識があれば、素材ログに `{"ev":"asr_stop_timeout",…}` を残し、入口の知らせの欄にそう出して進む
  - 待ち終えた後（3 秒の上限を過ぎた後と、`end` の後）に届いた確定の結果は、記録（素材ログの発話と判断ログ）に入れない。ただし黙って捨てず、素材ログに出来事 `{"ev":"late","text":本文,"t":届いた時刻（聞き始めからの秒）,"at":壁時計}` を残し、入口の知らせの欄に「聞き終えた後に届いた認識の結果を 1 件捨てました（記録の外）」と出す（2 件目からは「聞き終えた後に届いた認識の結果を、もう 1 件捨てました（記録の外。合わせて N 件）」）
  - 待ち終えた後は、`late` 以外の認識の出来事（`asr_end` など）を素材ログに足さない
  - 聞き終えて別の記録を開いた後に、前の記録の認識が結果を返したときは、前の記録の素材ログに `late` として残し、新しい記録には何も入れない。知らせの欄には「前の記録「…」で聞き終えた後に届いた認識の結果を 1 件、その記録の素材ログに残しました（記録の外）」と出す
  - ページが記録に書けない状態が続いて聞き取りを止めた後に入口が返した結果も、記録に入れずに `late` として残し、「聞き取りを止めた後に届いた認識の結果を 1 件捨てました（記録の外）」と出す（`src/app.js` のコードを読んで確かめた。画面では確かめていない）
- 中断（`pause`）の間に打った行・貼った行・音声入力で入った行も捨てない。届いた時刻で溜まりに入り、再開した後の窓に、届いた時刻の順で入る（1 窓 40 件の上限も同じに当たる。ページと `rt.py` で同じ決まり）

## イベント語彙（v2）

例はすべて架空（架空の社内会議「備品の見直し」）。

### `open` — ログの先頭

```json
{"e":"open","v":2,"name":"備品の見直し","t0":"2026-10-07T01:00:00Z","mode":"live","window":30,"known":""}
```

| 欄 | 型 | 意味 |
|---|---|---|
| `v` | 2 | 版。無ければ v1 |
| `name` | 文字列 | 会議の名前。ファイル名の元 |
| `t0` | 壁時計 | 聞き始めた（ファイルなら読み始めた）時刻。`live` では `t = at − t0` の目安になるが、`t` の正は素材ログ |
| `mode` | `live` / `file` | `live` は素材が届くそばから処理する。`file` は素材のファイルを窓ごとに読む（事後の作り直し・試験用） |
| `window` | 整数（秒） | 既定の窓幅。5〜180 の整数（`7.5` のような小数は F02） |
| `known` | 文字列 | 聞き始める前に知っていたこと（前回の会議の引き継ぎなど）。無ければ空文字。0〜2000 字（前回の `rt.py digest --full` の出力はこの上限に収まる） |
| `src` | 文字列（任意） | 素材ファイルかメモ帳の名前。`.txt`・`.tsv`・`.vtt` で終わる（大小文字は問わない。P30）。判断ログ・素材ログ・印・覚え書きは素材にできない |

v1 の `chunk`（行数で刻む）は v2 では使わない。

### `step` — 1 つの窓

```json
{"e":"step","n":12,"lines":[61,66],"t":[330,360],"at":"2026-10-07T01:06:08Z"}
```

| 欄 | 意味 |
|---|---|
| `n` | ステップ番号。1 から 1 ずつ増える |
| `lines` | この窓で渡した発話の `i` の範囲 `[最初, 最後]`。直前の step の続きに限る。件数は 40 まで |
| `t` | 窓 `[始まり, 終わり]`（秒）。`t[0] ≧ 0`、`t[1] > t[0]`（同じ時刻の 41 件以上で上限に当たった窓だけは `t[1] = t[0]` もありうる）、`t[0]` は直前の step の `t[1]` 以上（窓は重ならない）、幅は `window × 3` 以下 |
| `at` | 壁時計。**道具が追記の瞬間に押す。** 直前の step の `at` 以上。`live` では `at − open.t0 ≧ t[1]`（聞き終える前に判断を押せない） |
| `think` | 文字列（任意）。分析役の思考の要約が取れたとき道具が入れる。2000 字まで |

分析役が返すのは `t` だけ。`n`・`lines`・`at`・`think` は道具が埋める（返事に `think` があっても道具は捨てる）。

### `card` — カード

```json
{"e":"card","id":"C7","t":335,"d":1,"role":"case","who":"話者B","src":[62,63],"li":["L1",2],"ti":"椅子は現物を二脚試してから選ぶ","b":"見本を取り寄せて一週間使う。費用は貸出なので掛からない。"}
```

| 欄 | 意味 |
|---|---|
| `id` | `C` ＋ 連番 |
| `t` | **その話が出た時刻で、縦の並びの位置。後から動かせない（R1）。** 窓より前でもよい（前に出た話を、いまカードにしてよい）。ただし根拠の発話（`src`）の時刻の最小以上・最大以下（P29）。根拠の無いカードは位置を確かめられないので、v2 では書けない |
| `d` | インデントの深さ（0 以上の段数）。書いた時点の見立てで、`fix` で変えてよい |
| `role` | `claim`（言い分を立てる）、`counter`（それを押し返す）、`case`（具体の例を出す）、`land`（話が落ち着いた先）。v1 にあった `top` は v2 に無い（最上位は、`top` という別のイベントで表す） |
| `who` | 話者。素材ログに出てきた話者名か、複数の話者にまたがるなら `null`。欄そのものは必ず書く |
| `src` | 根拠の発話の `i` の配列。聞いた範囲（`1 〜 step.lines[1]`）の中。**v2 では 1 つ以上**（空の配列は P29 で拒む。v1 は空でも警告だけ） |
| `li` | 任意。`[数え上げの id, 何番目か]`（1 から数える）。無いか `null` なら、どの数え上げにも属さない |
| `ti` | 見出し。1〜50 字 |
| `b` | 詳細。0〜120 字 |

- **話のひとまとまりが閉じたら 1 枚。** 発話ごとには作らない。目安は 1〜2 分に 1 枚
- **この先の展開の予想はカードにしない。** 予想が当たっても同じ。カードにすると、その時点では手にしていなかった中身を、手にしていたかのように記録が語ってしまう。予想は `note` に書く。
  ただし検査器がこれを機械で見分けられるのは、推量語（だろう／かもしれない／おそらく）を含むときの警告（P24）だけで、言い切った予想は通ってしまう。分析役への指示と、見返す人の目で守る

### `hold` / `close` — 保留と決着

```json
{"e":"hold","id":"H3","t":340,"who":"話者A","q":"机の買い替えは今期の予算に入るのか"}
{"e":"close","id":"H3","t":371,"as":"今期の予算には入らない。来期に回す","by":["C9"]}
```

| 欄 | 意味 |
|---|---|
| `hold.id` | `H` ＋ 連番 |
| `hold.q` | 問い。1〜120 字 |
| `hold.who` | 問いを出した話者か `null`。欄は必ず書く |
| `hold.kind` | 任意。`"gap"` だけが特別で、**検証に落ちた窓の印**（下の「検証に落ちたとき」）。道具が書く。分析役は書かない |
| `close.id` | 閉じる保留の id。開かれているものだけ |
| `close.t` | 答えが出た時刻。保留を開いた `hold.t` 以上（P29） |
| `close.as` | 答え。1〜120 字 |
| `close.by` | 答えを出したカードの id の配列。既存かこのバッチで先に出たカード。カードが無い決着（話の流れで分かった、など）は `[]` |

- 答えがまだ出ていない問いは、保留として開いておくのが正しい扱いで、失敗ではない。迷ったら保留にする
- `close.t − hold.t` を「決着までの時間」として測る（0 以上）。`kind:"gap"` の保留はこの統計に入れない
- **同じ id への2つ目以降の `close` を許す**（下の穴 4）

### `fix` — 書いたものを直す

```json
{"e":"fix","id":"C5","t":412,"field":"d","was":1,"now":0,"why":"机の話ではなく、備品全体の方針だった"}
{"e":"fix","id":"B","t":600,"field":"span","was":[300,null],"now":[300,590],"why":"椅子の塊が閉じた"}
```

| 欄 | 意味 |
|---|---|
| `id` | 対象。`field` によって種類が決まる: `d`/`ti`/`b`/`role` → カード、`span` → 括り、`items`/`n` → 数え上げ |
| `field` | `d` / `ti` / `b` / `role` / `span` / `items` / `n` |
| `was` | 直す前の値。**道具が現状から埋める**（`now` の手前に置く）。分析役が書いた値が現状と違えば拒む。v1 では道具が埋めないので、書き手が必ず書く |
| `now` | 直した後の値。その欄の制約（型・enum・値の範囲・上限・未聴でない）を満たすこと。`d` は 0 以上（版に依らず）、`span` の始まりは括りの `t` 以下、`items` の各項目は 1〜50 字 |
| `why` | 理由。200 字まで |

**直すときも前の行には触らず、`fix` を足す。** 再生すると、直った時刻に、直ったことがそのまま見える。
`t` を直す欄は無い。位置は動かさない（R1）。

### `group` — ひとまとまりにする（並びを動かさずに塊を表す要）

```json
{"e":"group","id":"B","t":300,"span":[300,null],"lb":"（仮）椅子の話","kind":"start"}
{"e":"group","id":"C","t":783,"span":[115,760],"lb":"備品より先に、置き場の話だった","kind":"retro"}
```

| 欄 | 意味 |
|---|---|
| `id` | `A`, `B`, …, `Z`, `AA`, `AB`, … の順 |
| `t` | 括ったと気づいた時刻（印を置く位置） |
| `span` | `[始まり, 終わり]`。終わりが分からなければ `null`。始まりは `t` 以下、終わりは聞いた範囲の中 |
| `lb` | 名前。1〜50 字。仮の名前は「（仮）」で始めると再生側で分かりやすい |
| `kind` | `start`＝始まったところで塊だと気づいた。`retro`＝後になって、前からの話がひとまとまりだったと気づいた |

- `retro` の印は、**気づいた時刻のところに置く**。`span` に入るカードは右へずれる
- **縦の並びは一度置いたら変えない**（R1）。括りが変えるのは左の線の幅だけ
- 検査器が見るのは `span` の始まり ≦ `t`（P15）と `t ≧ 0`（P29）まで。`retro` の印を気づいた窓より前（たとえば `span` の始まり）に置くことは、機械では止めていない

### `rename` — 括りの名前を付け直す

```json
{"e":"rename","id":"B","t":420,"was":"（仮）椅子の話","now":"椅子は試してから選ぶ"}
```

対象は括り。`was` は道具が現状から埋める（`fix` と同じ）。
塊にふさわしい名前は、次の話題に移ってから見えてくることが多い。まず仮の名前で置き、見えた時点で付け直す。

### `top` — いちばん上の候補が替わる

```json
{"e":"top","id":"C12","t":612,"prev":"C4","why":"費用の節約より、使う人の体の話が上に来た"}
```

| 欄 | 意味 |
|---|---|
| `id` | 最上位候補のカード |
| `prev` | 直前の候補の id。無ければ `null`。現状と違えば**警告**（拒まない） |
| `why` | 理由。200 字まで |

候補が替わっていく経過そのものを残すのが目的で、終わりまでに一つに決まらなくてよい。

### `echo` — 閉じた塊に、あとから重みが足される

```json
{"e":"echo","id":"B","t":880,"why":"椅子の見本の話が、置き場の問題を補強した"}
```

対象は括り（閉じた括りでもよい）。並びの位置はそのまま（R1）で、変わるのは重さ。再生側は、echo の時刻にその括りを短く光らせるなどして、前に括った話がいまの話で重みを増したことを見せる。

### `note` — その窓で考えたこと（所感）

```json
{"e":"note","t":360,"x":"次に話者Cが予算の話を持ち出しそうに聞こえる（予測。カードにはしない）。H3 はまだ閉じない。"}
```

- **毎ステップちょうど1件。** 1〜400 字
- 先の展開の予想は、ここにだけ書く。**言い切らない。** 外れていたら `fix` は使わず、次の窓の `note` で書き足す
- 画面の「考えたこと」欄にそのまま出る。人向けの別文書（md）は作らない

### `list` — 話者が宣言した数え上げ

```json
{"e":"list","id":"L1","t":12,"who":"話者A","n":3,"items":["椅子","机","置き場"]}
```

| 欄 | 意味 |
|---|---|
| `id` | `L` ＋ 連番 |
| `who` | 宣言した話者か `null` |
| `n` | 宣言された数。2 以上 |
| `items` | 分かっている項目を順に。0 〜 `n` 件、各 1〜50 字。「三点あります」とだけ言われた時点では `[]` でよく、分かるたびに `fix`（`field:"items"`）で足す。数が変わったら `fix`（`field:"n"`） |

話者が「三点あります」のように数え上げを宣言したら書く。
左欄の「全部でいくつ・いまどれ」の表示は、この `list` と、カードの `li` から出す。括り（`group`）で代用しない。

### `end` — 聞き終えた

```json
{"e":"end","t":1812,"at":"2026-10-07T01:30:20Z"}
```

1件だけの追記。道具が書く。`t` は直前の step の `t[1]` 以上。`t` の既定と、`live` で聞き終えた時計の秒より先に置けないことは「`live` の終わり方」。**`end` の後には何も追記できない。**

### `pause` — 聞くのを止めた

```json
{"e":"pause","t":900,"why":"休憩","at":"2026-10-07T01:15:05Z"}
```

1件だけの追記。道具が書く。`why` は 200 字まで。`t` は直前の step の `t[1]` ちょうど（step がまだ無ければ 0）。**中断は読み終えた所に置く。** 先に置くと、再開した窓がその間の発話をまとめて渡すことになる。再開は、次の `step` がそのまま表す（`t[0]` は `pause.t` 以上）。

## バッチの上限（v2）

| 種類 | 1バッチあたり |
|---|---|
| `card` | 0〜5 |
| `hold` | 0〜3 |
| `close` | 0〜3 |
| `note` | ちょうど 1 |
| その他 | 上限なし |

分析役に「塊が閉じたときだけ」を守らせるための上限。足りなければ次の窓に回す。

---

## 採番（`next_ids`）

v2 では id に欠番を許さない。カードは `C1, C2, …`、保留は `H1, H2, …`、数え上げは `L1, L2, …`、括りは `A, B, …, Z, AA, AB, …`。
道具は状態から次の id を計算して分析役に渡す（`pack.md` の `next_ids`）。**分析役が書いた id が次の id と違えば拒む。**
`kind:"gap"` の保留も `H` の番号を1つ使う。

## 検査

**規則表 `format/rules.json` は、Python の道具（`tools/rt.py`）とページの中の JS（`verify.js`）が、どちらも読む。**
規則表にあるのは、語彙（`kinds`）、各イベントの欄と型と必須の版、enum、上限、版ごとの列。
次の**手続き的検査**は規則表に項目名（`P01`…）だけを列挙し、**実装は Python と JS の両方が持つ**。同じ `tests/cases/*.json` を両方が通ることで、2つの実装がずれないよう縛る。

違反文は規則の id で始める（例 `P09: 時刻 1:15 は、この窓の終わり 1:00 より後です`）。id の後ろの文は道具ごとに違ってよく、試験は id で照らす。

| id | 検査 |
|---|---|
| P01 | `open` を書けるのは空のログの 1 行目だけで、空のログの 1 行目に書けるのも `open` だけ。新しい記録を始める入口は `rt.py open`（とページの「新しい記録」）だけで、`open` は v2 だけを書く。`rt.py append` は `open` を受けない（v1 の記録は、既にあるものの続きにだけ追記できる）。検査器そのもの（ページと `rt.py` の両方）は、空のログへの `open` だけの追記を受ける |
| P02 | `open`・`end`・`pause` はそれぞれ1件だけの追記（他のイベントと混ぜない）。それ以外の追記は先頭が `step` で、1回の追記に `step` は1つ。`step` より前に他のイベントを置かない |
| P03 | `step.n` は直前の step の `n` ＋ 1（最初は 1） |
| P04 | `step.lines` は直前の続き（`lines[0]` ＝ 直前の `lines[1]` ＋ 1、最初は 1）で、`lines[1] ≧ lines[0]` |
| P05 | 窓の幅。v1: 1 ステップの行数は `chunk` 以下で、`chunk` より短いステップは最後の 1 つだけ。v2: `t[1] ≧ t[0]` かつ `t[1] − t[0] ≦ window × 3`。v2 では、1つの窓の発話の数（`lines[1] − lines[0] + 1`）は `limits.step.max_lines`（40）以下。上限に当たった窓は、終わりを 41 件目の時刻 T まで縮め、窓の中に T と同じ時刻の発話があればその塊の手前で切る（窓は 40 件より少なくなり、渡した発話はどれも `t[1]` より前）。`t[1] = t[0]`（幅 0）を受けるのは、発話がちょうど 40 件の窓だけ（塊が窓の最初の発話から始まるときの `[T, T]` と、T が窓の始まり以下のときの `[始まり, 始まり]`） |
| P06 | `step.t[0]` は直前の step の `t[0]`（v1）／ `t[1]`（v2）以上。`pause` の直後なら `pause.t` 以上 |
| P07 | 道具が渡した窓を知っているとき、`step.t` と `step.lines` はその窓と一致。素材のある記録（`open.src` か、`open` で名指しした素材。`live` と `file` のどちらでも）では、道具は渡した窓を信じきらず、素材から計算し直して照らす。素材は読むときに時刻を単調にする。`t[0]` は直前の step の `t[1]`（無ければ 0。発話の無い窓を丸ごと飛ばしたときだけ、窓の幅の刻みで先へ進む）、`t[1] − t[0] ≦ window × 3`、`lines` は、まだ読んでいない発話のうち `t ＜ t[1]` のものを先頭から順に 40 件まで（超えた分は次の窓）。40 件で切ったときは、`t[1]` を渡さなかった最初の発話の時刻 T まで縮め、窓の中に T と同じ時刻の発話があればその塊の手前で切る（聞いたのはそこまで）。塊が窓の最初の発話から始まるときだけ、幅 0 の窓 `[T, T]`（始まりも T まで進む）に 40 件。T が窓の始まり以下（遅れて届いた発話）なら、幅 0 の窓 `[始まり, 始まり]` に 40 件。ページの検査器は素材の全文を持たないので計算し直さないが、素材ログ（`src`）を渡されたときは、窓の発話と、渡さなかった次の発話の時刻を照らす。幅のある窓では、窓の発話は `t[1]` より前で、次の発話は `t[1]` 以後。始まりを進めた幅 0 の窓では、窓の発話は `t[1]` ちょうどで、次の発話は `t[1]` 以後。始まりを進めていない幅 0 の窓では、窓の発話も次の発話も `t[1]` 以下。`open` で素材を名指しした記録は、素材が見つからなくても免除しない（拒む）。1つの素材ファイルに開けるログは1つ（素材の隣の `.owner`）で、別のログで同じ素材を `open`・`next` すると拒む。`file` の記録で `next`・`append` に渡す素材は、`open.src` と同じファイル（解決したパスで比べる）でなければ拒む |
| P08 | `step.at` は道具が押す（分析役が `step`・`end`・`pause` に書いた `at` は、値の検査も含めてどの検査よりも前に捨てる）。直前の step の `at` 以上 |
| P09 | すべてのイベントの `t` は `step.t[1]` 以下（窓の終わりより先、つまり聞く前の所には書けない）。上限で切った窓では、縮めた `t[1]` で比べる（縮めた窓の発話はどれも `t[1]` より前。幅 0 の窓では、渡した発話も `t[1]` ちょうどか、遅れて届いてそれより前） |
| P10 | 指す相手がある: `close`・`fix`・`top`・`echo`・`rename` の `id`、`close.by`、`card.li` の数え上げは、既存かこのバッチで先に出たもの |
| P11 | 採番（v2）: 新しい `card`・`hold`・`list`・`group` の id は `next_ids` と一致 |
| P12 | 同じ id の `card`・`hold`・`group`・`list` を二度出さない |
| P13 | `close` は開かれた保留だけ。同じ id への2つ目以降は追加の答えとして受ける |
| P14 | `fix`: `field` と対象の種類が合う。`now` はその欄の制約を満たす（`d` は 0 以上（版に依らず）、`span` の始まりは括りの `t` 以下で終わりは未聴でない、`items` は `n` 以下で各項目は字数の上限内（v2）、`n` は分かっている項目数以上、など）。`was` は現状と一致（v2。JSON の文字列にして比べる。`false` と `0` は別。無ければ道具が `now` の手前に埋める）。`rename` の `was` も同じ |
| P15 | `group.span` は `[始まり, 終わりまたは null]`。始まりは `t` 以下、終わりは `step.t[1]` 以下 |
| P16 | `top.prev` が現状の最上位と違えば警告（拒まない） |
| P17 | `note` の件数（v1: 何件でも。v2: ちょうど1） |
| P18 | `list.n ≧ 2`、`items` は `n` 件以下。`card.li` は存在する数え上げで、`1 ≦ 番目 ≦ n` |
| P19 | `card.src` の各 `i` は `1 〜 step.lines[1]`。空の `src` は、v1 では警告（v2 では P29 で拒むので、警告は出さない） |
| P20 | `who` は、素材ログがあるとき、聞いた範囲に出てきた話者か `null`。素材ログが無ければ検査しない |
| P21 | `end` の後には何も追記できない。`end.t` は直前の step の `t[1]` 以上 |
| P22 | `pause.t` は直前の step の `t[1]` 以上で、`t[1]` 以下（つまり `t[1]` ちょうど。step がまだ無ければ 0 以下）。中断は読み終えた所に置く |
| P23 | 1バッチの件数（上の表） |
| P24 | 警告: `card.ti`・`card.b` に推量語（だろう／かもしれない／おそらく）がある |
| P25 | 警告: このバッチより前から開いている保留の `q` と、このバッチのカードの `ti` に 4 文字以上の共通部分がある（閉じ忘れの疑い）。同じバッチで開いた保留は見ない |
| P26 | 全か無か: 違反がどれか 1 つでもあれば、その追記は 1 行も書かない。警告だけなら書く |
| P27 | `live` の記録では `step.at − open.t0 ≧ step.t[1]`（秒。小数部まで読む）。聞き終える前に判断を押せない。`file` の記録には当てない（v2） |
| P28 | 警告: `file` の記録で、`open.known` と素材の本文に 30 字以上の共通部分がある（素材の先の中身を `known` に入れていないか）。比べる前に、両方から空白と句読点・記号（Unicode の分類が Z・P・S で始まる文字と、空白文字）を除く。拒まない。素材の全文を持つ `rt.py` が見る |
| P29 | 並びの位置（R1）。位置は後から動かせないので、置ける範囲を縛る。すべてのイベントの `t`（step は `t[0]`）は 0 以上。v2 の `card.src` は 1 つ以上（空の配列は拒む。根拠の無いカードは位置を確かめられず、先頭などへ置けてしまうため）。`card.t` は、`src` の発話の時刻（読むときに単調にした時刻）の最小以上・最大以下（その発話の時刻が分かるとき）。`close.t` は閉じる保留の `hold.t` 以上（2つ目以降の答えも）。`group.t` が `span` の始まり以上であることは P15 が見る |
| P30 | 素材の名前（v2）: `open.src` は `limits.open.src_ext` のどれか（`.txt`・`.tsv`・`.vtt`）で終わる。大小文字は問わない（`.TXT` も受ける）。拡張子の無い名前、`.json`・`.jsonl`（判断ログ・素材ログ・覚え書き）、`.owner`（持ち主の印）、`.text` などは拒む。名前の途中ではなく終わりで決める（`memo.txt.owner` は拒む）。ページの検査器も `rt.py` も、空のログに `open` を書くときに見る。`rt.py open` はこれに加えて、記録の形の名前（`.jsonl`・`.owner`・`.watch.json`・`.next.json`）と、同じフォルダの持ち主の印が指す別のログの記録（判断ログ・素材ログ・覚え書き・watch の印）を名指した `open` を P07 で断る。v1 の記録には当てない |

欄の検査（規則表から機械的に導く）:

| id | 検査 |
|---|---|
| F01 | 必須の欄が無い（版の列で「必須」のもの。道具が押す `at` と、v2 で道具が埋める `was` は除く。v1 の `was` は必須） |
| F02 | 型が違う（配列の長さを含む。id は空でない文字列）。数は有限のものだけ（`NaN`・`Infinity`・`-Infinity` と、読むと無限になる `1e999` のような値も F02）で、絶対値が 2^53 − 1（9007199254740991）以下のものだけ（超える整数・小数は、何桁でも落ちずに F02）。整数の欄は `2.0` のような小数点つきの整数も整数として受ける（JS では `2` と区別できないため。`rt.py` は書くときに整数に直す）。文字列に対になっていないサロゲート（片割れ）があれば F02（欄の値でも、配列やオブジェクトの中でも、鍵でも）。壁時計の形は文字列の末尾まで当て（末尾の改行も違反）、数字は半角だけ。形が合っても暦に無い日時（24 時、60 分、60 秒、2 月 30 日、4 月 31 日、0 年）は F02。欄の値の入れ子は `limits.value.max_depth`（32）段まで（数・文字列は 0 段、配列やオブジェクトは 1 ＋ 中身のいちばん深いもの）。超えれば、何段でも落ちずに F02 |
| F03 | enum に無い値 |
| F04 | 上限・下限を超える。欄の定義にある値の範囲（`card.d` は 0 以上、`open.window` は 5〜180 など）は、**その版に在る欄なら版に依らず**見る。その版に無い欄（v1 の `open.window` など）は見ない。字数・件数の上限（`limits`）は v2 のみ |
| F05 | 知らない欄がある（v2 のみ）。分析役が `step`・`end`・`pause` に書いた `at` は、値の検査も含めてどの検査よりも前に捨てるので、どんな値でも F05 にも F02 にもしない |
| F06 | id の形が違う（v2 のみ）。形は文字列の末尾まで当てる（末尾の改行も違反） |
| F07 | この版に無い種類のイベント。イベントとして読めない行（オブジェクトでない行: 文字列・数・配列・`null`。`e` が文字列でない行）も F07（落ちずに拒む）。`open.v` がどの版にも無い（知らない版。型も比べる） |

追記の `step` が欄の形の検査（F01・F02・F03・F05・F06）に落ちたときは、その `step` の番号と窓の検査（P03〜P08・P27）をしない。同じ追記の後ろのイベントは、`step` の `lines` を使う検査（P19 の範囲・P20 の話者・P29 のカードの位置）を飛ばし、ほかの検査だけをする。窓の終わり（P09）は、`t` が [数, 数] なら使う。拒むことは変わらず（違反は欄の検査が出している）、検査器は落ちない。

`step` より後ろのイベントが欄の形の検査（F01・F02・F03・F05・F06。上限の F04 は除く）に落ちたときは、そのイベント自身の手順の検査（指す相手・採番・決着・`src` の範囲・並びの位置など）をしない。落ちたのが `card`・`hold`・`group`・`list` なら、その id は出たものとして覚える。id の欄そのものが壊れているとき（空・文字列でない・`null`）は、採番の次の id（v2 の `next_ids`）が出たものとして覚える（v1 では覚えない）。だから同じ追記の後ろのイベントがその id を指しても、最初の違反から続いて出る文（P10・P11・P13・P19・P29 など。連鎖の文）は出ない。件数（P17・P23）は、欄の壊れたイベントも 1 件に数える。`rt.py` とページの検査器（`verify.js`）は同じ扱いで、連鎖の文が出ないことを `tests/cases` の `forbid_rules`（出てはいけない規則の id）で縛る。

既存のログの行も、追記のたびに同じ欄の検査（F01〜F07）にかける。壊れた行が1つでもあれば追記しない（`rt.py` は手順の規則も含めてログを畳み直す。`verify.js` は欄だけ）。

スキーマ（`format/schema.json`）は分析役の返事の**形**だけを縛る。中身の正しさ（時刻・id・上限）は検査器が落とす。

## 検証に落ちたとき

分析役の返事が検査に落ちたら、違反文を添えて同じ窓で出し直しを2回まで求める（合計3回）。
返事が機械向けの形として読めないとき（下の「返事の読み方」で読めないもの）も、同じ窓の 1 回に数える。
3回目も落ちたら、道具が次の最小バッチを書いて窓を進める。

### 返事の読み方（`rt.py` もページも同じ）

1. 返事の文字列の前後の空白を除く。全体が ```` ``` ```` で始まって ```` ``` ```` で終わっていれば、その囲みを **1 回だけ**外し（開きの直後の `json` も捨てる）、内側の前後の空白も同じように除く。囲みが返事の途中にあるだけなら外さない（文字列の値の中の ```` ``` ```` は、ただの字として読む）。前置き・後書きの付いた返事は読まない
2. 残りが空なら、読めない返事
3. JSON として読む**前に**、文字列の外にある `[` と `{` の入れ子を数える。500 段を超えていれば **F02** で読めない返事にする（読む道具が深すぎる入れ子で落ちないように）。文字列の中の括弧は数えない。文字列の中の `\` は、次の 1 字と組で読む（`\"` で文字列は終わらない）
4. 残りの全体が 1 つの JSON オブジェクトとして読めなければ、読めない返事
5. オブジェクトの一番外に `e` の欄があれば、読めない返事（`e` は `events` の中の判断にだけ書く。`rt.py` は `e` のあるオブジェクトを JSONL の 1 行として読み、`step` で始まらないので断る。ページも同じく断る）。ほかの知らない欄は捨てて読む
6. `step` が無いか、オブジェクトでなければ、読めない返事
7. `events` の欄が無ければ `[]`（何も書くことが無い静かな窓）として読む。欄があって配列でなければ、読めない返事。**`"events": null` も読めない返事**で、欄が無いのとは区別する
8. `events` の中に `note` があれば、読めない返事（所感は `events` の外の `note` に 1 つだけ書く）
9. ここまで通った返事を追記に直して検査器に通す。欄の中身（型・値の入れ子の 32 段・時刻・id）は検査器が見る

1〜8 のどこで読めなくても、検査に落ちたのと同じ窓の 1 回に数える（上の「検証に落ちたとき」）。ただしページの手動の輪で、返事の欄が空のまま「返事を貼ったら取り込む」を押したときは、返事として扱わず数えない（押し間違いとみなす）。`rt.py append` に空のバッチファイルを渡したときは、2 のとおり読めない返事として 1 回に数える。

**空白として除く字**は次の 25 字だけ（JS の `String.prototype.trim` が除く字と同じ集まりを、字で書き出したもの）。ブラウザや Unicode の版で集まりが揺れないように、`rt.py` もページもこの一覧を持つ。話者の切り出し（上の「話者の切り出し」）も同じ一覧を使う。

| 符号位置 | 字 |
|---|---|
| U+0009〜U+000D | タブ・改行・垂直タブ・改ページ・復帰（5 字） |
| U+0020 | 半角の空白 |
| U+00A0 | 改行しない空白 |
| U+1680 | オガム文字の空白 |
| U+2000〜U+200A | 幅の違う空白（11 字） |
| U+2028・U+2029 | 行区切り・段落区切り |
| U+202F | 幅の狭い改行しない空白 |
| U+205F | 数式用の空白 |
| U+3000 | 全角の空白 |
| U+FEFF | BOM（ファイルの頭に付く印） |

この一覧に**無い**字は除かない。たとえば U+0085（次の行）・U+001C〜U+001F（区切りの制御文字）・U+200B（幅の無い空白）・U+180E（モンゴル文字の母音区切り）が返事の前後に付いていると、JSON として読めない返事になる。

`rt.py append` に渡した入力が 1 つの JSON オブジェクトで、`e` の欄を持たないときは返事として読む。そうでなければ JSONL（1 行 1 イベント）として読む。どちらとして読むかを決める前に、1〜3（囲みを外す・空白を除く・500 段の数え）を入力の全体に当てる。

```json
{"e":"step","n":6,"lines":[25,29],"t":[150,180],"at":"2026-10-07T09:02:55Z"}
{"e":"hold","id":"H4","t":150,"who":null,"kind":"gap","q":"この窓（2:30〜3:00）の構造は未確定（検証に3回落ちた）"}
{"e":"note","t":180,"x":"P09: 時刻 3:10 は、この窓の終わり 3:00 より後です（3回とも同じ違反）"}
```

- 嘘のカードを作らず、素材を飛ばさず、空振りを記録に残す
- `kind:"gap"` の保留は決着の統計（中央値・最長）に入れず、左欄では「未確定の窓」として別に出す
- 次の窓で、道具は落ちた窓の発話を `gap_lines` として分析役にもう一度渡す（`pack.md`）。分析役はその窓の時刻にカードを置き（過去の位置は許される）、`close.by` でこの保留を閉じられる。人が閉じてもよい
- 違反文は所感に書き写すことがあるので、違反文には記録に書けない文字（片割れのサロゲート）を入れない（置換文字に直して出す）

## 再生する側の決まり

1. **時刻 T の画面は、T の時点で書き終わっていた追記だけを材料にする。** その後に書いた行は、無かったものとして描く。ライブでは、まだ書いていない行のための部品も画面に作らない
2. 直したところは、直したという事実ごと見せる。直したあとの姿だけを出さない（前の値と後の値を並べる）
3. 開いている保留は、閉じるまで画面から消さない。閉じたら、いつ閉じたかも見せる
4. `retro` の括りが入ったとたん、範囲の中の前のカードが右へ動く様子が見えるようにする
5. 縦の順は時刻で決まり、**どの時点でも並べ替えない**

## v1 の実走で見つかった欠けと、v2 での扱い

先に決めた形式には、実際に流して初めて見える欠けがあった。v1 で見つかった 6 つは、v2 でも同じ扱いを続ける。例は架空。

1. **`fix` で括りの `span` を直せること。** 括った範囲を後から変える方法が要った。`{"e":"fix","id":"B","field":"span","was":[300,null],"now":[300,590],"why":"…"}` を受ける
2. **`span` の終わりを空けておけること。** 塊の頭は見えていても、どこで閉じるかは見えていないことがある。終わりを `null` にして置き（`span:[300,null]`）、閉じた時点で `fix` で埋める
3. **★ カードが並ぶ位置と、カードが画面に現れる時刻は別物。** 位置は `card.t`（その話が出た時刻。R1 で動かさない）。現れるのは、そのカードを記録に足した `step`（v2 では `step.at`）の時刻。例: 2:49 に出た提案を、3:00 で閉じた窓でカードにする。**再生側は、位置を `t` で、出す時刻を `step` で決める。** 二つを取り違えれば、判断する前の時刻の画面にカードが出てしまう
4. **`close` は答えが一つ出たという印で、問いがそこで終わるとは限らない。** たとえば「なぜ去年は数量が落ちなかったのか」に、5:38 と 8:39 で別々の答えが出ることがある。→ 閉じた保留にも、同じ `id` で `close` を重ねて書ける。再生側は答えを出た順に並べて見せ、前の答えを消さない。どのカードが答えかは `close.by` で機械が照らせる
5. **閉じた括りにも、後から重さが足されうる。** 4 分で括った「価値をどう説明するか」が、その後も別の議題の途中で何度も引き合いに出されることがある。→ 並びの位置はそのまま（R1）、重さだけが増える。`echo` で表す
6. **保留の閉じ忘れに気づけない。** 保留を何件も抱えていると、答えが聞こえたあとも `close` を書き漏らす。開いている長さで色を付けても目印にならない（重い問いほど長く開いているのがふつうだから）。→ 読解側の対処: 道具は追記のたびに、その回に出したカードと、まだ開いている保留を一緒に示し、今回のカードがどれかの問いの答えになっていないかを毎回見えるようにする。v2 ではさらに `close.by` を必須にし、P25 の警告で疑いを出す

## 規則表の読み方（`rules.json`）

- `kinds`: 語彙。`versions.<版>.kinds` がその版で受ける種類
- `events.<種類>.fields.<欄>`: `type`（下の表）、`req`（`all` ＝ どの版でも必須、`v2` ＝ v2 で必須、`opt` ＝ 任意）、`null`（`true` なら `null` を許す）、`enum`（`enums` の鍵）、`max`／`min`（配列は件数、数は値。**欄の形の一部なので、その版に在る欄（`req` が `opt` か、版の `required_levels` に入る欄）なら版に依らず当てる**。配列の件数は版に依らず当てる）、`tool_writes`（道具が押す欄）、`tool_fills`（道具が埋める欄。`fill_was` の版だけ欠けを許す）
- `versions.<版>.open_v`: その版と見なす `open.v` の値の一覧（`null` は「欄が無い」）。版の判定はこれだけで行う
- `type` の語: `int`（整数）、`num`（数）、`str`（文字列）、`bool`、`t`（秒。数）、`iso`（壁時計）、`id:card` など（id の形は `id_patterns`）、`span`（`[数, 数または null]`）、`li`（`[id:list, 1以上の整数]`）、`arr:int`／`arr:str`／`arr:id:card`（配列）、`any`（`fix.was`／`now` のように欄で決まる）
- `limits`: 字数・件数の上限。`step.max_lines` は 1 つの窓の発話の数の上限（P05・P07）。`versions.<版>.limits` が `false` の版では当てない（欄の `min`／`max` は別で、上のとおり版に依らない）。ただし `value.max_depth`（欄の値の入れ子の上限。数・文字列は 0 段、`[]` と `{}` は 1 段＋中身）だけは版に依らず当てる（F02）
- `versions.<版>`: 版の列。`required_levels` に含まれる `req` の欄を必須として扱う。`live_at_after_heard` が `true` の版では、`live` の記録の `step.at` に P27 を当てる。`card_src_min` は `card.src` の件数の下限（下回れば P29。`0` の版では空の `src` を P19 の警告にとどめる）
- `procedural`: 手続き的検査の id と一文。実装は Python と JS の両方が持つ
