# tests — 検査器のテストと、架空の素材

検査器は2つある（Python の `tools/rt.py` と、ページの中の `verify.js`）。
どちらも規則表（`format/rules.json`）に従い、ここにある **同じ** `cases/*.json` と `fixtures/` を通す。
片方だけ通る状態は不合格。テストを欠かすと2つの実装は黙ってずれる。

## cases の形

```json
{"name": "拒否：行を飛ばす",
 "why": "step.lines[0] が直前の続きでない",
 "log_prefix": [ ...イベント... ],
 "batch": [ ...イベント... ],
 "expect": "reject",
 "expect_rule": "P04",
 "clock": "2026-10-07T09:01:04Z"}
```

| 欄 | 意味 |
|---|---|
| `log_prefix` | 追記の前にあるログ（イベントの配列）。空なら新しいログ |
| `batch` | 追記しようとするイベントの配列（先頭は `step`。`end`・`pause` だけの追記もある） |
| `expect` | `accept` か `reject` |
| `expect_rule` | 拒否のとき、違反文のどれかがこの id で始まること（`P04:` など）。`format/rules.json` の `procedural` / `field_checks` の id |
| `expect_warn` | 受理のとき、警告文のどれかがこの id で始まること |
| `clock` | ツールが `step.at` に押す壁時計。**毎回ある**（テストを決定的にするため） |
| `forbid_rules` | 任意。拒否のときに、出てはいけない規則 id の並び（欄の形の検査に落ちたあとに連鎖する文など）。警告も含めて見る |
| `expect_step_at` | 受理のとき、書かれた `step.at` がこの値であること（分析役が書いた `at` を捨てたことの確認） |
| `src` | 任意。素材ログの行 `{i,t,who,text}`。あるとき P20（話者）の検査に使う。無ければ P20 は検査しない |
| `window` | 任意。ツールが渡した窓 `{"t":[a,b],"lines":[i,j]}`。あるとき P07（窓の一致）の検査に使う |

実行のしかた（両方の実装が同じ手順を踏む）:

1. `log_prefix` からログを作る（Python は一時ファイル、JS はメモリ）
2. `batch` を `clock`（と `src`・`window`）付きで追記にかける。Python では、`src` があるケースは「`next` が素材ログに残した行」として書いておき、`window` が無ければ `batch` の `step` の窓を `next` の覚え書き（`<ログ名>.next.json`）として置く（素材のある記録は `next` を経ないと追記できないため）
3. 受理／拒否が `expect` と一致。拒否なら `expect_rule` の id で始まる違反文が1つ以上ある。受理なら `expect_warn`・`expect_step_at` を照合
4. **拒否のときログが1文字も変わっていない**（全か無か、P26）。`forbid_rules` があれば、そのどれでも始まる違反文・警告文が無いこと
5. すべてが通って合格。1件でも違えば不合格

## fixture の使い方

### 作り直しのテスト（rt.py）

`meeting10.jsonl` を `open` / `step` / `end` で区切って追記の単位に分け、`rt.py next` → `rt.py append` でステップを 1 つずつ書き直していき、**元のファイルと一字も違わない**ことを確かめる。

- 窓の切り方: ステップ n の窓は `t:[30(n−1), 30n]`。発話は `30(n−1) ≦ t < 30n` の窓に入る。窓の終わりちょうどの発話は、それが素材の最後の発話でも次の窓に回す（素材がそこで終わることを、窓の中身から先に分からせない。この素材の最後の発話は 9:55 で、最後の窓 n＝20 の中にある）。`next` が出す行がそのステップの `lines` と一致すること
- 壁時計: 記録の `at` をそのままツールの時計として渡す（`at` はツールが押すので、同じ値を渡さないと一致しない）
- 記録の約束: `at` ＝ `open.t0`（08:59:30Z）＋ 窓の終わり。つまり分析役が窓の閉じた瞬間に返した架空の壁時計。例外はステップ 6（検証に3回落ちた窓）で、25 秒遅れている
- 作り直しのあと `next` を呼ぶと、`end` があるので「ここで終わり」と言うこと
- 素材ログがあるので P20（話者）が効く。警告は1件出る（ステップ 3 の P25: H2 の q と C5 の ti に「三社目の反」が共通。閉じ忘れではないので警告止まりで正しい）

### 内蔵のダミー（テスト用）

窓 n の呼び出しに対して、`meeting10.jsonl` のステップ n のイベントを `schema.json` の形に直して返す:
`n`・`lines`・`at` を落として `step:{t}` に、`fix`／`rename` の `was` を落とし、`hold.kind` を落とし、`li` の無いカードは `li:null` に、`note` は `{x}` に。
ステップ 6 は分析役が3回落ちた窓なので、内蔵のダミーはわざと壊れた返事（`t:190` のカードと 51 字の `ti`）を3回返し、ツールが gap の最小バッチを書くところまでをテストする。

### 畳み込み（fold）の正解

`fold(events, T)` の期待値はこの記録から機械的に導く。見るべき点:

- 位置と出現の分離: C10 は `t:169`（窓 6 の中）に置かれるが、出現はステップ 7（`at` 09:03:00Z）
- 複数回の `close`: H3 は 5:38 と 8:39 の2回閉じる。左の欄では答えが番号つきで 2 つ並ぶ
- `fix(span)`: A・B・C・D の終わりが後から埋まる。`retro` の E は 7:08 に置かれ、範囲 6:31〜7:14 のカードは右へ寄って見える
- `top` の入れ替わり: C4 → C15 → C34。`fix(d)` で C15 が深さ 1 へ
- `rename`: B の仮名が 3:01 に確定
- `echo`: A に2回、B に1回
- `list`: L1（3点）。カードの `li` で「今何番目か」が動く。C34・C35 は `li` 無し
- `kind:"gap"` の H4 は決着の統計に入れず、ステップ 7 で `close.by` により閉じる
- 開いたまま終わる保留: H7（来週に持ち越し）

## fixture を作るときの決まり

1. **架空であること。** 実在する会社・製品・人物を使わない。作る人自身・同僚・実在の素材（実際の発話の文字起こし）を連想させない。社名・製品名・姓は作る
2. **形:** `m:ss<TAB>話者<TAB>本文`。本文は句読点つき、1発話 10〜80 字、合計 90〜130 発話。時刻は単調非減少
3. **構造を意図して入れる:** 宣言された数え上げ（「三点あります」）、遡って括れる塊、揺り戻し、開いてから後で答えが出る問い、答えが2回出る問い。テストで見たい形を素材の側に仕込む
4. **判断ログは先を読まずに書く。** 窓 n の判断は窓 n までの発話だけから書く。後の展開を知っているからといって、早い窓に答えを置かない。先の見込みは `note` だけに書く
5. **規則表をすべて満たす。** 書いたら検査器に通す（違反ゼロ。警告は理由を書いて残してよい）
6. **壁時計は架空でよいが、単調に進める。** `open.t0` から窓ごとに進める。検査に通らなかった窓は遅らせる
7. **gap の窓を1つ入れる。** ツールが書く最小バッチの形（`step`＋`hold{kind:"gap"}`＋`note{違反文}`）で
8. v2 の語彙を全部使う: `list`・gap の `hold`・`close.by`・`fix(span)`・`echo`・`top` の入れ替え・`rename`・`end`
9. 素材を足したり並べ替えたりしたら、`lines` と `src` の番号を全部引き直す（番号は素材の行番号そのもの）
10. 足したり変えたりしたら `python3 tools/make_test_data.py` で `_data.js` を作り直す（`meeting10.status.json` も手で引き直す）

## cases を足すときの決まり

- 1ファイル1件。`name` は「受理：…」「拒否：…」「受理＋警告：…」で始める
- 拒否には必ず `expect_rule` を付ける。狙った規則だけで落ちるように `batch` を最小にする（他の規則で先に落ちると、狙った規則のテストにならない）
- `clock` を必ず付ける。`log_prefix` のどの `at` よりも後の時刻にする
- 共通の素材は「備品の見直し」（話者A・B・C、7 発話）。別の素材が要るときはそのファイルの中に書く
- Python と JS の両方で実行してから足す。足したら `_data.js` を作り直す
