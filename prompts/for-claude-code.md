# Claude Code で会議を聞く（L-A の読み手への指示）

このファイルは、この道具のフォルダを Claude Code で開いたときに読まれる `CLAUDE.md` の中身です（この道具の根、つまり `kiku.html` のあるフォルダに `CLAUDE.md` として複製するか、`CLAUDE.md` に `@prompts/for-claude-code.md` と1行書いて読み込ませます）。
**あなた（Claude Code）が分析役（読み手）になり、`tools/rt.py` を回して判断ログを書きます。**
分析役としての役・語彙・縛り・出力の形は `prompts/analyst.md` にあります。**先にそれを読んでください。**この文書は、その指示を Claude Code の手順に写したものです。

---

## 1. 何をするか

会議の文字が `live/<会議名>.txt`（メモ帳）に流れ込みます。あなたは、

0. 会議のあいだ `rt.py watch` を裏で回しておき（メモ帳に届いた行に、届いた時刻を押して素材ログへ移す）、
1. 次の窓（数十秒ぶんの発話）を `rt.py next` で受け取り、
2. その窓だけを材料に判断（カード・保留・決着・括り・所感）を書き、
3. `rt.py append` で判断ログ `live/<会議名>.jsonl` に追記する

これを、会議が終わるまで繰り返します。**1窓ずつ。次の窓を見る前に、いまの窓の判断を書き切る。**

大事なのは、話が進むのと同じ速さで判断を重ねていくことです。画面や記録は、その結果として残るものです。結末を知ったうえで整った記録を組み立てると、この道具を使う意味が無くなります。

---

## 2. 手順（命令文はこの形で固定。書き換えない）

すべてこの道具の根（`kiku.html` と `tools/` のあるフォルダ）から打ちます。`<会議名>` は使う人が決めた名前です。

### 始める

```
python tools/rt.py open live/<会議名>.jsonl --live --name <会議名> --transcript live/<会議名>.txt
```

判断ログの先頭に `open`（v2・live・窓 30 秒）が書かれます。メモ帳 `live/<会議名>.txt` がまだ無ければ、`open` が空のファイルとして作ります（上の命令文のように、判断ログと同じフォルダに置くとき）。ほかのフォルダを名指して、そのフォルダがまだ無いときは、メモ帳を作りません。そのときは `open` がそう言い、`watch` はメモ帳ができるまで「見つかりません」と知らせます。

**判断ログの名前の決め。**道具は、判断ログの名前から `.jsonl` を除いた部分（語幹。`live/<会議名>.jsonl` なら `<会議名>`）で、同じフォルダの素材ログ `<語幹>.src.jsonl`・覚え書き `<語幹>.next.json`・`watch` の印 `<語幹>.watch.json` の名前を作ります。だから、

- 判断ログの名前は、**小文字の `.jsonl` でちょうど終わる**名前にします。`.JSONL`・`.peek`・`.tsv`・拡張子の無い名前は断ります。`.src.jsonl`（大小文字を問わない）と `.batch.jsonl` で終わる名前も断ります
- `open` は、その判断ログか派生ファイル（素材ログ・覚え書き・`watch` の印）が**もうあるとき**（空のファイルでも）と、同じフォルダに語幹が**大小文字を無視して同じ**になる判断ログか派生ファイルがあるとき（`会議.jsonl` を開こうとして `会議.JSONL`・`KAIGI.src.jsonl` などがある）、何も書かずに断ります（終了コード 1）。大小文字を区別しない Windows で、別のログの素材ログ・覚え書きを自分のものとして読み書きしないためです。**新しい会議は新しい名前で始めます**
- `watch`・`next`・`append`・`end`・`pause` も、毎回はじめに名前の決めを照らします
- 判断ログのパスに `..`（一つ上のフォルダ）をはさむと、どの命令も断ります（`status`・`digest`・`tools/audit_r2b.py` も同じ）。上の命令文のとおり `live/<会議名>.jsonl` と書けば当たりません
- `open` は、渡されたパスをリンクも解いた本当の場所に直してから、上の決めを照らします。判断ログを置くフォルダ（ここでは `live/`）が無ければ、そのフォルダ 1 つだけを作ります。その上のフォルダも無いときは、何も作らずに断ります（終了コード 1）。途中にフォルダと同じ名前のファイルがあるときも、そう言って断ります
- 判断ログの名前が `/` か `/.` で終わるとき、その名前がフォルダのとき、まだ無い判断ログ（`open` の前）を渡したときは、`watch`・`next`・`append`・`end`・`pause`・`status`・`digest`・`tools/audit_r2b.py` が何も書かずに文で断ります（終了コード 1）。判断ログの名前がリンク（シンボリックリンク）のときも、`open` を含めてどの命令も断ります（リンクの名前と実体の名前が同じでも、別のフォルダから指すリンクなら断ります）。判断ログは実体の名前で渡します。上の命令文の形なら、どれにも当たりません

同時に、メモ帳の隣に**持ち主の印** `live/<会議名>.txt.owner`（中身はこの判断ログの場所）が書かれます。**1 つの素材に開ける判断ログは 1 つ**で、別の判断ログで同じメモ帳（素材ファイル）を `open`・`next`・`append` しようとすると P07 で断られます。
素材（メモ帳・素材ファイル）の名前は `.txt`・`.tsv`・`.vtt` のどれかで終わる名前にします（大小文字は問いません）。判断ログ・素材ログ・持ち主の印・覚え書き・`watch` の印（`.jsonl`・`.owner`・`.next.json`・`.watch.json`）や拡張子の無い名前を素材に名指しすると、`open` が断ります（P30。記録の形の名前と、同じフォルダの別のログの記録は P07 でも断ります）。
素材の名前に `..`（一つ上のフォルダ）をはさむと、`open` は何も書かずに断り（終了コード 1）、`next`・`append` に `--transcript` で渡しても断ります（P07）。
新しい記録を始められるのは `open` だけです（`append` に `open` の行を渡しても P01 で断られます）。
素材ログ `live/<会議名>.src.jsonl` は `open` では作られません。次の `watch` がメモ帳の最初の行を移したときにできます。
前回の会議の引き継ぎがあるときは `--known "<引き継ぎの文>"` を足します（`digest --full` の出力を渡す。`known` の上限は 2000 字で、`digest --full` はその中に収めて出します）。

### 会議のあいだ、watch を裏で回す

```
python tools/rt.py watch live/<会議名>.jsonl
```

- `open` のすぐ後に、**裏で**（Bash を裏で走らせる指定で）打ちます。終わるのを待たずに、次の `next` へ進みます
- `watch` は 1 秒ごとにメモ帳を見て、**新しく確定した行**を素材ログに移します。改行で終わった行は見つけたときに確定します。改行の無い最後の行は、**同じ中身のまま 2 秒変わらなければ**確定します（打っている途中の行は読みません）
- 発話の時刻は、**いつもその行が届いた時刻**（聞き始めからの秒）です。メモ帳に時刻を打ってあっても使いません。だから、時刻を 1 か所打ち間違えても、後の発話の位置はずれません
- 行の読み方: 空でない行はすべて 1 つの発話です（メモ帳には「読めない行」はありません）
  - タブで区切った 1 列目が**時刻らしい**行（数字で始まり、数字と「:」「.」だけで、「:」を含む。全角の数字とコロンは半角に直して見る。「0:5」のような正しくない時刻も含む）は、その列を捨てて残りを読みます。残りにタブがあれば「話者<TAB>本文」、無ければ下の「名前: 本文」の読み方です（「0:20<TAB>司会: 始めます」の話者は「司会」）。最初の 1 回だけ「メモ帳の時刻は使いません（届いた時刻で押します）」と知らせます
  - ほかのタブを含む行は「話者<TAB>本文」。話者の列の終わりの「:」「：」は落とします（「司会:<TAB>始めます」の話者は「司会」）
  - タブを含まない行は、頭が「名前: 」か「名前：」の形なら名前を話者として切り出します（名前は 1〜20 字で、空白を含まず、数字で始まらない。半角の「:」は直後に空白が要る）。「0:45 甲 反対です」「9:00 から始めます」「https://…」のような行は、行の全体が話者無しの本文になります
  - 細かな決まりは `format/FORMAT.md` の「`live` のメモ帳」にあります（ページの打つ入口と同じ読み方です）
- 確定した行（もう素材ログに移した行。以下「読み終えた行」）はあとから直せません。新しい発話として拾うのは、**末尾に足した行だけ**です。読み終えた行の書き換え・消し・間への挿入は拾わず、行番号を挙げて知らせます
- **突き合わせの決め**: `watch` はメモ帳を読むたびに、前に見たメモ帳と行の中身で突き合わせます。道具がめざすのは「黙って欠かさない・黙って二重にしない」で、拾わなかった行は、たいてい行番号で知らせます（知らせが出ない形と、知らせの出ない二重が起きうる形は、下の「知らせが出ない形」のとおりです）。決めの全体は `format/FORMAT.md` の「読み終えた行との突き合わせ」にあります。使う人から見える振る舞いは次のとおりです
  - 読み終えた行が消えると「消えた」と知らせ、道具はその中身を覚えておきます。あとで（同じ保存でも、何回か後の保存でも）**同じ中身の行**が現れたら、末尾でも間でも、戻した行とみなして二度は足しません。だから、読み終えた行を末尾へ動かすと、元の場所は「消えた」、末尾の行は戻した行になり、拾いません
  - 読み終えた行の書き換えは、元の行の「消えた」と、書き換えた行の「間の行は拾いません」の 2 つの知らせになります。最後の行に字を足したときだけは、足した後の行が末尾の新しい行なので新しい発話として拾い、元の行を「消えた」と知らせます
  - 戻した行とみなされた行が本当は新しい発話だったときは、知らせのとおり**末尾にもう一度打ちます**。戻した行とみなされた行をメモ帳に残したままなら、打ち直した行は、同じ中身の消えた行をほかにも覚えていても、新しい発話として拾います（そのとき、覚えていた同じ中身の行は忘れます）。戻した行を消してから末尾に打った（末尾へ動かした）ときは、末尾の行はまた戻した行になります
  - 同じ保存で消えた同じ中身の行が 2 つ以上あり、そのうち 1 つを戻した行とみなしたあとで（下の「残った行」を名指したあとも）、同じ中身の行を末尾に打つと、新しい発話として拾ったうえで「末尾にもう一度打った行とみなして足しました」と知らせます。同じ保存で同じ中身の行を何行も打ったとき（消した行をまとめて元に戻したときなど）は、覚えていた数までの行をそれぞれ名指します。知らせるのはその保存の分だけで、次の保存からは、同じ中身を打っても知らせません。知らせのとおり打ち直したのか、消した行を戻しただけなのか（それなら同じ発話が二重に入っています）は、道具には見分けられないので、黙らずに知らせます
  - 読み終えた行の半分以上が一度に消え、しかも消えた読み終えた行が 3 行以上の保存（メモ帳を空にして打ち直したときなど）では、残った読み終えた行も「前からある行とみなして足していません」と名指します。消えた読み終えた行が 2 行以下なら名指しません
  - 拾っていなかった行（間の行）が消えても、知らせません
  - 行の中身は、1 列目の時刻を捨てたもので比べます。だから時刻の列だけが違う行（「12:05<TAB>乙<TAB>はい」と「12:06<TAB>乙<TAB>はい」）は同じ中身です
  - **知らせが出ない形と、知らせが実際の操作と合わない形があります**（事実。道具が見るのは保存ごとのメモ帳の中身だけで、保存と保存の間の操作は見えません。全体は `format/FORMAT.md` の「読み終えた行との突き合わせ」の 12）。たとえば次の形です
    - 2 行のメモ帳を空にして、最後の行と同じ中身を打つ: 「消えた」の 1 文だけが出て、打った行は発話になりません（消えた読み終えた行が 1 行で、上の 3 行に届かないため）
    - 一度「間の行は拾いません」と名指した行を含むメモ帳を空にして、元に戻す（undo）: その行が名指されずに新しい発話になります（数は合いますが、素材ログでの順がメモ帳の順と違います）
    - 最後の読み終えた行のすぐ手前に、その行と時刻の列だけが違う同じ中身の行を足す（手前の読み終えた行を書き換えて、そうなったときも）: 道具は「最後の読み終えた行の時刻の列を直し、末尾に同じ中身の行を打った」とみなします。知らせは「時刻の列だけが書き換わった」で、末尾の行は新しい発話になります（8 回目の乱数の試験で見つけた形。直し方を変えると、時刻の列を直して末尾に打った場面のほうが黙って欠けるので、変えていません）
    - メモ帳を空にして打ち直し、知らせのとおり末尾に打ち直したあとで、元に戻す（undo）を重ねて空にする前の行まで戻す: 打ち直しで覚えを使い終えているので、戻った行のうちいくつかが、名指されずに二度目の発話になります（8 回目の乱数の試験で見つけた形）
    - 相づちだけの長いメモ帳をまるごと別の中身にするような大きな入れ替え: 知らせの数と行番号が、実際の操作と大きく違うことがあります
    - どの形でも、あなたはメモ帳を開いて確かめません（第3節）。窓に出た発話と知らせだけで判断します
- 1 列目の時刻だけを直した行（時刻の列を捨てると、話者も本文も前と同じ行）は、「読み終えた行の時刻の列だけが書き換わった（N 行目）」と知らせ、「時刻の列だけの直しは記録に効きません（時刻は届いた時刻で押します）」と添えます。末尾に足し直す必要はありません。同じ中身の行が続くメモ帳で、前・後ろ・途中の行の時刻だけを直しても、その直しを元に戻しても、発話は二重にならず、「消えた」とも言いません
- **メモ帳が見つからないとき**: メモ帳が無い・フォルダになっている間、`watch` はメモ帳を読まず（空のメモ帳とはみなしません。みなすと、読み終えた行がすべて消えたことになるため）、「（知らせ）メモ帳 … が見つかりません（…）」か「（知らせ）メモ帳 … はフォルダです（…）」を、状態が変わったときに 1 回だけ出します。見つかると「（知らせ）メモ帳 … が見つかりました。読み始めます」と出します。`next` と `next --last` の出力にも同じ知らせが出ます（黙って 0 行の窓にはしません）。そのときは使う人に知らせをそのまま見せます。メモ帳を作ったり動かしたりするのは使う人です
- **メモ帳はあるのに開けないとき**（ほかのアプリが掴んでいる・権限が無い）: `next` の出力に「（知らせ）メモ帳 … を開けません（…）」が出ます。`next --last` と `end` は、開けるようになるまで同じ文で断ります（開けない間に打った行が、知らせ無しに記録から欠けないように）。使う人に知らせを見せ、メモ帳を開けるようにしてもらってから打ち直します。`watch` は今までどおり、続けて 5 回読めないときに 1 回だけ知らせて読み直します
- メモ帳が続けて 5 回読めないとき（ほかのアプリが掴んでいるときなど）は、`watch` が 1 回だけ「（知らせ）メモ帳 … を続けて読めません…」と出し、読めるようになったら「…読めるようになりました」と出します。そのあいだも止まらずに読み直します
- 素材ログに行を足せるのは `watch` だけです。`next` は素材ログを読むだけで、自分の時刻で行を押すことはしません（押すと、話した位置が `next` を打った時刻まで後ろへずれるため）
- `watch` が出すのは、足した発話の件数と番号、知らせ（行番号だけ）です。**発話の中身は出しません。**裏の出力を読んでも先は見えません
- 記録が `end` で閉じると、`watch` は自分で止まります。1 つの判断ログに回せる `watch` は 1 つです（2 つ目は断られます）
- `watch` の印の読み書きが一時的に失敗したとき（Windows でほかのアプリがそのファイルを掴んでいるときなど）は、少し待って数回やり直します。それでも書けなければ、止まらずに 1 回だけ「（知らせ）watch の印 … を書けませんでした」と出し、次の回に書き直します。書けないあいだは、`next` が `watch` を止まっているとみなすことがあります
- `watch` は回っている間、`watch` の印 `live/<会議名>.watch.json` を書きます。印には**判断ログの名前**が入ります。印の名前が自分と違う（語幹が同じ別の判断ログの印）と、`watch`・`next`・`append`・`end`・`pause` は何もせずに断ります（P07、終了コード 2）。止まった `watch` が残した古い印を、新しい `watch` が引き継ぐのも、名前が同じときだけです
- 名前の書かれていない印（前の版の道具が残した印）も、このログの印とはみなさずに断ります。この知らせが出たら、あなたは印を消さず（第3節）、知らせをそのまま使う人に見せます。その `watch` が止まっていることを確かめて印を消すのは、使う人です
- `watch` が止まっていて、メモ帳に素材ログへまだ入っていない変化（新しい行・消えた行・戻した行・時刻の列の直しなど）があると、`next` は窓を出さずに「watch が回っていません」と言って終わります（終了コード 1）。そのときは上の命令文をもう一度裏で打ってから、`next` を打ち直します。止まっていた間に届いた行には、`watch` が見つけた時刻が押されます（実際より後ろの時刻になります。前にはずれません）

### 次の窓を受け取る

```
python tools/rt.py next live/<会議名>.jsonl --wait 40
```

- 素材ログ（`watch` が移した行）を読み、**窓が閉じていればその窓の発話を出します**（番号・時刻・話者・本文）。閉じていなければ最大 40 秒待ち、それでも閉じなければ「まだ閉じていません」と言って戻ります。その場合はもう一度同じ命令文を打ちます
- live の窓は、**壁時計が窓の終わりを過ぎたときにだけ**閉じます
- `next` を打つのが遅れて、壁時計が窓の終わりをいくつも過ぎていたときは、窓を広げます（窓の幅の 3 倍まで）。広げた窓の終わりも、**窓の幅の目盛り**（窓の始まりから幅の 1・2・3 倍の所）のうち、もう過ぎた所のいちばん後ろに揃えます。`next` を打った時刻そのものにはしません（ページの窓と同じ切り方です）
- 窓が閉じたとき、`next` は窓の覚え書き `live/<会議名>.next.json`（窓の時刻と発話の範囲、この窓で何回目か）を残します。次の `append` は、**この覚え書きを信じきらず、素材ログから窓を計算し直して照らします**（窓の始まりが直前の窓の終わりか（発話の無い窓だけは飛ばす）、幅が窓の幅の 1〜3 倍か、発話の範囲が素材ログのまだ読んでいない発話のうち窓の終わりより前のものちょうど全部か）。合ったときだけ、返事の `step` をその窓と突き合わせます（P07）。**覚え書きが無い間（`next` を打っていない、または「まだ閉じていません」のまま）は `append` が拒まれ、1行も書かれません。**これは live でも、素材ファイルを読む `file` の記録でも同じです（`file` では素材ファイルから計算し直します）
- 1 つの窓で渡す発話は **40 件まで**です。それを超える分は、時刻が窓の中でも次の窓に回ります。そのとき窓の終わりは、**渡さなかった最初の発話の時刻まで縮みます**（聞いたのはそこまで、という扱い）。窓の中にその時刻と同じ時刻の発話があれば、その同じ時刻のまとまりの手前で切ります（渡した発話はどれも窓の終わりより前）。窓の最初の発話から 41 件以上が同じ時刻のときだけ、始まりと終わりが同じ窓に 40 件ちょうどを入れます。返事の `step.t` は、`next` が出した窓をそのまま書きます。素材ファイルの時刻が前の行より前に戻っていたら、前の行の時刻に揃えて渡します（時刻を打ち間違えても、1 つの窓が残りを丸ごと渡すことはありません）
- 窓の発話の後に「（知らせ）…」の行が出ることがあります。素材の読み方で気づいたことを、**行番号だけ**で伝えるものです
  - live の記録（メモ帳）で出るもの
    - 「メモ帳の時刻は使いません（届いた時刻で押します）」: 1 列目に時刻を打った行があった。最初の 1 回だけ出ます
    - 「読み終えた行が消えた（いまの N 行目の手前）」: もう素材ログに移した行が消えた。同じ位置で続けて消えた行は「読み終えた行が 3 行消えた（いまの 1 行目の手前）」のように 1 文にまとめます。説明「読み終えた行は直せません。直した行や新しい行は、メモ帳の末尾に足してください」は、1 つの窓に 1 回だけ添えます
    - 「読み終えた行の間の行は拾いません（N 行目）。新しい発話なら、末尾に打ってください」: 読み終えた行の間に足された行か、読み終えた行を書き換えた行。拾っていません
    - 「消えた行と同じ中身なので、戻した行とみなして足していません（N 行目）。新しい発話なら、末尾にもう一度打ってください」: 消えた行と同じ中身の行が現れた（上の「突き合わせの決め」）。同じ発話を二度は渡しません
    - 「読み終えた行の半分以上が一度に消えました。残った行（N 行目）は…前からある行とみなして足していません…」: メモ帳を空にして打ち直したときなどに、残った行が前の行と同じ中身だった
    - 「消えた行と同じ中身ですが、末尾にもう一度打った行とみなして足しました（N 行目）。消した行を戻しただけなら、同じ発話が二重に入っています」: その行は新しい発話として、窓に入っています。二重かどうかは道具には分かりません。確かめにメモ帳を開くことはせず、気になれば `note` に書きます
    - 「読み終えた行の時刻の列だけが書き換わった（N 行目）」: 1 列目の時刻だけを直した。説明は「時刻の列だけの直しは記録に効きません（時刻は届いた時刻で押します）」です
    - **出る時期**: 出来事の後で最初に届いた発話を渡す窓で出ます。最後の発話より後ろで起きた出来事は、`next --last` の最後の窓で出ます。渡す発話がもう残っていないときは、「（最後の発話より後ろで起きたメモ帳の出来事の知らせです。最後の窓で知らせたものも含みます）」に続けて出ます
    - 前の版の道具が書いた素材ログには「読み終えた行が書き換わった・分かれた・まとめられた・末尾へ動いた」が残っていることがあります。いまの道具は書きません
  - file の記録（素材ファイル）で出るもの。素材ファイルの書き方は 4 つで、中身から 1 つに決まります（拡張子では決めません）。先頭の空でない行が `WEBVTT` で始まれば字幕（`vtt`）。そうでなければ、最初に時刻を持つ行の形で決まります: 時刻だけの行（`alone`）、タブで区切った 1 列目が時刻（`tsv`）、時刻＋空白＋本文の行か、括弧で囲んだ時刻（「[0:45] 甲: …」）で始まる行（`inline`）、字幕の時刻の行（`00:00:01.000 --> 00:00:04.000` の形。`WEBVTT` の行が無くても `vtt`）。決まった書き方は途中で変わりません。発話が 1 つも読めない素材ファイルは、`open` が記録を作らずに断ります（時刻のある行が無い、または時刻のある行の本文がどれも空。ページのファイルの入口と同じ文）。字幕の時刻の行（「-->」を含む行）で字幕と決めた素材を断るときは、何行目でそう決めたかを文に添えます。細かな決まりは `format/FORMAT.md` の「素材ファイルの形」にあります
    - 「読めない行があった（N 行目）。発話にしていない。時刻の書き方を確かめる」: 時刻を書いたつもりらしいのに読めない行（タブで区切った 1 列目が時刻として読めない、行の全体が時刻らしいのに秒が 1 桁、字幕の時刻の形が違う、など）。全角の数字とコロンは半角に直して読むので（字幕の時刻は除く）、それだけでは読めない行になりません
    - 「時刻が飛んでいる行（N 行目）。前に戻った時刻は前の発話の時刻に揃え、10 分を超えて進んだ時刻はそのまま読んだ」: 前の発話より前の時刻か、10 分を超えて先の時刻。拒まずに読んでいます
    - 「読めないバイトを含む行（N 行目）。発話にしていない。素材の文字コードが UTF-8 かを確かめる」: UTF-8 として読めないバイトを含む行。どの書き方でも発話にしません（その手前で前の発話を閉じ、続く行も読めない行として扱います）
    - 「時刻で始まる行は本文として読んだ（N 行目）。時刻の行にするなら、時刻だけを1行に書く」: 頭が時刻らしいのに時刻の行として読まなかった行。前の発話の本文の続きとして読んでいます。当たるのは、`alone` の素材で「9:00 から始めます」のように頭の時刻のあとに空白と本文が続く行、どの書き方でも、タブを含まない行で「0:45司会：…」「9:00から…」のように時刻のすぐ後ろに字が続く行、`alone` の素材で「[0:45] 甲: …」のように括弧で囲んだ時刻で始まる行です（`tsv`・`inline` の素材では、頭が正しい時刻の行と括弧で囲んだ時刻の行は、その時刻の新しい発話です）。書き方がまだ決まらないうちに、時刻のすぐ後ろに字が続く行が来たら、読めない行にします。`alone` の素材に「0:45 甲 反対です」のような時刻・話者・本文の行が混ざると、その行の話は前の発話の本文に入るので、決めどおり、行の頭の時刻（0:45）より早い窓であなたに渡ります（README の「先の話は読みません」の但し書きに書いてある場合で、その窓にはこの知らせが行番号つきで出ます）
    - **出る時期**: その行を含む発話を渡す窓で出ます。どの発話にも入らない行（読めない行とその続き）は、後ろの最初の発話を渡す窓で出ます。最後の発話より後ろの行は、最後の発話を渡す窓で出ます（聞き終えたときにまとめて出すことはしません）
    - **文の数**: 1 つの窓では、種類ごとに 1 文にまとめて行番号を並べます（最初の 5 つまで「・」でつなぎ、残りは「ほか N 行」）。文はページの知らせと一字違わず同じです
  - どの知らせも、メモ帳や素材ファイルを開いて確かめる理由にはなりません。窓に出た発話だけで判断し、気になれば `note` に書きます
- 出力の最後に **次の id**（カード・保留・括り・数え上げ）が出ます。返事の新しい id はこの値から順に使います
- 同じ窓で2回目以降の呼び出しなら、前の返事の違反文が出ます。違反の箇所だけを直します
- 「未確定の窓の発話を gap_lines として読み直せます」と出たら、その発話を根拠にカードを過去の位置に置き、`close.by` でその保留を閉じてよい
- 「新しい発話はまだありません」が続くときは、使う人に聞かず待ちます。**総尺や残りは、道具も出しませんし、あなたも尋ねません**

`--json` を足すと `format/pack.md` の形（状態の最小表現）で出ます。開いている保留・最上位・括り・数え上げ・直近のカードと所感・`next_ids` が全部入っているので、**判断の前にこちらを読むほうが確かです**。

### 判断を書く

返事を **`live/<会議名>.batch.jsonl` に Write** します。形は `format/schema.json` の返事そのもの（`{"step":{"t":[a,b]},"events":[…],"note":{"x":"…"}}`、JSON 1個）でも、1行1イベントの JSONL（先頭は `step`）でも構いません。返事の形で書けば、`n`・`lines`・`at`・`note.t` は道具が埋めます。

```
python tools/rt.py append live/<会議名>.jsonl live/<会議名>.batch.jsonl
```

- `append` は、直前の `next` が残した覚え書きの窓と `step.t` が一致するときだけ受けます。先に `next` を打っていなければ P07 で拒まれます（終了コード 2）
- **道具が照らすものと、照らせないもの。**`append` が照らすのは3つです。(1) 覚え書き（`next` が書いた窓）、(2) 素材ログ（覚え書きの窓を、素材ログから計算し直した窓と比べる。覚え書きを手で書いても、素材ログと合わなければ拒まれる）、(3) 壁時計（live の記録では、`step` の壁時計が「聞き始め＋窓の終わり」より前なら P27 で拒む。聞き終える前に判断は押せない）。**照らせないのは、同じ PC の上で覚え書き・素材ログ・メモ帳そのものを書き換えること**です。道具はそれを見分けられません。`.claude/settings.json` の雛形は `*.next.json`・`*.src.jsonl` への Write・Edit を止めますが、Bash からの書き込みは全部は止められません。だから**あなたはこれらのファイルを書きません**。書き換えたかどうかは、後から会話記録（人が開く。Write・Edit・Bash で何を書いたかが残る）で見ます。`tools/audit_r2b.py` は判断ログに残った先読みの痕跡を数えます
- 規則に反する所が一つでもあれば、**何も書き足されません**（終了コード 2）。違反文が出るので、直して同じ命令文を打ちます（同じ窓で最大3回）
- 返事が JSON として読めないとき・`step` が無いかオブジェクトでないとき・`events` が配列でないとき（`null` も）・`events` の中に `note` を入れたとき（所感は `events` の外の `note` に 1 つ）も、同じ窓の1回に数えます（終了コード 2。違反文は「返事を読めません: …」）
- 書くことの無い窓では、`events` の欄を省いても構いません（`events:[]` として読みます。`"events":null` と書くと読めない返事です）。返事の全体を ``` で 1 回だけ囲んであれば、外して読みます（2 回囲むと読めません）
- 返事の前後の空白は、ページと同じ集まり（半角・全角のスペース、タブ、改行、ノーブレークスペース、BOM など）だけを除きます。それ以外の見えない字（U+0085・U+200B など）が前後に付くと、JSON として読めない返事になります
- 文字列の外の `[` と `{` の入れ子が 500 段を超える返事は、JSON として読む前に F02 で断ります。読めた値の入れ子は 32 段までで、それより深い値も F02 で拒まれます。どちらも同じ窓の1回に数えます
- 3回目も落ちたら、道具が「未確定の窓」の最小バッチ（`kind:"gap"` の保留）を書いて窓を進めます（終了コード 3）。次の `next` で `gap_lines` として戻ってきます
- 書き足せたら、**今回の窓のカードと、まだ閉じていない保留が並んで表示されます**。今回のカードで決着した保留が無いかを、毎回ここで見直してください。閉じ忘れは、この道具でいちばん起きやすい誤りです
- カードは、根拠にした発話を `src` に **1 つ以上**挙げます（空の `src` は P29 で断られます）。カードの時刻（並びの位置）は、その発話の時刻の間に置きます。外に置くと P29 で断られます。保留の決着（`close`）は、保留を開いた時刻より前には置けません

### 聞き終える

会議が終わったら、**`next --last` → `append` → `end`** の順に打ちます（`watch` は回したまま）。

```
python tools/rt.py next live/<会議名>.jsonl --last --json
```

- `watch` が回っていることを確かめ、メモ帳の変化が素材ログに入り終わるのを待ってから、まだ窓にしていない発話を**最後の窓**として出します。待つ変化は、新しい行だけでなく、消えた行・戻した行・間の行・残った行・時刻の列だけの直しも数えます。改行の無い最後の行は、2 秒の確定で入るのを待ちます。返事を書いて、いつもどおり `append` します
- 最後の窓の終わりは、聞き終えた時計の秒（聞き始めからの秒を整数に切り捨て）です。窓の幅の目盛りには揃えません。ただし窓の幅の 3 倍までで、始まりから窓の幅の 3 倍を過ぎていたら、そこで切ります（そこから後ろの発話は、次の `next --last` で出ます）。時計がまだ最後の発話と同じ秒のときは、次の秒に進むのを待ってから閉じるので、窓の終わりは窓の中のどの発話よりも後です
- 最後の窓の終わりは `next --last` が窓を閉じたときに読んだ時計の秒で、`end` の時刻は `end` を打ったときに読んだ時計の秒（と最後の窓の終わりの大きいほう）です。時計を 2 回読むので、続けて打っても 1 秒ずれることがあります（事実。ページの「聞き終える」も同じ作り）。どちらも、時計が進んだ所までしか渡さないので、先を読むことにはなりません
- 最後の窓には、メモ帳の突き合わせの知らせ（最後の発話より後ろで起きた出来事も）が出ます。返事が検査に落ちて打ち直すときは、前に出した最後の窓がそのまま出ます
- 「まだ渡していない発話が N 件あります」と出たら（40 件の上限や、いつもの窓がもう閉じていたため）、`append` のあとでもう一度 `next --last` を打ちます
- 最後の窓の結びは「（最後の窓です。メモ帳の行はすべて読みました（足していない行は上の知らせのとおり）。append のあとで end を打てます）」です。「すべて読みました」は、道具がメモ帳の行を読み終えたという意味で、発話にしなかった行は知らせのとおりです
- 「渡す発話は残っていません」と出たら、`end` を打ちます。最後の発話より後ろで起きたメモ帳の出来事があれば、その前に、上の「出る時期」の見出しの文に続けて知らせが出ます。`--json` を足していれば、このときも JSON 1 個で出ます: `{"last": true, "window": null, "notices": [...]}`。`notices` には知らせと、最後に結びの文（括弧を除いたもの）が入ります
- メモ帳が見つからない・フォルダのときは、待たずに、その知らせを最後の窓に出し、結びは「メモ帳を読めていません（上の知らせ）。…」になります（「すべて読みました」とは言いません）。使う人に知らせを見せ、メモ帳を読ませるなら `watch` が読めるようにしてもらってから `next --last` を打ち直します。このまま終えるなら、そのまま `end` を打てます
- `watch` が止まっていて、メモ帳に素材ログへまだ入っていない変化があると、`next --last` は窓を出さずに断ります（「watch が回っていません。メモ帳に、素材ログへまだ入っていない変化（…）が N 件あります…」、終了コード 1）。`watch` を裏で回し直してから打ち直します
- 会議の途中では使いません（窓が早く閉じるだけで、害はありません）

```
python tools/rt.py end live/<会議名>.jsonl
```

- `end` は、まだ窓に入っていない発話（素材ログにあって、どの窓にも入っていない発話）か、メモ帳にあってまだ素材ログに入っていない変化（`next --last` が待つのと同じ数え。改行の無い最後の行も）があれば、**何も書かずに断ります**（終了コード 1）。会議の最後の発話や知らせが、どの窓にも入らないまま記録が閉じることを防ぐためです。文は次の 2 つです
  - 渡していない発話があるとき: 「まだ渡していない発話が N 件あります。next --last で最後の窓を出し、追記してから end を打ってください」。メモ帳の変化もあれば、続けて「（ほかに、メモ帳に、素材ログへまだ入っていない変化（…）が M 件あります）」
  - メモ帳の変化だけのとき: 「メモ帳に、素材ログへまだ入っていない変化（…）が M 件あります（改行の無い最後の行も数えます）。watch が素材ログに入れるのを待って next --last で最後の窓を出し、追記してから end を打ってください」
- `append` に `end` だけのバッチを渡しても、同じ断りを通ります（同じ文、終了コード 1、何も書かない）。`end` を書く道はどれも、この 1 つの確かめを通ります。それでも、聞き終えるときは上の `end` の命令文を使います
- `end` の時刻は道具が決めます。live の記録では、聞き終えた時計（聞き始めからの秒を整数に切り捨て）と最後の窓の終わりの大きいほうです。素材ファイルを読む `file` の記録では、最後の窓の終わりです（窓が無ければ 0）。ページの「聞き終える」と同じ決め方です
- この手順では `end` に `--t` を足しません。足しても、live の記録では聞き終えた時計の秒より先の時刻は断ります（終了コード 1。何も書きません）。試験の時計（`KIKU_TEST_CLOCK=1` と `--now`）のときだけは別です。`end` と `pause` の `--t` の既定は `python tools/rt.py end -h`・`pause -h` に出ます

### 止める（中断）

```
python tools/rt.py pause live/<会議名>.jsonl --why 休憩
```

中断している間にメモ帳へ入った行も捨てません。届いた時刻で素材ログに入り、再開した後の最初の窓で渡されます。

`end` の後には何も追記できません。`pause` の後は、次の `next` → `append` がそのまま再開になります。`end`・`pause` は、上の命令文で打ちます。どちらも**それ1件だけの追記**で、カードや保留と同じ追記に混ぜることはできません（道具が押す壁時計で書かれます）。`pause` は直前の窓の終わりに置かれます。それより先の時刻には置けません（P22。先に置くと、再開した窓がその間の発話をまとめて渡すことになるため）。

### 次回への引き継ぎ

```
python tools/rt.py digest live/<会議名>.jsonl --full
```

## 4. 許可の種類を最少にする理由

Claude Code は、**初めて出会う命令文・初めて書くパス**ごとに、使う人へ許可を求めます。会議中に許可の画面が出るたびに、使う人は会議から目を離してボタンを押すことになり、その間の窓は溜まります。

許可の規則は**命令文の文字列**に当たります。`python tools/rt.py …` の前方一致に「いつも許可」が出ていれば、`open`・`watch`・`next`・`append`・`end`・`pause`・`digest`・`status` の全部が1つの許可で通ります。ところが、

- `cd <フォルダ> && python tools/rt.py …` のように `&&` で繋ぐと、**そもそも「いつも許可」が出せない**（出る選択肢が「拒否」と「一度だけ許可」の2つになる）
- `PYTHONUTF8=1 python tools/rt.py …` のように環境変数を前に付けると、**別の文字列**になって規則が当たらない
- `python tools/rt.py append … < step.jsonl` や `echo … | python …` も同じ。足りないものは命令文ではなく Python 側（`rt.py`）が持っています（UTF-8 の扱い、ファイル引数）
- ヒアドキュメントの中に書いた JSON は、バックスラッシュが化けることがあります（Python で観測、JSON では未検証）。**バッチはファイルに Write して、ファイル引数で渡す**

だから、**初めて出会う許可の種類は最少で2つ**です。

| 種類 | 文字列 | 回数 |
|---|---|---|
| Bash | `python tools/rt.py …`（前方一致で「いつも許可」） | 1 |
| Write | `live/<会議名>.batch.jsonl`（パスごと） | 1（1つの会話の中で同じパスへの Write が毎回許可を求めるかは記録が無い。**推測：求めない**。初回に数える） |

命令文を組み立て直すと、この数が黙って増えます。**上のコードブロックの形から変えないでください。**

`.claude/settings.json` の雛形（第6節）には `python tools/rt.py …` の allow を入れてあります。それが効いていれば、Bash の 1 回も要りません。

## 5. 1窓の流れ（まとめ）

```
（会議の初めに 1 回）python tools/rt.py watch live/<会議名>.jsonl を裏で回す
python tools/rt.py next live/<会議名>.jsonl --wait 40 --json
  → pack（状態の最小表現）を読む。開いている保留・next_ids・new.lines・notices（知らせ）
  → prompts/analyst.md の縛りで判断する
  → live/<会議名>.batch.jsonl に返事（JSON 1個）を Write
python tools/rt.py append live/<会議名>.jsonl live/<会議名>.batch.jsonl
  → 「このステップのカード／開いている保留」を見る。閉じ忘れが無いか
  → 次の窓へ
（会議が終わったら）python tools/rt.py next live/<会議名>.jsonl --last --json
  → 最後の窓の返事を Write して append。「渡す発話は残っていません」まで繰り返す
python tools/rt.py end live/<会議名>.jsonl
```

**沈黙より保留、断定より所感。**記録に残るのは、あなたが「その時刻に何を分かっていて、何を分かっていなかったか」です。
