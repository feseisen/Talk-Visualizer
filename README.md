# 聞きながら組み上げる（kiku）

会議や研修のように耳で聞く話の構造（論点・問い・まとまり）を、聞いているそばからカードにして並べて見せるツールです。カードは話された時刻の順に上から並び、後から並べ替えることはありません。文字起こしを貼った場合も、後の部分を先に読んでから整理することはありません（話された順に少しずつ読みます）。

使い方は 2 つです。

- **聞きながら。**「聞き取りを開始」を押すと、流れている会議の言葉を受け取り、区切りごとにカードを足していきます。「停止」を押すと終わります。
- **あとから。**「文字起こしを貼って組み上げる」を押して文字起こしを貼ると、同じ表示を作ります。時刻の入っていない文章でも読めます（1 分に 300 字として時刻を見積もります）。

記録の名前を入力しなくても、始めた日時が名前になります。設定は歯車の「設定と記録」にまとめてあり、何も変えずに始められます（ZIP 版だけは、最初に整理する AI を選びます）。終えた記録は、最初の画面の「前の記録」から開き、話が進んだ順に見直せます。

**本番の会議の前に、一度試してください**。このリポジトリのテスト（テスト用の Chromium）でページを通して動かしたのは、入力方法の「打つ／貼る」「ファイル」と、「文字起こしを貼って組み上げる」、分析役（画面の「整理する AI」）の「内蔵のダミー」「手動でチャットに貼る」「人が書く」です。ブラウザの音声認識は、拡張機能「ブリッジ」を通して、画面共有の音を実際の音声認識で文字にできました（私用の Windows の Chrome で 1 回。「対応環境」を参照）。マイクから直接聞く使い方は、まだ実際には試していません。API の分析役は、呼び出す部分をダミーの返事で試しただけで、ページから実際の API キーで会議の区切りを送るところは、まだどこでも試していません（「対応環境」を参照）。

## claude.ai のアーティファクトで使うとき

- **いまは、自分の声は入りません**。拡張機能が取り込むのは「PC から出ていく音」（画面全体を共有したときの音）だけで、自分がマイクに向かって話した声は含まれません（2026-10-10 に確認）。オンライン会議では、相手の声だけが文字になります。マイクの音声もあわせて取り込む仕組みは、まだありません。
- 話を整理するのは、画面を開いている人の Claude です。API キーは要りません。使った分は、その人の使用量に数えられます。最初に 1 回、この画面から Claude を使ってよいかの確認が出ます。
- アーティファクトの中では音声を取り込めないので、会議の音を文字にするのは Chrome の拡張機能「ブリッジ」（`bridge/chrome/`）です。拡張機能が見つからないときは、画面に 3 つの手順が出ます（「拡張機能を保存する」→ `chrome://extensions` を開いてデベロッパー モードをオンにする → 保存した ZIP をその画面にドラッグ＆ドロップする）。インストールすると画面が自動で検出するので、タブを再読み込みする必要はありません。詳しくは `bridge/chrome/README.md` を見てください。
- 拡張機能がインストールされていれば、「聞き取りを開始」を押すと画面共有の選択画面が出ます。会議の画面（またはタブ）を選び、音声も共有します。拡張機能の新しいバージョンがあると画面に表示され、ZIP をもう一度ドラッグ＆ドロップすると置き換わります。
- 拡張機能が無くても、「文字起こしを貼って組み上げる」は使えます。

## はじめに（ZIP で受け取った人へ）

1. <https://github.com/feseisen/Talk-Visualizer/archive/refs/heads/main.zip> を開くと、ZIP がダウンロードされます（このページの「Code」→「Download ZIP」と同じものです）。ZIP を右クリックして「すべて展開」を選びます。
2. 展開したフォルダにある環境チェックのページ `check.html` を、使うブラウザで開いて「調べる」を押します。そのブラウザで何が使えるかが一覧で出ます（調べる内容は「対応環境」の節）。調べるときに、クリップボードの中身は短い文に置き換わります。
3. 同じブラウザで `kiku.html` を開きます。`kiku.html` は完成した状態で入っているので、Python は要りません。ダブルクリックで別のブラウザが開いてしまうときは、`kiku.html` を使いたいブラウザのウィンドウへドラッグ＆ドロップします。
4. 練習します。
   - 右上の歯車「設定と記録」を開き、「入力方法」を「打つ／貼る（OS の音声入力もここ）」に、「整理する AI」を「内蔵のダミー（テスト用）」にして、「閉じる」を押します。記録の名前は空のままで構いません（日時が名前になります）。
   - 「聞き取りを開始」を押し、出てきた入力欄に数行入力して Enter を押します。30 秒ほどでカードが出ます。ダミーなので、カードの中身に意味はありません。
   - 「停止」を押し、「設定と記録」の「書き出す（判断ログと素材ログ）」→「記録を消す」→「本当に消す」の順に押します。
   - 練習のあいだ、ページは外部に何も送りません。
5. 本番では、分析役を選びます。本番の前に、実際に使う入力方法と分析役の組み合わせで、数分間試してください。

| 分析役 | 会議の最中に使えるか | 外へ出るもの |
|---|---|---|
| API（Anthropic）・API（OpenAI 互換） | API キーが要る。会議の速さに追いつくかは未確認。claude.ai のアーティファクトの中では選べない（アーティファクトからは外部に送れない） | 区切りごとに、指示文（約 1.3 万字）と、その区切りの発言・未確定の区切りの発言（どちらも話者名つき）・問いと尋ねた人の名前・カードの見出しと話者名・章の名前・数え上げの項目・最近の所感・「前から知っていたこと」を API の提供元へ送る。うまくいかなかった区切りは、同じ区切りを 3 回まで送る（全体は「外へ出るもの」の節） |
| この画面の Claude（アーティファクトの中） | claude.ai のアーティファクトの中で開いたときだけ選べる（それ以外では断る）。API キーは要らず、使った分は画面を開いている人の使用量に数えられる。会議の速さに追いつくかは未確認 | 区切りごとに、API と同じもの（指示文と、その区切りの発言・未確定の区切りの発言・問い・カードの見出し・話者名など）を、この画面を開いている人の Claude（claude.ai）に渡す。最初に呼び出すとき、画面を開いている人に、この画面から Claude を使ってよいかの確認が出る（その人が決めるまで待ち、ページの側ではタイムアウトを設けない。1 回の呼び出しは claude.ai の側が 5 分ほどで打ち切る）。許可しなければ、同じ区切りを送り直さずに聞き取りを止める |
| 手動でチャットに貼る（遅い） | 1 人では難しい（手動のときは、1 回に貼る区切りが「区切りの長さ」の設定値の 2 倍になる（60〜180 秒の範囲に収める）。既定の 30 秒なら 60 秒、設定値が 20 秒未満なら 3 倍。区切りごとに約 1.4 万字をチャットに貼り、返事をページに貼る）。会議の後に字幕ファイル（`.vtt`）から作るなら使える | ページは何も送らない。貼った先のチャットの提供元に、API と同じもの（指示文、その区切りと未確定の区切りの発言、問い、カードの見出し、話者名など）が渡る |
| 人が書く | 書記（記録係）を別に置けば使える。「区切りの長さ」を 120〜180 秒にする（既定は 30 秒） | 何も出ない |
| 内蔵のダミー（テスト用） | 本番では使わない（話の構造を判断しない） | 何も出ない |

API を使うときは、「API の設定」に API キーを貼り、「接続を試す」でつながることを確かめてから「聞き取りを開始」を押します。「接続を試す」も外部に送信します（「外へ出るもの」の節）。

ページを使わずに、Claude Code を分析役にする方法もあります（「分析役を Claude Code にするとき」の節）。

## 外へ出るもの

ページ（`kiku.html`）が自分から外部にリクエストを送るのは、分析役に API を選んだときの呼び出しだけです。音声認識で音声がサーバーに送られるときは、ページではなくブラウザが送っています。

### 音声

- **ブラウザ音声認識**。聞き始める前に、このブラウザに「この PC の中だけで日本語を文字にできるか」を問い合わせ、その答えに従います。問い合わせる機能（`available()` と、認識の `processLocally`）がブラウザに無ければ、できないものとして扱います。
  - できるという答えなら、PC の中で文字にします。音声は外に出ません。「ブラウザ音声認識」の欄に「この PC の中で文字にする（音声は外へ出ない）」と表示されます。
  - 日本語の音声認識データがまだダウンロードされていないときは、「日本語の音声認識データをダウンロードする」ボタンでダウンロードできます。データはブラウザが提供元（Chrome なら Google）からダウンロードします。サイズは確かめていません。ダウンロードするときに音声は送りません。会社などが管理している PC では、データのダウンロードが止められていることがあります。
  - できないという答えなら、音声をブラウザの提供元のサーバー（Chrome なら Google、Edge なら Microsoft）に送って文字にすることになります。「ブラウザ音声認識」の欄の「音声を…送って文字にすることを承知する」にチェックを入れないと、聞き始められません。このチェックは保存されないので、ページを開き直したら入れ直します。
  - Chrome が音声を送る先は、Google の音声認識のサーバーです（`www.google.com` の中の URL だったと記憶していますが、確かめていません）。会社のネットワークで外部への通信先が制限されているときは、そこが許可されていないと認識は失敗します（下の「5 回失敗すると」）。
  - PC の中で文字にする設定で始めた後に失敗しても、知らせずにサーバーへの送信に切り替えることはしません。
  - 何も聞き取れないまま認識が続けて 5 回失敗すると（使っている場所のネットワークが送り先を止めているときなど）、間隔を少しずつ空けて試したあと止まり、「ブラウザ音声認識」の欄にそう表示します。記録は開いたままなので、入力方法を「打つ／貼る」にして「もう一度聞く」を押せば、同じ記録の続きに書けます。
  - サーバーに送る設定で聞いている間は、「ブラウザ音声認識」の欄に「音声は提供元のサーバーへ送られている」と表示されます。ブラウザが自分の判断で PC の中で文字にしていることもあるので、この表示は実際より大げさな場合があります。逆に、PC の中で文字にしていると表示しながら音声を送ってしまうことは、ページの側では起きないように作ってあります。「この PC の中で文字にしている」と表示するのは、PC の中だけで文字にするようブラウザに指定して始めたときだけです（ブラウザがその指定を守るかどうかは、実際のブラウザでは確かめていません）。
  - 確かめた範囲：問い合わせる機能と、データをダウンロードする機能（`install()`）の名前と呼び出し方は、テストに使った Chromium 141（ヘッドレス。画面を出さずに動かすモード）で確かめ、合っていました。ただしその環境では日本語の音声認識データをダウンロードできず、PC の中で実際に文字にするところまでは試せていません。実際の Chrome 150 と Edge では確かめていません（未確認）。Edge にも PC の中で文字にする仕組みがあるかもしれません（未確認）。どのブラウザでも、ページはブラウザに問い合わせて、その答えに従います。
  - 聞き取るのは、この PC のマイクの音だけです。オンライン会議の相手の声をヘッドホンで聞いているときは、その声は入りません。
  - `kiku.html` をファイルとして開いたページ（URL が `file://` で始まる）で、ブラウザの音声認識が動くかは確かめていません。ブラウザによっては、ページをサーバーから開かないと動かないことがあります。動かないとき（「マイクの許可が無い」と出て止まるなど）は、入力方法を「打つ／貼る」にして、OS の音声入力（Windows なら Win+H）を使ってください。
  - マイクの許可は、ページを開くたびに求められることがあります（ファイルとして開いたページの許可をブラウザが覚えておくかは、確かめていません）。
  - 会社などが管理している PC で、マイクの使用が会社の設定で止められていると、認識は「マイクの許可が無い」として止まります。`check.html` はマイクの許可を求めないので、これを事前に見分けることはできません。
- **打つ／貼る**。OS の音声入力（Windows なら Win+H）を使う場合、音声がどう扱われるかは OS の設定しだいです。ページからは分かりません。
- **ファイル**。選んだファイルは、このブラウザの中で読むだけです。

### 会議の中身（分析役）

- **API（Anthropic）・API（OpenAI 互換）**。区切りが終わるたびに、指示文（約 1.3 万字）と次のものを API の提供元へ送ります。画面の「API の設定」の欄にも、同じことが書いてあります。
  - 「前から知っていたこと」（毎回）
  - その区切りの発言（話者名つき）
  - 未確定の区切りの発言（話者名つき）。未確定の区切りとは、3 回送っても使える返事が来ず、判断を書けなかった区切りです。その区切りが片付くまで、後の区切りでも毎回送ります
  - 答えを待っている問いと、尋ねた人の名前
  - 最上位の候補のカードの見出し
  - 章の名前
  - 宣言された数え上げの項目
  - 最近のカード（8 枚まで）の見出しと話者名
  - 分析役が最近書いた所感（3 つまで）
  - いまの日時

  呼び出しに失敗したときや、返事が決まった形式に合わないときは、その理由を添えて同じ区切りをもう一度送ります（1 つの区切りで 3 回まで）。

  「接続を試す」では、会議の発言は送りません。指示文（約 1.3 万字）と「「了解」とだけ答えてください。」という短い質問を、2 回続けて送ります（2 回目は、指示文が提供元のキャッシュに載るかを見るためです）。この 2 回も使用量に数えられます。

  Anthropic の既定のモデル（`claude-opus-5-5`）には、エフォート（考える量）を `medium`、1 回の返事の上限を 16000 トークン（考えた分を含む）、1 回の呼び出しのタイムアウトを 120 秒にして送ります。「モデル」の欄に別のモデルを入力したときは、エフォートを送りません（受け付けないモデルがあるため）。1 回の呼び出しにかかる時間は確かめていません。返事を待っている間に話された分は、次の区切りにまとめて入ります（区切りは「区切りの長さ」の 3 倍、または 40 件まで広がります）。

  設定の決まり：

  - API キーが空のときは、聞き始めません。
  - 「API（OpenAI 互換）」は、モデル名が空なら聞き始めません。
  - 「API（Anthropic）」の送り先は常に `api.anthropic.com` で、変えられません。「送り先の URL」の欄に何か入っていると、聞き始めません。OpenAI 互換の送り先を使うなら「API（OpenAI 互換）」を選びます。
  - Azure のように API キーのヘッダー名が違う送り先や、`?api-version=` を付ける送り先は、いまの画面では設定できません（未対応）。
  - API キーはページにもファイルにも入っていないので、この画面で貼ります。既定では、このタブの中だけに置き、タブを閉じると消えます。「この PC に保存する」を選ぶと、このブラウザの保存領域（この PC の中）に暗号化されずに残り、同じブラウザでファイルとして開いた他のページからも読めます。画面にも「保存すると、API キーはこの PC の中に暗号化されずに残り、ファイルとして開いた他のページからも読める場所に置かれます。共有の PC では選ばないでください。」と表示されます。
  - 「送り先の URL」と「モデル」の欄は、「この PC に保存する」を選ばなくても、常にこのブラウザに保存します。秘密の情報ではありませんが、同じブラウザでファイルとして開いた他のページからも読めます。
- **手動でチャットに貼る**。ページは何も送りません。画面に「プロンプトには、指示文（約 1.3 万字）と次のものが入る：「前から知っていたこと」、その区切りの発言（話者名つき）、未確定の区切りの発言（話者名つき。その区切りが片付くまで毎回）、答えを待っている問いと尋ねた人の名前、最上位の候補の見出し、章の名前、宣言された数え上げの項目、最近のカード 8 枚までの見出しと話者名、最近の所感 3 つまで、いまの日時。返事が決まった形式に合わないときは、合わなかった理由を添えた同じ区切りのプロンプトがもう一度出る（1 つの区切りで 3 回まで）。貼ったものは全部、貼った先のチャットの提供元に渡る。」と表示されます。中身は、上の API に送るものと同じです。
- **人が書く・内蔵のダミー**。何も外に出ません。
- **Claude Code（`tools/rt.py`）**。ページは使いません。Claude Code が読んだ区切りの発言は、Claude Code が使うモデルの提供元に渡ります。

### 記録

- 記録（判断ログと素材ログ）は、このブラウザの保存領域（IndexedDB）に残ります。タブを閉じても消えません。
- この保存領域は、同じブラウザでファイルとして開いた他のページ（URL が `file://` で始まるもの）からも読めます。共有の PC では、使い終えたら書き出してから「記録を消す」を押してください。
- 会社などが管理している PC で、ブラウザを閉じるとサイトのデータを消す設定になっていると、書き出していない記録はそのときに消えます。
- ページを開き直しても、最初の画面の「前の記録」（最近の 5 件）か、「設定と記録」の「前の記録」→「開いて見る」で記録を画面に出し、見直したり書き出したりできます。停止していない記録は、その名前を「記録の名前」に入力して「聞き取りを開始」を押すと、続きから聞けます（「使い方の細部」を参照）。
- 消すときは「記録を消す」→「本当に消す」の順に押します（「記録を消す」だけでは消えず、画面の中で確認が出ます。「やめる」で戻れます）。消えるのはその名前の記録だけです。書き出していなければ、元に戻せません。
- 「書き出す」は、この PC にファイルとして保存するだけです。書き出したファイルを `kiku.html` に読み込んで見直す機能は、まだありません。

### 社内のルール

- 会議の内容を外部の API やチャットに送ってよいかどうかは、社内のルールに従ってください。
- 記録を取ることを参加者に知らせるのは、使う人の責任です。
- 同僚に記録を渡すときは、素材ログは渡さず、判断ログの話者名（`who` の欄と、所感・見出しなどの文中）を役割名に置き換えてください。
- 渡した判断ログは、受け取った人の `kiku.html` では開けません（読み込む機能がありません）。判断ログは 1 行に 1 件の JSON を書いたテキストファイルなので、テキストとして読んでもらうことになります。

### `check.html` が調べること

`check.html` は、その PC のブラウザで何が使えるか（音声認識・保存・クリップボード・API への到達）を一覧にします。音声認識は、音声認識の機能とマイク入力の機能が**あるか**を見るだけです。認識は始めず、マイクの許可も求めません。この PC の中で文字にできるかは調べません。

外部にリクエストを送るのは API の項目だけで、送り先は 2 つの API の URL に限ってあります。API 1 つにつき、リクエストは最大 3 回です。内訳は、ブラウザが自動で送る事前確認のリクエスト（プリフライト）、中身の無い呼び出し、そして、その応答が読めず、リダイレクトが返ったかどうかも分からないときだけ送る到達確認のリクエストです。

API の項目を「可」にするのは、API キーなしの呼び出しが 401 で拒否され、その本文がその API 特有の拒否の形式になっているときだけです。Anthropic は `error.type` が `authentication_error`。OpenAI は、`error.code` に `api_key` か `apikey` の語があるか、`error.type` が `invalid_request_error` で `error.message` に `api key`・`api_key`・`apikey`・`bearer`・`authenticat` のどれかの語があるものです（語は大文字・小文字を区別せず、含むかどうかだけを見るので、API キーと関係のない認証のメッセージでも OpenAI の形式として数えます）。401 でも形式が違えば、社内のプロキシが止めた可能性があるので「不可」にします。Anthropic の形式は実物で確かめました。OpenAI の形式は、開発した環境からはつながらず実物を見ていないので推測です。2026-10-09 の Chrome 150 では OpenAI の 2 項目も「可」でしたが、返ってきた本文そのものは見ていません。

どのリクエストもリダイレクトをたどらず（同じサイトの中のリダイレクトもたどりません）、タイムアウトしたものはその場で取り消し、API キーとクッキーは付けません。テスト用に作ったプロキシ 22 種類（社内のプロキシをまねたものと、実際の API に似せたもの）と、開発した環境のネットワークで試した範囲では、どれも 2 つの API を合わせて 6 回以下でした（実際の Edge と実際の社内のプロキシでは試していません。結果は `docs/results.md`）。

結果は 15 行のテキスト（見出し 1 行と項目 14 行。各行は「可／不可／未実行」に短い補足が付き、補足に HTTP のステータスコードが入ることがあります）にまとまるので、そのまま貼り付けて渡せます。

## しくみ

話した言葉のテキスト（「打つ／貼る」・ブラウザの音声認識・「ファイル」）を、30 秒ほどの区切りに分けます（`format/FORMAT.md` と `tools/rt.py` では、この区切りを「窓」と呼びます）。区切りごとに分析役（API、Claude Code、「手動でチャットに貼る」、または人）が「カード・問い・括り」の判断を返します。検査器を通った判断だけを、追記専用の記録（判断ログ `<会議名>.jsonl` と素材ログ `<会議名>.src.jsonl`）に書きます。画面はその記録をそのまま描いたものです。縦の並びは話された時刻の順のまま動かさず、先の話は読みません。ページを開いている間は、その記録を「振り返り」で頭から見直せます（「記録」の節）。

形式の決まりは `format/FORMAT.md`、検査の規則表は `format/rules.json`、守る規則の一覧は `docs/rules.md` です。

## 使い方の細部

`kiku.html` は完成した状態で入っているので、ブラウザで開くだけで使えます。`src/` などを直したときだけ、`python3 build_html.py`（Windows ではたいてい `py -3 build_html.py`）で作り直します（外部のファイルを読み込まない 1 つの HTML ファイルになります）。

入力方法と分析役を「設定と記録」で選び（ZIP 版で初めて使うとき）、「聞き取りを開始」を押します。記録の名前が空なら、始めた日時が名前になります。名前を入力して始めると、同じ名前の記録の続きになります。ただし次のときは断り、記録には何も書きません：その記録がもう聞き終えているとき、古い形式（1 版）の記録や、この画面が対応していない版の記録のとき、前と入力方法の種類が違うとき（「ファイル」で聞いた記録の続きは「ファイル」でだけ、「打つ／貼る」「ブラウザ音声認識」「ブリッジ」で聞いた記録の続きは、この 3 つのどれでも聞けます）。続きでは、「区切りの長さ」は前の記録のものを使います（「ファイル」では、前と同じ文字起こしのファイルを読み込めば、前に聞いた発話を頭から読み飛ばして続けます。ファイルが前と合わなければ断ります）。一時停止している間に入力した行も捨てず、再開した後の最初の区切りに入れます。

「打つ／貼る」では、行頭が「名前: 本文」（半角の「:」のあとに空白）か「名前：本文」（全角の「：」）の形なら、その名前を話者にします。「15:00までに」「https://…」のように時刻や URL で始まる行は、行全体を話者なしの本文として扱います（決まりは `format/FORMAT.md` の「話者の切り出し」）。表から貼った「時刻<TAB>話者<TAB>本文」の行は、1 列目の時刻を使わず、届いた時刻で記録します（`rt.py` のメモ帳と同じ読み方です）。

終わったら「停止」→「書き出す」で、2 つの記録をファイルに保存します。「停止」を押すと、まだ区切りに入っていない発話（入力途中の欄の文字も）を最後の区切りとして渡してから、記録を閉じます。ブラウザの音声認識で聞いているときは、止めた認識（一時停止の前に止めたものも）の終了の通知を合わせて 3 秒まで待ち、その間に届いた言葉も最後の区切りに入れます。3 秒たっても来なければ、「入力方法」の欄の下にそう表示して閉じます。それより後に届いた言葉は素材ログに出来事として残し、「入力方法」の欄の下に「聞き終えた後に届いた認識の結果が 1 件あった。構造には入れず、素材ログにだけ残した」と表示します。

## 読み込むファイルについて

「ファイル」で読み込める文字起こしの書き方は 4 つです：時刻・話者・本文をタブで区切った表、時刻だけの行と本文の行、「0:05 甲: 始めます」のように時刻のあとに空白と本文を続けた行、WebVTT の字幕（会議ツールが書き出す `.vtt`。話者タグ `<v 名前>` の名前を話者にします）。どの書き方かは、拡張子ではなくファイルの先頭の中身で決めます（`WEBVTT` の行が無い字幕も、字幕の時刻の行で見分けます。決まりは `format/FORMAT.md` の「素材ファイルの形」。`rt.py` も同じ読み方です）。

時刻のある行が 1 つも無いなどで発話が 1 つも無いファイルは、読み込んだときにそう表示し、「聞き取りを開始」を押しても記録を作らずに断ります（0 バイトのファイルや空白だけのファイルも同じで、断るときの文は `rt.py` と同じです。見出しの「10:00 --> 11:00 定例」のような行のせいで字幕として読んだファイルなら、何行目で字幕と判断したかも文に添えます）。

読めない行・文字化けしている行（UTF-8 として読めないバイトを含む行）・時刻が飛んでいる行・時刻で始まる本文の行があると、その発話を渡す区切りのときに、「入力方法」の欄の下に行番号つきで知らせます（続きから聞くときも、まだ区切りで渡していない発話についての知らせは同じように出します。ただし欄の「前の区切りまでの知らせ」の 1 行には、開き直した後に渡した区切りの分しか入りません）。

時刻のように見えても、時刻のある行としては読まない行があります。ファイルにこれが混ざると、その行は前の発話の本文の続きとして読みます。そのため、その話は前の発話の区切りで（行の時刻より早く）分析役に渡ります。

- 当てはまるのは、WebVTT の字幕以外のどの書き方でも、時刻のすぐ後ろに空白を置かずに文字が続く行（「0:45司会：次の議題です」「9:00から始めます」）と、「時刻だけの行と本文の行」の書き方での「0:45 甲 反対です」のような行や、「[0:45] 甲: …」のように括弧で囲んだ時刻の行です。
- どの場合も、その区切りで行番号つきの知らせ（ふつうは「時刻で始まる行は本文として読んだ（N 行目）」。読めない行のすぐ後ろに続く行なら、読めない行の知らせ）が必ず出ます。
- 表と「時刻＋空白＋本文」の書き方では、括弧で囲んだ時刻の行は、括弧の中の時刻の発話として読みます。文字化けしている行は、どの書き方でも発話にせずに知らせます。
- これに当てはまらない行（括弧の中が時刻の書き方に合わない「[0:5] 甲: …」、先頭が時刻として読めない「16:9の画面」など）は、知らせを出さずに前の発話の続きになります。ファイルの時刻の打ち間違いがこの形だと、その話は知らせが出ないまま前の区切りで渡ります。

決まりは `format/FORMAT.md` の「素材ファイルの形」の 9・9b・10 です。

## 分析役を Claude Code にするとき

ページは使わず、`tools/rt.py` を使います（手順は `prompts/for-claude-code.md`、許可設定のひな形は `.claude/settings.json`）。

判断ログの名前は、小文字の `.jsonl` で終わるものだけ使えます（`.src.jsonl` で終わる名前は素材ログの名前なので断ります。パスの途中に「..」を挟んだ名前も断ります。メモ帳・文字起こしのファイルの名前に「..」を挟んだときも断ります。判断ログの名前がリンクなら断ります。フォルダの部分のリンクは解決して使います）。`rt.py open` は、名前から `.jsonl` を除いた部分が大文字・小文字を無視して同じになる判断ログか、その素材ログ・覚え書き・`watch` が動いている間に置くファイル（`.watch.json`）が同じフォルダにすでにあれば、断ります（大文字・小文字を区別しない Windows で、別の記録のファイルを自分のものとして読み書きしないためです）。

`rt.py next` は、区切りが終わったときに覚え書き `<会議名>.next.json`（区切りの時刻と行の範囲、何回目か）を残し、次の `append` がそれと突き合わせます。これは記録ではなく一時ファイルで、終われば消えます。

その場で聞くとき（メモ帳に入力するとき）は、発話の時刻に `watch` が受け取った時刻を使い、メモ帳に入力した時刻は使いません。一時停止している間に入力した行も捨てません。読み終えた行をメモ帳で消したり書き換えたりしても記録は直さず、拾わなかった行はたいてい行番号つきで区切りに知らせます。ただしツールはメモ帳の中身だけを見るので、見分けられずに、拾いも知らせもしないケースがあります（メモ帳を空にして前と同じ中身の行を入力する、など）。メモ帳を空にして入力し直した後に、元に戻す（undo）を重ねて前の行を戻すと、同じ中身の行が知らせの無いまま 2 回目の発話になるケースも、まれにあります。相づちだけの長いメモ帳をまるごと入れ替えたときは、知らせの数と行番号が実際の操作と大きく食い違います（決まりと、知らせが出ないケースの一覧は `format/FORMAT.md` の「読み終えた行との突き合わせ」の 12）。

聞き終えるときは、`next --last` → `append` → `end` の順に実行します。`end` は、まだ区切りに入っていない発話（メモ帳の、改行の無い最後の行も）が残っていれば、何も書かずに断ります。ページの「停止」と同じく、どの発話もいずれかの区切りに入ってから記録が閉じます。最後の区切りの終わりも同じ決め方で、聞き終えた時点の経過秒数（会議の開始からの秒数。小数点以下は切り捨て。幅は「区切りの長さ」の 3 倍まで）です。これは、ツールが最後の区切りの終わりを決めるときに読んだ時計の値なので、前の区切りの返事を待っている間に聞き終えたときなどは、コマンドを実行した時刻より後になります。`end` の `t` は書くときに時計を読み直すので、最後の区切りの終わりと 1 秒ずれることがあります。
