# 聞きながら組み上げる（kiku）

会議や研修のように耳で追う話について、その組み立て（論点・問い・まとまり）を、聞いているそばからカードにして並べて見せる道具です。縦の並びは語られた時刻のままで、先の話は読みません。ページを開いている間は、その記録を「追体験」として頭から見直せます（書き出したファイルを読み込んで見直す口は、まだありません）。

見た目はまだ試験用の素の形です（画面の設計はこれから）。

**本番の会議の前に、一度ためしてください。**このリポジトリの試験（試験用の Chromium の上）で、ページを通して動かしたのは、打つ／貼る・ファイルの入口と、内蔵の模擬・手動の輪・人が書く、の分析役です。ブラウザの音声認識は作り物の認識で試しただけで、本物のマイクと本物の認識では動かしていません。API の分析役は、呼び出しの部品を作り物の返事で試しただけで、ページから本物の鍵で会議の窓を送るところは、まだどこでも動かしていません（「対応環境」）。

## はじめに（ZIP で受け取った人へ）

1. このページの「Code」→「Download ZIP」で落とします。ZIP を右クリックして「すべて展開」します。
2. 展開したフォルダの `check.html` を、使うブラウザで開いて「調べる」を押します。そのブラウザで何が動くかが一覧になります（調べることは「対応環境」の節）。調べるとき、クリップボードの中身は短い文に置き換わります。
3. 同じブラウザで `kiku.html` を開きます。`kiku.html` は組み立て済みで入っています。Python は要りません。ダブルクリックで別のブラウザが開くときは、`kiku.html` を使いたいブラウザの窓へ引きずり込みます。
4. 練習します。
   - 会議の名前に「練習」と打ちます。入口は「打つ／貼る（OS の音声入力もここ）」、分析役は「内蔵の模擬（試験用）」を選び、「聞き始める」を押します。
   - 数行打って Enter を押します。30 秒ほどで中央にカードが出ます。模擬なので、カードの中身に意味はありません。
   - 「聞き終える」→「書き出す（判断ログと素材ログ）」→「記録を消す」の順に押します。
   - 練習では、ページは外へ何も送りません。
5. 本番では、分析役を選びます。本番の前に、使う入口と分析役の組み合わせで、数分ためしてください。

| 分析役 | 会議の最中に使えるか | 外へ出るもの |
|---|---|---|
| API（Anthropic）・API（OpenAI 互換） | 鍵が要る。会議の速さに追いつくかは未確認 | 窓ごとに、指示文（約 1.3 万字）と、その窓の発言・未確定の窓の発言（どちらも話者名つき）・問いと尋ねた人の名前・カードの見出しと話者名・章の名前・数え上げの項目・最近の所感・「聞き始める前に知っていたこと」を API の提供元へ送る。うまくいかない窓は同じ窓を 3 回まで送る（全部は「外へ出るもの」） |
| 手動の輪（遅い） | 1 人では難しい（窓の長さは窓幅の 2 倍を 60〜180 秒に収めたもので、既定の窓幅 30 なら 60 秒。窓幅を 20 より小さくすると窓幅の 3 倍。1 窓ごとに約 1.4 万字をチャットに貼り、返事を戻す）。会議の後に字幕ファイル（`.vtt`）から作るなら回る | ページは何も送らない。貼った先のチャットの提供元に、API と同じもの（指示文、その窓と未確定の窓の発言、問い、カードの見出し、話者名など）が渡る |
| 人が書く | 書き役を別に立てれば使える。窓幅の欄を 120〜180 にする（既定は 30） | 何も出ない |
| 内蔵の模擬（試験用） | 使わない（構造の判断をしない） | 何も出ない |

API を使うときは、「API の設定」で鍵を貼り、「接続を試す」で通ることを確かめてから「聞き始める」を押します。「接続を試す」も外へ送ります（「外へ出るもの」）。

ページを使わずに、Claude Code を分析役にする道もあります（「分析役を Claude Code にするとき」の節）。

## 外へ出るもの

ページ（`kiku.html`）が自分で外へ要求を出すのは、分析役に API を選んだときの呼び出しだけです。音声認識で音声がサーバーへ行くときは、ページではなくブラウザが送ります。

### 音声

- **ブラウザ音声認識。**聞き始める前に、このブラウザに「この PC の中だけで日本語を文字にできるか」を尋ね、その答えに従います。尋ねる口（`available()` と、認識の `processLocally`）がブラウザに無ければ、できないものとして扱います。
  - できると答えたら、PC の中で文字にします。音声は外へ出ません。入口の欄に「この PC の中で文字にする（音声は外へ出ない）」と出ます。
  - 日本語の部品がまだ入っていないときは、「日本語の部品を入れる」ボタンで入れられます。部品はブラウザが提供元（Chrome なら Google）から落とします。大きさは確かめていません。入れるときに音声は送りません。管理された PC では、部品の取得が止められていることがあります。
  - できないと答えたときは、音声をブラウザの提供元のサーバー（Chrome なら Google、Edge なら Microsoft）へ送って文字にすることになります。入口の欄の「音声を…送って文字にすることを承知した」に印を付けないと、聞き始められません。この印は覚えません。ページを開き直したら、付け直します。
  - Chrome が音声を送る先は、Google の音声認識のサーバー（`www.google.com` の中の口、と記憶しています。確かめていません）です。会社のネットワークで外への通信を許す先が決められているときは、そこが許されていないと認識は失敗します（下の「5 回失敗すると」）。
  - PC の中で文字にする設定で始めた後に失敗しても、黙ってサーバーへ切り替えることはしません。
  - 何も聞き取れないまま認識が続けて 5 回失敗すると（使う場所のネットワークが送り先を止めているときなど）、間を少しずつ空けて試したあと止まり、入口の欄にそう出します。記録は開いたままなので、入口を「打つ／貼る」にして「聞き始める」を押せば、同じ記録の続きに書けます。
  - サーバーへ送る設定で聞いている間、入口の欄には「音声は提供元のサーバーへ送られている」と出ます。ブラウザが自分の判断で PC の中で文字にしていることもあるので、この札は言い過ぎのことがあります。逆の向き（PC の中だと言いながら送る）には、ページの側からは倒れません。「PC の中で文字にしている」と出すのは、PC の中だけで文字にするようブラウザに指定して始めたときだけです（その指定をブラウザが守るかは、実物では確かめていません）。
  - 確かめた範囲：尋ねる口と、部品を入れる口（`install()`）の名前と形は、試験に使った Chromium 141（headless）で確かめ、合っていました。ただしその環境では日本語の部品が入らず、PC の中で実際に文字にするところまでは試せていません。実物の Chrome 150 と Edge では確かめていません（未確認）。Edge にも PC の中で文字にする仕組みがあるかもしれません（未確認）。どのブラウザでも、ページはブラウザに尋ねて、その答えに従います。
  - 聞くのは、この PC のマイクだけです。オンライン会議の相手の声をヘッドホンで聞いているときは、その声は入りません。
  - `kiku.html` をファイルとして開いた（住所が `file://` で始まる）ページで、ブラウザの音声認識が動くかは確かめていません。ブラウザによっては、ページをサーバーから開かないと動かないことがあります。動かないとき（「マイクの許可が無い」と出て止まるなど）は、入口を「打つ／貼る」にして、OS の音声入力（Windows なら Win+H）を使ってください。
  - マイクの許可は、ページを開くたびに聞かれることがあります（ファイルとして開いたページの許可をブラウザが覚えるかは、確かめていません）。
  - 管理された PC で、マイクを使うことが会社の設定で止められていると、認識は「マイクの許可が無い」として止まります。`check.html` はマイクの許可を求めないので、これを前もって見分けられません。
- **打つ／貼る。**OS の音声入力（Windows なら Win+H）を使うと、音声の扱いは OS の設定しだいです。ページからは分かりません。
- **ファイル。**選んだファイルは、このブラウザの中で読むだけです。

### 会議の中身（分析役）

- **API（Anthropic）・API（OpenAI 互換）。**窓が閉じるたびに、指示文（約 1.3 万字）と次のものを、API の提供元へ送ります。画面の「API の設定」の欄にも、同じことを書いてあります。
  - 「聞き始める前に知っていたこと」（毎回）
  - その窓の発言（話者名つき）
  - 未確定の窓の発言（話者名つき）。未確定の窓は、3 回送っても使える返事が来ず、判断を書けなかった窓です。その窓が片付くまで、後の窓でも毎回送ります
  - 答えを待っている問いと、尋ねた人の名前
  - 最上位の候補のカードの見出し
  - 章の名前
  - 宣言された数え上げの項目
  - 最近のカード（8 枚まで）の見出しと話者名
  - 分析役が最近書いた所感（3 つまで）
  - いまの日時

  呼び出しに失敗したときや、返事が決まりに合わないときは、その理由を添えて、同じ窓をもう一度送ります（1 つの窓で 3 回まで）。

  「接続を試す」は、会議の発言を送りません。指示文（約 1.3 万字）と「「了解」とだけ答えてください。」という短い問いを、2 回続けて送ります（2 回目は、指示文が提供元の一時保存に乗るかを見るため）。この 2 回も、使った量に数えられます。

  Anthropic の既定のモデル（`claude-opus-5-5`）には、考える量を `medium`、1 回の返事の上限を 16000 トークン（考えた分を含む）、1 回の呼び出しの打ち切りを 120 秒にして送ります。モデルの欄に別のモデルを打ったときは、考える量を送りません（受け付けないモデルがあるため）。1 回の呼び出しにかかる時間は確かめていません。返事を待つ間に話された分は、次の窓にまとめて入ります（窓は窓幅の 3 倍、または 40 件まで広がります）。

  設定の決まり：

  - 鍵が空なら、聞き始めません。
  - 「API（OpenAI 互換）」は、モデル名が空なら聞き始めません。
  - 「API（Anthropic）」の送り先は、いつも `api.anthropic.com` で、変えられません。送り先の住所の欄に何か入っていると、聞き始めません。OpenAI 互換の送り先を使うなら「API（OpenAI 互換）」を選びます。
  - Azure のように鍵の見出しが違う送り先や、`?api-version=` を付ける送り先は、いまの画面からは設定できません（未対応）。
  - 鍵はページにもファイルにも入っていません。この画面で貼ります。既定では、このタブの中だけに置き、タブを閉じると消えます。「この PC に覚える」を選ぶと、このブラウザの保存（この PC の中）に平文で残り、同じブラウザでファイルとして開いた他のページからも読めます。画面にも「覚えると、鍵はこの PC の中に平文で残り、ファイルとして開いた他のページからも読める場所に置かれる。共有の PC では選ばない。」と出ます。
  - 送り先の住所とモデルの欄は、「この PC に覚える」を選ばなくても、いつもこのブラウザに覚えます。秘密ではありませんが、同じブラウザでファイルとして開いた他のページからも読めます。
- **手動の輪。**ページは何も送りません。画面に「プロンプトには、指示文（約 1.3 万字）と次のものが入る：「聞き始める前に知っていたこと」、その窓の発言（話者名つき）、未確定の窓の発言（話者名つき。その窓が片付くまで毎回）、答えを待っている問いと尋ねた人の名前、最上位の候補の見出し、章の名前、宣言された数え上げの項目、最近のカード 8 枚までの見出しと話者名、最近の所感 3 つまで、いまの日時。返事が決まりに合わないときは、合わなかった理由を添えた同じ窓のプロンプトがもう一度出る（1 つの窓で 3 回まで）。貼ったものは全部、貼った先のチャットの提供元に渡る。」と出ます。中身は、上の API に送るものと同じです。
- **人が書く・内蔵の模擬。**何も出ません。
- **Claude Code（`tools/rt.py`）。**ページを使いません。Claude Code が読んだ窓の発言は、Claude Code が使うモデルの提供元に渡ります。

### 記録

- 記録（判断ログと素材ログ）は、このブラウザの中の保存（IndexedDB）に残ります。タブを閉じても消えません。
- この保存は、同じブラウザでファイルとして開いた（住所が `file://` で始まる）他のページからも読めます。共有の PC では、使い終えたら書き出して、「記録を消す」を押してください。
- 管理された PC で、ブラウザを閉じるとサイトのデータを消す設定になっていると、書き出していない記録はそのときに消えます。
- ページを開き直すと、聞き終えた記録は画面に出せず、書き出すこともできません（ブラウザの中には残っていて、名前を打って「記録を消す」を押せば消せます）。だから、聞き終えたら、ページを閉じる前に「書き出す」を押してください。聞き終えていない記録は、同じ名前で聞き始めると続きになります（「使い方の細部」）。
- 消すときは「記録を消す」を押します。その名前の記録だけを消します。書き出していなければ戻りません。
- 「書き出す」は、この PC にファイルとして落とすだけです。書き出したファイルを `kiku.html` に読み込んで見直す口は、まだありません。

### 使う場所の決まり

- 会議の中身を外の API やチャットに送ってよいかは、使う場所の決まりに従ってください。
- 録ることの告知は、使う人の責任です。
- 同僚に記録を渡すときは、素材ログを渡さず、判断ログの話者名（`who` の欄と、所感・見出しなどの文の中）を役割名に置き換えてください。
- 渡した判断ログは、受け取った人の `kiku.html` では開けません（読み込む口が無い）。判断ログは 1 行に 1 件の JSON を書いた文字のファイルなので、文字として読んでもらうことになります。

### `check.html` が調べること

`check.html` は、その PC のブラウザで何が動くか（音声認識・保存・クリップボード・API への到達）を一覧にします。音声認識は、認識の口とマイクの入口が**あるか**を見るだけです。認識を始めず、マイクの許可も求めません。この PC の中で文字にできるかは調べません。

外へ要求を出すのは API の項目だけで、行き先は 2 つの API の住所に限ってあります。API 1 つにつき多くて 3 本（ブラウザが自分で出す下見、中身の無い呼び出し、その返事が読めず、案内が返ったとも分からないときだけ出す見るだけの要求）です。

API の項目を「可」にするのは、鍵なしの呼び出しが 401 で断られ、その本文がその API の断り方の形（Anthropic は `error.type` が `authentication_error`。OpenAI は、`error.code` に `api_key` か `apikey` の語があるか、`error.type` が `invalid_request_error` で `error.message` に `api key`・`api_key`・`apikey`・`bearer`・`authenticat` のどれかの語がある形。語は大小文字を問わず、含むかだけを見るので、鍵と関係のない認証の文でも OpenAI の形として数えます）のときだけです。401 でも形が違えば、社内の中継が止めた可能性があるので「不可」にします。Anthropic の形は実物で確かめました。OpenAI の形は、作った環境からつなげず実物を見ていないので推測です。2026-10-09 の Chrome 150 では OpenAI の 2 項目も「可」でしたが、返った本文そのものは見ていません。

どの要求も案内（転送）を追わず（同じ住所の中の案内も追わない）、時間切れにしたものはその場で取り消し、鍵とクッキーは付けません。偽の中継の 22 の型（社内の中継を真似たものと、本物に似せた API）と、作った環境の網で試した範囲では、どれも 2 つの API で合わせて 6 本以下でした（実の Edge と実の社内の中継では試していません。結果は `docs/results.md`）。

結果は 15 行の文字（見出し 1 行と項目 14 行。各行は 可／不可／未実行 に短い補足が付き、補足に状態の数字が入ることがある）にまとまるので、そのまま貼って渡せます。

## しくみ

話の文字（打つ・貼る・ブラウザの音声認識・ファイル）を、30 秒ほどの窓に刻みます。窓ごとに分析役（API、Claude Code、手動の輪、または人）が「カード・問い・括り」の判断を返します。検査器を通った判断だけを、追記専用の記録（判断ログ `<会議名>.jsonl` と素材ログ `<会議名>.src.jsonl`）に書きます。画面はその記録をそのまま描いたものです。縦の並びは語られた時刻のまま動かさず、先の話は読みません。ページを開いている間は、その記録を「追体験」として頭から見直せます（「記録」の節）。

形式の決まりは `format/FORMAT.md`、検査の規則表は `format/rules.json`、守る規則の一覧は `docs/rules.md` です。

## 使い方の細部

`kiku.html` は組み立て済みで入っています。ブラウザで開くだけです。`src/` などを直したときだけ、`python3 build_html.py`（Windows ではたいてい `py -3 build_html.py`）で組み立て直します（外部参照なしの 1 枚になります）。

会議の名前を打ち、入口と分析役を選んで「聞き始める」を押します。同じ名前で聞き始めると、その記録の続きになります。ただし、その記録がもう聞き終えているとき、古い形（1 版）や知らない形の記録のとき、前と入口の種類が違うとき（ファイルの入口で聞いた記録の続きはファイルの入口だけで、打つ／貼る・ブラウザ音声認識で聞いた記録の続きはその 2 つのどちらかでだけ聞けます）は、断って記録に何も書きません。続きでは、窓幅は前の記録のものを使います（ファイルの入口では、前と同じ素材を読み込めば前に聞いた発話を頭から読み飛ばして続け、素材が前と合わなければ断ります）。中断している間に打った行も捨てず、再開した後の最初の窓に入ります。

打つ入口では、行の先頭の「名前: 本文」（半角の「:」のあとに空白）か「名前：本文」（全角の「：」）が話者になり、「15:00までに」「https://…」のように時刻や住所で始まる行は、行の全体が話者無しの本文になります（決まりは `format/FORMAT.md` の「話者の切り出し」）。表から貼った「時刻<TAB>話者<TAB>本文」の行は、1 列目の時刻を使わず、届いた時刻で記録します（`rt.py` のメモ帳と同じ読み方）。

終わったら「聞き終える」→「書き出す」で 2 つの記録を落とします。「聞き終える」は、まだ窓に入っていない発話（打ちかけの欄の字も）を最後の窓として渡してから記録を閉じます。ブラウザの音声認識で聞いているときは、止めた認識（中断の前に止めたものも）の終わりの知らせを合わせて 3 秒まで待ち、その間に届いた言葉も最後の窓に入れます。3 秒で来なければ、入口の下の欄にそう出して閉じます。それより後に届いた言葉は記録に入れず、素材ログに出来事として残し、入口の下の欄に「聞き終えた後に届いた認識の結果を 1 件捨てました（記録の外）」と出します（黙って捨てません）。

## ファイルの素材について

ファイルの入口が読む素材の書き方は 4 つです: 時刻・話者・本文をタブで区切った表、時刻だけの行と本文の行、「0:05 甲: 始めます」のように時刻のあとに空白と本文を続けた行、WebVTT の字幕（会議の道具が書き出す `.vtt`。話者の札 `<v 名前>` を話者にします）。どれになるかは、拡張子ではなく中身の頭で決まります（`WEBVTT` の行の無い字幕も、字幕の時刻の行で見分けます。決まりは `format/FORMAT.md` の「素材ファイルの形」。`rt.py` も同じ読み方です）。

時刻のある行が 1 つも無いなどで発話が 1 つも無い素材は、読み込んだときにそう言い、「聞き始める」を押しても記録を作らずに断ります（0 バイトのファイルや空白だけの素材も同じで、断りの文は `rt.py` と同じです。見出しの「10:00 --> 11:00 定例」のような行のせいで字幕として読んだ素材なら、何行目で字幕と決めたかも文に添えます）。

読めない行・読めないバイトを含む行・時刻が飛んでいる行・時刻で始まる本文の行は、その発話を渡す窓で、入口の下の欄に行番号つきで知らせます（続きから聞くときも、まだ窓で渡していない発話の知らせは同じに出します。ただし欄の「前の窓までの知らせ」の 1 行は、開き直した後に渡した窓の分しか持ちません）。

時刻のように見えて、時刻のある行としては読まない行があります。素材にこれが混ざると、その行は前の発話の本文の続きとして読みます。そのため、その話は前の発話の窓で（行の時刻より早く）分析役に渡ります。

- 当たるのは、WebVTT の字幕のほかのどの書き方でも、時刻のすぐ後ろに空白を置かずに字が続く行（「0:45司会：次の議題です」「9:00から始めます」）と、「時刻だけの行と本文の行」の書き方での「0:45 甲 反対です」のような行や「[0:45] 甲: …」のような括弧で囲んだ時刻の行です。
- どの場合も、その窓で行番号つきの知らせ（ふつうは「時刻で始まる行は本文として読んだ（N 行目）」。読めない行のすぐ後ろに続く行なら、読めない行の知らせ）が必ず出ます。
- 表と「時刻＋空白＋本文」の書き方では、括弧で囲んだ時刻の行は括弧の中の時刻の発話として読みます。UTF-8 として読めないバイトを含む行は、どの書き方でも発話にせずに知らせます。
- この形に当たらない行（括弧の中が時刻の書き方に合わない「[0:5] 甲: …」、先頭が時刻として読めない「16:9の画面」など）は、知らせを出さずに前の発話の続きになります。素材の時刻の打ち間違いがこの形なら、その話は知らせの無いまま前の窓で渡ります。

決まりは `format/FORMAT.md` の「素材ファイルの形」の 9・9b・10 です。

## 分析役を Claude Code にするとき

ページは使いません。`tools/rt.py` を使います（手順は `prompts/for-claude-code.md`、許可の雛形は `.claude/settings.json`）。

判断ログの名前は、小文字の `.jsonl` で終わるものだけです（`.src.jsonl` で終わる名前は素材ログの名前なので断ります。パスの途中に「..」を挟んだ名前も断ります。メモ帳・素材の名前に「..」を挟んだときも断ります。判断ログの名前がリンクなら断ります。フォルダの部分のリンクは解いて使います）。`rt.py open` は、同じフォルダに、名前から `.jsonl` を除いた部分が大小文字を無視して同じになる判断ログか、その素材ログ・覚え書き・watch の印がすでにあれば断ります（大小文字を区別しない Windows で、別の記録のファイルを自分のものとして読み書きしないため）。

`rt.py next` は窓が閉じたときに覚え書き `<会議名>.next.json` を残し（窓の時刻と行の範囲、何回目か）、次の `append` がそれと突き合わせます——記録ではなく一時ファイルで、終われば消えます。

その場で聞くとき（メモ帳に打つ）は、発話の時刻は `watch` が届いた時刻で押し、メモ帳に打った時刻は使いません。中断の間に打った行も捨てません。読み終えた行をメモ帳で消したり書き換えたりしても記録は直さず、拾わなかった行はたいてい行番号つきで窓に知らせます。ただし道具はメモ帳の中身だけを見るので、見分けられずに拾いも知らせもしない形があります（メモ帳を空にして前と同じ中身の行を打つ、など）。メモ帳を空にして打ち直した後に、元に戻す（undo）を重ねて前の行を戻すと、同じ中身の行が知らせの無いまま二度目の発話になる形も、まれにあります。相づちだけの長いメモ帳をまるごと入れ替えたときは、知らせの数と行番号が実際の操作と大きく違います（決まりと、知らせが出ない形の一覧は `format/FORMAT.md` の「読み終えた行との突き合わせ」の 12）。

聞き終えるときは `next --last` → `append` → `end` の順に打ちます。`end` は、まだ窓に入っていない発話（メモ帳の改行の無い最後の行も）が残っていれば、何も書かずに断ります。ページの「聞き終える」と同じく、どの発話もどれかの窓に入ってから記録が閉じます。最後の窓の終わりも同じ決め方で、聞き終えた時計の秒（会議の頭からの秒の切り捨て。幅は窓幅の 3 倍まで）です。この秒は道具が最後の窓を閉じるときに読んだ時計で、前の窓の返事を待っている間に聞き終えたときなどは押した秒より後ろになります。`end` の `t` は書くときに時計を読み直すので、最後の窓の終わりと 1 秒ずれることがあります。
