# 環境を調べる計器（check.html）

会議や研修など「耳で聞く話」の構造を、聞いているそばから組み上げて見せる道具を作っています。その道具がブラウザだけで動くか、動かないならどこで止まるかを先に知るために、この計器 1 枚を置いています。`check.html` をブラウザで開き、「調べる」を押すと、そのブラウザで何が動くか（音声認識、マイクの入口、記録の保存、クリップボード、ファイルの保存、2 つの API への到達）を、項目ごとに「可／不可／未実行」で一覧にします。鍵は持たず、入力も求めず、会議の内容も送りません。

**外へ出る要求。**外へ要求を出すのは API の 4 項目だけで、行き先は 2 つの API（Anthropic と OpenAI）の住所だけです。ほかの住所にはブラウザがつながないよう、ページに決まりを入れてあります。API 1 つにつき多くて 3 本です。

1. 下見の要求。次の呼び出しの前に、ブラウザが自分で 1 回出します
2. 鍵を付けない、中身の無い呼び出しを 1 回。返事が読めて 401（鍵が無いので断る、という API のふつうの返事）で、本文がその API の断り方の形（Anthropic なら `error.type` が `authentication_error`。OpenAI なら、`error.code` に `api_key` か `apikey` の語があるか、`error.type` が `invalid_request_error` で `error.message` に `api key`・`api_key`・`apikey`・`bearer`・`authenticat` のどれかの語がある形）のときだけ「可」にします。語は大小文字を問わず、含むかだけを見ます。そのため、鍵と関係のない認証の文でも、この形の入れ物で返れば OpenAI の形として数えます。401 でも形が違えば、社内の中継が止めた可能性があるので「不可」にします
3. 2 の返事が読めず、案内（転送）が返ったとも分からなかったときだけ、API の根元へ見るだけの要求を 1 回

2 つの API で合わせて多くて 6 本です。どの要求も、案内（転送）が返ってもその先へは行かず（同じ住所の中の案内も追いません）、時間切れにしたものはその場で取り消し、鍵とクッキーは付けません。社内の中継を真似た小さな中継をいくつかの型で立てて試した範囲では、どの型でも 6 本以下でした。実の社内の中継と実の Edge では、まだ試していません。

**開き方。**このページの緑の「Code」ボタン →「Download ZIP」で落とし、展開して `check.html` をダブルクリックします（Edge で開く想定です。Chrome でも動くはずですが、確かめていません）。インストールは要りません。インターネットにつながらない環境でも、API への到達の項目が「不可」になるだけで、ほかの項目は調べられます。

**結果の貼り方。**調べ終えたら「コピー」を押すと、一覧が 15 行の文字（見出し 1 行と項目 14 行）になってクリップボードに入ります。それを、この道具について相談しているチャットやスレッドに貼ると、どの入口が使えるかを相手が読み取れます。貼るかどうかは、使う人が決めてください。各行は「項目: 可／不可／未実行（補足）」の形で、補足は「ファイルから開いている」「鍵なしの呼び出しが 401 で断られた」「401 が返ったが API の形ではない。中継の可能性」「断られた（状態 403）。API か社内の中継かは区別できない」のような短い文です。補足には返事の状態の数字（401・403 など）が入ることがあります。ブラウザの行は、名前と大まかな版（「Edge 141」のような形）です。ホスト名・URL・ユーザー名・ユーザーエージェントの文字列そのものは出ません。

## 注意

- この計器と文書は、生成 AI（Claude）で作りました
- 対応環境は未確認です。勤め先の PC でこの計器を開いて実測し、分かったことから埋めていきます
- API の断り方の形は、Anthropic は実物で確かめました。OpenAI は、作った側の環境からつながらなかったので実物を見ていません。実物の形が違えば、OpenAI の 2 項目は本物の API でも「不可」になります。逆に、社内の中継が API の断り方の形をそのまま真似た 401 を返せば、「可」になります
- 道具の本体は、まだこのリポジトリに入っていません。この計器の結果を見てから、動く入口に合わせて足します
