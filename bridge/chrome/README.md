# kiku ブリッジ（Chrome の拡張機能）— 画面共有の音を、アーティファクトの中の kiku へ流す

## 何をするものか

claude.ai のアーティファクトの中（iframe）で動く kiku は、その中からは画面共有の音もマイクも取り込めません。
この拡張機能は **claude.ai の親ページ**（アーティファクトの外側）で動き、

1. 画面共有の音（Windows なら「画面全体」＋「システム音声も共有」。PC で鳴っている Teams・Zoom の音）を取り込み、
2. ブラウザの音声認識で日本語の文字にして、
3. アーティファクトの中の kiku へ `window.postMessage` で送ります。

アーティファクトの中の kiku で「聞き取りを開始」を押すと、kiku がこの拡張機能に画面共有を始めさせ、届いた文字を「打つ／貼る」と同じ形で受け取ります（アーティファクトの中の kiku は、入力方法が最初から『拡張機能「ブリッジ」（画面共有の音）』になっています）。

0.2.1 から、アーティファクトに「音の診断（約 40 秒）」ボタンが出ます。押すと、この拡張機能が「画面全体」を勧めて画面共有を開き、同じ音を 3 つの段階（PC の中で音をそのまま／PC の中で 16kHz・1ch に直して／Google のサーバーで）で 12 秒ずつ認識させ、音が届いたか・文字になったかをアーティファクトに表示します（データベースの `probe` にも残します）。最後の段階では音声が外部に出るので、外に出てよい音だけを流して使います。2026-10-10 に私用 PC で初めて実際に動かしたとき、PC の中の認識が「aborted」で止まったため、文字にする処理を直す前に、どこで失敗しているのかを調べるためのものです。
この拡張機能の中身は、`manifest.json` と 3 つのファイルです：`intake.js`（kiku 本体と同じ部品。`src/intake.js` のコピー）、`bridge.js`（親ページで動く部分）、`background.js`（インストール・置き換え（更新）をしたときに、開いている claude.ai のタブへ前の 2 つを差し込む）。

## インストール方法（はじめの 1 回）

拡張機能が見つからないときだけ、kiku のアーティファクトの画面に 3 つの手順が出る。そのとおりに進めればインストールできる。

1. 画面の「拡張機能を保存する」を押す。拡張機能の ZIP（`kiku-bridge-<バージョン>.zip`）が保存される
2. 「アドレスをコピー」を押し、新しいタブのアドレスバーに貼り付けて `chrome://extensions` を開く。右上の「デベロッパー モード」をオンにする（**オンのままにしておく**）
3. 保存した ZIP を、その画面にドラッグ＆ドロップする。**展開は要らない**。確認の画面も出ない

インストールされると kiku の画面が自動で検出し、「拡張機能とつながっています」に変わる。**開いていた claude.ai のタブを再読み込みする必要はない**（インストールしたときに、拡張機能が開いている claude.ai のタブへ自分を差し込む。`background.js`）。

ドラッグ＆ドロップしてもインストールできないときは、まずデベロッパー モードがオンか確かめる（オフのままドロップすると、ZIP がダウンロードされるだけでインストールされない）。それでもインストールできなければ、ZIP を展開し、「パッケージ化されていない拡張機能を読み込む」で展開したフォルダ（`manifest.json` のある所）を選ぶ。開発用のリポジトリでは、このフォルダ（`kit/bridge/chrome`）をそのまま選んでもよい。

確かめたこと（事実）：Chromium 141 で、デベロッパー モードがオンの `chrome://extensions` に ZIP を実際にドラッグ＆ドロップすると、確認の画面なしにインストールされ、開いていたタブのアーティファクトが再読み込みなしでつながった（`tests/e2e/e2e_bridge_install.js`）。オフのままドロップすると、ZIP がダウンロードされるだけでインストールされなかった（同じ Chromium 141 で、テストとは別に確かめた）。**Windows の Chrome では、2026-10-10 に私用の 1 台でインストールできることを確かめた**（下の「私用の Windows の Chrome で確かめたこと」）。

kiku の画面は、Claude のアプリ（デスクトップ・スマートフォン）の中や Chrome 以外のブラウザで開くと、この手順を出さずに「PC の Chrome でこのアーティファクトを開いてください」と表示する（見分けにはユーザーエージェントの文字列を使う。アプリの中での文字列は実物で確かめていない）。アーティファクトを単独のページとして開いた場合（claude.ai の中に埋め込まれていない場合）は、拡張機能が届かないので「ブリッジ」を選べない。

## 新しいバージョンに置き換える

つながった拡張機能のバージョンが古いと、kiku の画面がそれを知らせ、「新しいバージョンを保存する」を出す。保存した ZIP を同じように `chrome://extensions` にドラッグ＆ドロップすると、**同じ拡張機能が置き換わる**（2 つに増えず、同じ ID のまま）。開いているタブも、再読み込みなしで新しいバージョンに切り替わる。

- 拡張機能の ID は `manifest.json` の `key` で固定してある（`aaaamjmfpajoeghckebjabnkgggdmige`）。`key` を消すと、ドロップするたびに別の拡張機能が増える
- 置き換えたとき、タブに入っていた古いバージョンは動いたまま残る。新しいバージョンは動き出す前に、古いバージョンに終了するよう知らせ（`kiku-bridge-retire`）、古いバージョンはメッセージの受信処理と操作パネルを外す。**古いバージョンが音声を取り込んでいる途中なら、止めるまで終了せず、新しいバージョンは待つ**（会議を途切れさせない）。終了するとき、アーティファクトへまだ渡せていない発話（アーティファクトが聞いていない間に溜めた分）は、ページに置いて新しいバージョンへ渡す（新しいバージョンは、アーティファクトが聞き始めたら古い順のまま流す。`tests/run_bridge_ui_node.js`）
- 0.1.0（フォルダから読み込んだ最初のバージョン。拡張機能の画面での名前は「kiku 橋」）は、終了の知らせに対応していない。アーティファクトはやりとりの決まり（プロトコル）のバージョン 2 で話すので、タブに残った 0.1.0 は答えない。前に 0.1.0 をフォルダから読み込んでいたら、`chrome://extensions` で削除しておく（ID が違うので、ZIP をドロップしても置き換わらない）

## 使い方

1. claude.ai で kiku のアーティファクトを開く（アーティファクトの中に kiku の画面が出る）。
   拡張機能とつながると、kiku の「聞き取りを開始」の下に「拡張機能とつながっています」と出る
2. kiku の「聞き取りを開始」を押す。画面共有の選択画面が出る。
   PC の中で文字にできないときは、押す前に kiku の画面に「音声を Google（Chrome の提供元）のサーバーへ送って文字にすることを承知する」のチェックボックスが出る。チェックを入れたときだけ始まる
3. 画面共有の選択画面で選ぶ（何を選ぶかは下の「画面共有で何を選ぶか」）。
   共有を選ぶと kiku が聞き取りを始め、上のバーに「聞き取り中」と経過時間が出る。以後、確定した発話が kiku に届く。
   選択画面でキャンセルすると、kiku に「始められませんでした」と出て、記録は作らない
4. 終えるときは kiku の「停止」を押す。画面共有も止まる。Chrome の「共有を停止」で止めたときは、kiku も「画面の共有が止まったので、聞き取りを終えました」と表示して記録を閉じる

ページの右下にある小さな操作パネル「ブリッジ（画面共有の音をアーティファクトへ）」は、ふだんは隠れている。出るのは、聞いている間・始めている途中・音声を外部に送ってよいか尋ねている間・アーティファクトへ渡せていない発話がある間・エラーが出た後だけ。エラーを読んだら、操作パネルの「閉じる」でしまえる。

**アーティファクトが聞いていないあいだに確定した発話も失われない**。ブリッジは発話を溜め、操作パネルに「アーティファクトがまだ聞き取りを始めていない。発話を溜めている（N 件。アーティファクトで「聞き取りを開始」を押すと流れる）」と出る。
アーティファクトで「聞き取りを開始」を押すと、溜めた分が新しい発話より先に流れる（事実：実装の仕様。テスト用の Chromium に実際の拡張機能を読み込んで確かめた。実際の画面共有と実際の音声認識では未確認）。

## 画面共有で何を選ぶか

音声を取り込める選び方は OS によって違う（出典は MDN のブラウザ互換性データ。こちらで実測はしていない）。

- **Windows**：「画面全体」を選び、「システム音声も共有」をオンにする。PC で鳴っている音が全部入る
- **会議がブラウザのタブで動いているとき**（どの OS でも）：そのタブを選び、「タブの音声も共有」をオンにする。そのタブの音だけが入る
- **macOS／Linux**：「画面全体」では音声を取り込めない。会議がブラウザのタブなら、上のタブの選び方で取り込める。別のアプリで動いている会議の音声は取り込めない
- 「ウィンドウ」を選んだときの音は、Chrome 141 以降で取り込める（事実。MDN）。それより前の Chrome では取り込めない

音声の共有をオンにしないまま共有すると、音が無いので「音声が共有されていない。…」と断られる。もう一度押して選び直す。

## 会社の PC で止まりうる所

**読み込めない**（デベロッパー モードのスイッチが灰色で押せない・「パッケージ化されていない拡張機能を読み込む」が効かない）。原因はどれも組織のポリシーで、出典は Chromium の policy_definitions：

- `ExtensionDeveloperModeSettings` = 1（Chrome 128 以降）。デベロッパー モードそのものがオフにされる
- `DeveloperToolsAvailability` = 2。`ExtensionDeveloperModeSettings` が未設定のとき、同じ効果になる
- `ExtensionInstallBlocklist` に `*`。許可リストに載せても署名済みの拡張機能しか通らず、パッケージ化されていない拡張機能は全部止まる。管理者に依頼することになる
- `ExtensionSettings` の `installation_mode` が `blocked`

**読み込めるが動かない**：

- `ScreenCaptureAllowed` = false。画面共有の選択画面が出ない、または断られる。claude.ai が `ScreenCaptureAllowedByOrigins` などの許可の一覧に載っていれば通る
- **音声認識の通信が止められている**。Google の API キーを持たない環境と同じく `network` のエラーになり、5 回続けて失敗するとブリッジが止まる。アーティファクトの表示にも「ブリッジはエラーで止まった」と出る
- **PC の中で使う日本語の音声認識データをダウンロードできない**。ダウンロードするときに、ブラウザの確認画面が出る。`ComponentUpdatesEnabled` = false の PC ではダウンロードできず、3 分で諦めて前の状態に戻る。その場合は、音声を外部に送る方法しか残らない

確かめ方：まず `chrome://extensions` のデベロッパー モードのスイッチが押せるかを見る。画面に「管理されている」という表示が出ているだけなら、止められているとは限らない（何かのポリシーが設定されていれば出る）。詳しくは `chrome://policy` を開き、上の名前を探す（出ていなければ、その設定はされていない）。

## まだ実機で確かめていないこと

**確かめたこと（実測）**：操作パネルが出る・hello への返事・発話の到達・停止・実際の claude.ai と同じ CSP の下での操作パネルの見た目は、Chromium 141 に実際の拡張機能として読み込んで確かめた（`tests/e2e/e2e_bridge_ext.js`。画面共有と音声認識はテスト用に差し替えて通した）。
親ページが自分自身に画面共有を許可していることは、レスポンスのヘッダーで確かめてある（事実）。

**私用の Windows の Chrome で確かめたこと（2026-10-10、1 台）**：

- ZIP を `chrome://extensions` にドラッグ＆ドロップでインストールできた
- 実際の claude.ai のページでアーティファクトを見つけ、つながった
- 「画面全体」と「システム音声も共有」で、画面共有に音声のトラックが含まれ、`start(track)` で PC の中の認識が文字にした（31 分）
- PC の中の日本語の音声認識データが無いうちは、認識が「止められた（aborted）」で止まった。Chrome の設定（`chrome://settings/accessibility`）の「自動字幕起こし」をオンにして言語を日本語にした後は止まっていない（効いたのはこの設定だと見ているが、推測）
- **自分の声（マイク）は入らない**。画面全体の音は PC から出ていく音で、マイクに話した声は含まれない（音声検索で試して確かめた）
- インストールし直した直後に、拡張機能の画面に `postMessage` のエラー（`The target origin provided … does not match the recipient window's origin`）が 1 件出た。読み込み中のアーティファクトに hello が届いたもので、害は無い（Chromium 141 で同じメッセージを再現した）。直すのは次のバージョン

**未実測**：

- 会社の PC（組織のポリシーが設定された Chrome）でインストールできるか・動くか
- Zoom や Teams のデスクトップアプリの音が入るか（仕組みの上では、既定の再生デバイスに出ていれば入る。既定以外の出力に出していると入らない）
- Windows の Chrome が起動のたびに出す「デベロッパー モードの拡張機能を無効にする」のポップアップ。出たら「キャンセル」で残せる（推測）

## 外へ出るもの

- PC の中で文字にできないときだけ、音声がブラウザの音声認識の提供元（Google）のサーバーへ送られる。それ以外は何も外に出ない
- **この拡張機能は通信しない**（ページの外へ何も送らない）。`manifest.json` の権限は `scripting` と `https://claude.ai/*` だけで、インストールしたときに、開いている claude.ai のタブへ自分を差し込むために使う。Chrome が表示する権限の説明は 0.1.0 と同じ 1 つで、英語の Chromium 141 では "Read and change your data on claude.ai"（事実。日本語の文言は確かめていない）。ZIP をドラッグ＆ドロップするインストール方法では確認の画面が出ないので、インストールするときには表示されない
- 文字は claude.ai のページの中でアーティファクトへ渡るだけで、kiku 側での扱い（記録・書き出し）は kiku 本体の README のとおり
- 送り先は、`src` のホスト名が `claudeusercontent.com` で終わる iframe（アーティファクト）だけ。それ以外の iframe には送らない（アーティファクトが無ければ送らずに溜める）

## 実装のメモ

- `intake.js` は生成物。`build_bridge.py` が `src/intake.js` からコピーする（`--check` で一致を確かめる）。手で直さない
- ZIP は `build_bridge.py --zip <出力>` で作る。同じ中身からは、いつも同じバイト列になる。`build_html.py --artifact` が同じ ZIP をアーティファクトの画面に埋め込み、「拡張機能を保存する」がそれを渡す
- **拡張機能を直したら `manifest.json` の `version` を上げ、`build_bridge.py --lock` でバージョンの控え（`zip.lock`）を書き直す**（アーティファクトはバージョンを比べて「拡張機能の新しいバージョン（…）があります」を出すので、上げ忘れると、古い拡張機能のままの人に知らせが出ない）。`zip.lock` は拡張機能が動かすもの（README を除く）の SHA-256 とバージョンで、中身が変わったのにバージョンが同じだと `--check`・`--zip`・`build_html.py --artifact` が止まる。`src/intake.js` を直したときも、コピーが変わるので同じ
- `background.js` は、インストール・置き換え（更新）をしたときに、開いている claude.ai のタブの最上位のフレームへ `intake.js` と `bridge.js` を差し込むだけ
- アーティファクトとやりとりする決まり（プロトコル）のバージョン（`bridge.js` の `VERSION`、`intake.js` の `BRIDGE_VERSION`）は 2。拡張機能のバージョン（`manifest.json` の `version`）とは別。`here` に拡張機能のバージョン（`ver`）が入る
- `bridge.js` の、画面に依存しない部分（アーティファクトの選び方・発話のまとめ方・hello の判定・アーティファクトが聞き始めるまで溜めて流すこと・送り先の選び方・`intake.js` のコピーの一致）は `tests/run_bridge_ext_node.js` が、画面の側（ボタン・アーティファクトが消えたときに、届けられなかった分を溜めておく動き・音声認識データをダウンロードした後に元の表示へ戻る動き）は `tests/run_bridge_ui_node.js` がテストする
- 実際の Chromium に拡張機能を読み込んで通しで確かめるのは `tests/e2e/e2e_bridge_ext.js`、ZIP をドラッグ＆ドロップしてインストールする・置き換えるのは `tests/e2e/e2e_bridge_install.js`（実行のしかたは `tests/README.md`）
