# kiku 橋（Chrome 拡張）— 画面共有の音を、枠の中の kiku へ流す

## 何をするものか

claude.ai のアーティファクトの枠（iframe）の中で動く kiku は、枠の中では画面共有の音もマイクも取れません。
この拡張は **claude.ai の親ページ**（枠の外）で動き、

1. 画面共有の音（Windows なら「画面全体」＋「システム音声も共有」。PC で鳴っている Teams・Zoom の音）を取り、
2. ブラウザの音声認識で日本語の文字にして、
3. 枠の中の kiku へ `window.postMessage` で流します。

枠の中の kiku で「聞き取りを開始」を押すと、kiku がこの拡張に画面共有を始めさせ、届いた文字を打つ入口と同じ形で受けます（枠の中の kiku は、音の入り方が初めから「橋」になっています）。

0.2.1 から、枠に「音の診断（約 40 秒）」が出ます。押すと、この拡張が「画面全体」を勧めて画面共有を開き、同じ音を 3 段（この PC の中で音そのまま／この PC の中で 16kHz・1ch に直して／Google のサーバーで）に 12 秒ずつ認識させ、音が届いたか・文字になったかを枠に出します（保存庫の `probe` にも残す）。最後の段は音声が外へ出るので、外に出てよい音だけを流して使います。2026-10-10 の私用 PC の初めての実走で、端末内の認識が「aborted」で止まったので、文字にする所を直す前に、何が成り立たないのかを測るためのものです。
この拡張の中身は、`manifest.json` と 3 つのファイルです: `intake.js`（kiku 本体と同じ部品の写し）、`bridge.js`（親ページで動く部分）、`background.js`（入れた・置き換えたときに、開いている claude.ai のタブへ前の 2 つを差し込む）。

## 入れ方（はじめの 1 回）

kiku のアーティファクトの画面に、拡張が見つからないときだけ 3 つの手順が出ます。そのとおりに進めれば入ります。

1. 画面の「拡張を保存する」を押す。拡張の ZIP（`kiku-bridge-<版>.zip`）が保存される
2. 「アドレスをコピー」を押し、新しいタブのアドレス欄に貼って `chrome://extensions` を開く。右上の「デベロッパーモード」をオンにする（**オンのままにする**）
3. 保存した ZIP を、その画面に引きずって落とす。**展開は要らない**。確かめの画面も出ない

入ると kiku の画面が自動で気づき、「拡張とつながっています」に変わる。**開いていた claude.ai のタブを読み込み直す必要はない**（入れたときに、拡張が開いている claude.ai のタブへ自分を差し込む——`background.js`）。

落としても入らないときは、まずデベロッパーモードがオンか確かめる（オフのまま落とすと、ZIP がダウンロードされるだけで入らない）。それでも入らなければ、ZIP を展開し、「パッケージ化されていない拡張機能を読み込む」で展開したフォルダ（`manifest.json` のある所）を選ぶ。作業用のリポジトリでは、このフォルダ（`kit/bridge/chrome`）をそのまま選んでもよい。

確かめたこと（事実）: Chromium 141 で、デベロッパーモードがオンの `chrome://extensions` に ZIP を本物のドラッグで落とすと、確かめの画面なしに入り、開いていたタブの枠が読み込み直さずにつながった（`tests/e2e/e2e_bridge_install.js`）。オフのまま落とすと、ZIP がダウンロードされるだけで入らなかった（同じ Chromium 141 で、試験とは別に確かめた）。**Windows の Chrome では、まだ試していない。**

kiku の画面は、Claude のアプリ（デスクトップ・スマートフォン）の中や Chrome でないブラウザで開くと、この手順を出さずに「パソコンの Chrome でこのアーティファクトを開きます」と言う（見分けは userAgent の文字。アプリの中の文字は実物で確かめていない）。アーティファクトを自分のページとして開いた版（claude.ai の中の枠でない）では、拡張が届かないので「橋」を選べない。

## 新しい版に置き換える

kiku の画面が、つながった拡張の版が古いと知らせ、「新しい版を保存する」を出す。保存した ZIP を同じように `chrome://extensions` に落とすと、**同じ拡張が置き換わる**（2 つにならず、同じ ID のまま）。開いているタブも読み込み直さずに新しい版へ移る。

- 拡張の ID は `manifest.json` の `key` で固定してある（`aaaamjmfpajoeghckebjabnkgggdmige`）。`key` を消すと、落とすたびに別の拡張が増える
- 置き換えたとき、タブに入っていた古い版は動いたまま残る。新しい版は立ち上がる前に古い版へ「退いて」と知らせ（`kiku-bridge-retire`）、古い版は受け口と操作部を外す。**古い版が音を取っている途中なら、止めるまで退かず、新しい版は待つ**（会議を切らない）。退くとき、枠へまだ渡せていない発話（枠が聞いていない間に溜めた分）は、ページに置いて新しい版へ渡す（新しい版は、枠が聞き始めたら古い順のまま流す。`tests/run_bridge_ui_node.js`）
- 0.1.0（フォルダから読み込んだ最初の版）は退く知らせを知らない。枠は決まりの版 2 で話すので、タブに残った 0.1.0 は答えない。前に 0.1.0 をフォルダから読み込んでいたら、`chrome://extensions` で削除しておく（ID が違うので、ZIP を落としても置き換わらない）

## 使い方

1. claude.ai で kiku のアーティファクトを開く（枠の中に kiku の画面が出る）。
   拡張とつながると、kiku の「聞き取りを開始」の下に「拡張とつながっています」と出る
2. kiku の「聞き取りを開始」を押す。画面共有の画面が出る。
   端末内で文字にできないときは、押す前に kiku の画面に「音声を Google（Chrome の提供元）のサーバーへ送って文字にすることを承知する」の印が出る。印を付けたときだけ始まる
3. 画面共有の画面で選ぶ（何を選ぶかは下の「画面共有で何を選ぶか」）。
   共有を選ぶと kiku が聞き取りを始め、上の帯に「聞き取り中」と時計が出る。以後、確定した発話が kiku に届く。
   共有の画面で取り消すと、kiku に「始められませんでした」と出て、記録は作らない
4. 終えるときは kiku の「停止」。画面共有も止まる。Chrome の「共有を停止」で止めたときは、kiku も「画面の共有が止まったので、聞き取りを終えました」と出して記録を閉じる

ページの右下の小さな操作部「橋（画面共有の音を枠へ）」は、ふだんは隠れている。出るのは、聞いている間・始めている途中・送る承知を尋ねている間・枠へ渡せていない発話がある間・誤りが出た後だけ。誤りを読んだら操作部の「閉じる」でしまえる。

**枠が聞いていないあいだに確定した発話も失われない。**橋は発話を溜め、操作部に「枠がまだ聞いていない。発話を溜めている（N 件。枠で「聞き取りを開始」を押すと流れる）」と出る。
枠で「聞き取りを開始」を押すと、溜めた分が新しい発話より先に流れる（事実: 実装の仕様。試験用の Chromium に本物の拡張を読み込んで確かめた。本物の画面共有と本物の音声認識では未確認）。

## 画面共有で何を選ぶか

音が取れる選び方は OS で違う（出典は MDN の互換データ。こちらで実測はしていない）。

- **Windows**: 「画面全体」を選び、「システム音声も共有」に印を付ける。PC で鳴っている音が全部入る
- **会議がブラウザのタブで動いているとき**（どの OS でも）: そのタブを選び、「タブの音声も共有」に印を付ける。そのタブの音だけが入る
- **macOS／Linux**: 「画面全体」では音が取れない。会議がブラウザのタブなら上のタブの選び方で取れる。別のアプリで動いている会議の音は取れない
- 「ウィンドウ」を選んだときの音は Chrome 141 以降で取れる（事実、MDN）。それより前の Chrome では取れない

印を付けずに共有すると、音が無いので「音声が共有されていない。…」と断られる。もう一度押して選び直す。

## 会社の PC で止まりうる所

**読み込めない**（デベロッパーモードのスイッチが灰色で押せない・「パッケージ化されていない拡張機能を読み込む」が効かない）。どれも組織のポリシーで、出典は Chromium の policy_definitions:

- `ExtensionDeveloperModeSettings` = 1（Chrome 128 以降）。デベロッパーモードそのものが切られる
- `DeveloperToolsAvailability` = 2。`ExtensionDeveloperModeSettings` が未設定のとき、同じ効き
- `ExtensionInstallBlocklist` に `*`。許可リストに載せても署名済みの拡張しか通らず、パッケージ化されていない拡張は全部止まる。管理者に頼む形になる
- `ExtensionSettings` の `installation_mode` が `blocked`

**読み込めるが動かない**:

- `ScreenCaptureAllowed` = false。画面共有の画面が出ない・断られる。claude.ai が `ScreenCaptureAllowedByOrigins` などの許可の側に載っていれば通る
- **音声認識の通信が止められている**。鍵の無い環境と同じく network の誤りになり、5 回続けて失敗すると橋が止まる。枠の札にも「橋が止まった」と出る
- **端末内の日本語の部品が落とせない**。入れるときにブラウザの承諾の画面が出る。`ComponentUpdatesEnabled` = false の PC では入らず、3 分で諦めて前の状態に戻る。その場合は音を外へ送る形しか残らない

確かめ方: まず `chrome://extensions` のデベロッパーモードのスイッチが押せるかを見る。画面に「管理されている」旨の表示が出ているだけなら、止められているとは限らない（何かのポリシーが掛かっていれば出る）。詳しくは `chrome://policy` を開き、上の名前を探す（出ていなければ、その設定は掛かっていない）。

## まだ実機で確かめていないこと

**確かめたこと（実測）**: 操作部が出る・hello の返事・発話の到達・止める・本物と同じ CSP の下での操作部の見た目は、Chromium 141 に拡張を本物として読み込んで確かめた（`tests/e2e/e2e_bridge_ext.js`。画面共有と音声認識は差し替えて通した）。
親ページが自分自身に画面共有を許していることは、応答のヘッダで確かめてある（事実）。

**私用の Windows の Chrome で確かめたこと（2026-10-10、1 台）**:

- ZIP を `chrome://extensions` に落として入った
- 本物の claude.ai のページで枠を見つけ、つながった
- 「画面全体」と「システム音声も共有」で、画面共有に音のトラックが乗り、`start(track)` で端末内の認識が文字にした（31 分）
- 端末内の日本語の部品が無いうちは、認識が「止められた（aborted）」で止まった。Chrome の設定（`chrome://settings/accessibility`）の「自動字幕起こし」をオンにして言語を日本語にした後は止まっていない（効いたのはこの設定だと見ているが、推測）
- **自分の声（マイク）は入らない。**画面全体の音は PC から出ていく音で、マイクに話した声は含まれない（音声検索の試しで確かめた）
- 入れ直した直後に、拡張機能の画面に `postMessage` の誤り（`The target origin provided … does not match the recipient window's origin`）が 1 件出た。読み込み中の枠に hello が当たったもので、害は無い（Chromium 141 で同じ文を再現した）。直すのは次の版

**未実測**:

- 会社の PC（組織のポリシーが掛かった Chrome）で入るか・動くか
- Zoom や Teams のデスクトップアプリの音が入るか（仕組みの上では、既定の再生デバイスに出ていれば入る。既定以外の出力に出していると入らない）
- Windows の Chrome が起動ごとに出す「デベロッパーモードの拡張機能を無効にする」の泡。出たら「キャンセル」で残る（推測）

## 外へ出るもの

- 端末内で文字にできないときだけ、音がブラウザの音声認識の提供元（Google）のサーバーへ行く。それ以外は何も外へ出ない
- **この拡張は通信しない**（ページの外へ何も送らない）。`manifest.json` の権限は `scripting` と `https://claude.ai/*` だけで、入れたときに開いている claude.ai のタブへ自分を差し込むために使う。Chrome の断り書きは 0.1.0 と同じ 1 つで、英語の Chromium 141 では "Read and change your data on claude.ai"（事実。日本語の文言は確かめていない）。ZIP を落とす入れ方では確かめの画面が出ないので、入れるときには見えない
- 文字は claude.ai のページの中で枠へ渡るだけで、kiku 側の扱い（記録・写し）は kiku 本体の README のとおり
- 送る先は、`src` のホスト名が `claudeusercontent.com` で終わる枠だけ。それ以外の iframe には送らない（枠が無ければ送らずに溜める）

## 作りの注

- `intake.js` は生成物。`build_bridge.py` が `src/intake.js` から写す（`--check` で一致を確かめる）。手で直さない
- ZIP は `build_bridge.py --zip <出力>` で作る。同じ中身からはいつも同じバイト列になる。`build_html.py --artifact` が同じ ZIP を枠の画面に埋め込み、「拡張を保存する」がそれを渡す
- **拡張を直したら `manifest.json` の `version` を上げ、`build_bridge.py --lock` で版の控え（`zip.lock`）を書き直す**（枠は版を比べて「新しい版があります」を出すので、上げ忘れると古い拡張のままの人に知らせが出ない）。`zip.lock` は拡張が動かすもの（README を除く）の SHA-256 と版で、中身が変わったのに版が同じだと `--check`・`--zip`・`build_html.py --artifact` が止まる。`src/intake.js` を直したときも、写しが変わるので同じ
- `background.js` は、入れた・置き換えたときに、開いている claude.ai のタブの最上位の枠へ `intake.js` と `bridge.js` を差し込むだけ
- 枠と話す決まりの版（`bridge.js` の `VERSION`、`intake.js` の `BRIDGE_VERSION`）は 2。拡張の版（`manifest.json` の `version`）とは別。`here` に拡張の版（`ver`）が乗る
- `bridge.js` の純粋な部分（枠の選び方・発話のまとめ・hello の判定・枠が聞き始めるまで溜めて流すこと・送り先の選び方・`intake.js` の写しの一致）は `tests/run_bridge_ext_node.js` が、画面の側（ボタン・枠が消えたときの溜め・部品を入れた後の戻り）は `tests/run_bridge_ui_node.js` が試験する
- 本物の Chromium に拡張を読み込んで通しで確かめるのは `tests/e2e/e2e_bridge_ext.js`、ZIP を落として入れる・置き換えるのは `tests/e2e/e2e_bridge_install.js`（走らせ方は `tests/README.md`）
